# 2026-11-04 20:35 用户裁定停机（重启机器）

> 然后再让他们先后跑，不然环境太脏了」。

## 一、停机时的现场（Leader 取证，20:33:56）

| 项 | 状态 |
|---|---|
| 两链 Worker | 已 `interrupt`，均停止；无活动子会话 |
| `sim.lock` | 曾被 **两个 flock 同时排队**（180301 链B、182160 链A），现已释放 |

## 二、根因（Leader 判定，证据在下）

**直接原因：两链同时抢独占资源，锁没起作用，因为锁的是"命令"不是"整链"。**

时间线：

| 时刻 | 事件 |
|---|---|
| 20:12 | 链 B 拿 `sim.lock`，起 `s18` 跑 `run_demo.sh --duration 200`（`timeout 420`） |
| 20:15 | 链 A **也**起 `flock -w 1800`，排队等锁（正确行为） |
| 20:13:50 | 链 B 的 run 启动 |
| 20:17:12 | 该 run **失败退出码 5**：`gazebo` 被 `SIGTERM`（-15）、`MicroXRCEAgent` 双双 -15、`collision_monitor` 心跳丢失 4 s 触发 `lifecycle_manager` 悲观关停 |
| 20:33 | 链 A 仍在等锁（已等 18 分钟），链 B 的 `timeout 420` 早已到期但进程仍挂着 |

**关键证据**（`experiments/demo/20261104-201350/launch.log`）：

```
[225] process has died: gz sim ... exit code -15
[226] process has died: MicroXRCEAgent udp4 -p 8888 ... exit code -15
[227] process has died: MicroXRCEAgent udp4 -p 8889 ... exit code -15
[229] lifecycle_manager_ground: CRITICAL FAILURE: SERVER collision_monitor IS DOWN
      after not receiving a heartbeat for 4000 ms
[282] px4-35 ERROR [gz_bridge] timed out waiting for clock message
[284] px4-35 ERROR [init] gz_bridge failed to start and attach to existing model
```

RTF 崩到 **0.069**（正常 0.78–0.94），`sim_end_s` 只有 12.5 s 就死。

**为什么会 -15**：不是 OOM，是**同时存在多个仿真实例**争夺 DDS / `/dev/shm` / CPU（4 核）。
`gz sim` 与 `MicroXRCEAgent` 同时收到 SIGTERM，符合"两个 `run_demo` 的进程组互相清理"的特征——
`run_demo.sh stop` / 退出回收按 **PGID** 清理，两个实例若落在相近 PGID 或互相误判，
就会把对方的 gazebo 一起收掉。这与 `.coordination/README.md#parallel` 的
「**不得终止他人进程**」冲突——**这条纪律在实操上没有被机制保证**。

**次因：`flock` 只包住了"启动命令"，没包住"整个 run 生命周期"**。
链 A 的 `flock` 确实在排队，但链 B 自己的 `flock` 在 `run_demo` 失败后**没有及时返回**，
导致 `sim.lock` 被一个已死的 run 长期占用（实测 20:15→20:33 共 18 分钟），链 A 干等。

**第三因：`/dev/shm` 361 段残留**。每轮 run 失败/被 SIGKILL 都会留下 fastrtps 段，
累积到 361 段（正常应 <200），DDS 发现变慢、共享内存分配失败风险升高——这就是用户说的"环境太脏"。

## 四、重启后的执行顺序（Leader 下令，**严格串行**）

用户已裁定「让他们**先后**跑」。故：

1. **A 链先跑完**（它已到 T2 阶段且改动最少），B 链**保持 idle** 不写不跑。
2. A 链完成后，B 链再进 T2。
3. **串行期间锁的用法改为"包整轮"**，见下。

### 锁的用法修正（强制，两链共同遵守）

原来的写法（每跑一次包一条命令）**不够**，改为：

```bash
# 一次拿锁，覆盖整轮的全部 run；退出前显式释放
flock -w 3600 /home/chen/AGC/.coordination/locks/sim.lock -c '
  set -e
  # 1) 先清残留（只清自己起的，见下）
  # 2) 连续跑本轮的 N 个 run
  # 3) 结束
'
```

并且**每次拿锁之前**必须先做残留自检：

```bash
ps -ef | grep -E "gz sim|px4_sitl|MicroXRCEAgent|run_demo" | grep -v grep || echo CLEAN
```

**发现残留不是我自己的 → 立即停，`send_message` 报 Leader，不得清理**（`README.md#parallel` 冲突处置第 2 条）。

### 重启后第一件事（用户可做，也可由 Leader 做）

重启本身会清掉 `/dev/shm` 与全部进程，这已是最彻底的清理。**不需要**再执行 `run_demo.sh stop`。
重启后由 Leader 跑一次 `./run_demo.sh doctor` 取证（只读，不启仿真），确认 shm 段数回落、端口空闲。
