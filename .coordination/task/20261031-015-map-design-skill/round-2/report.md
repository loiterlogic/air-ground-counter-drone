## 1. 逐条对照（改前 → 改后）

**① 8 字净空不再被当成失败判决**（GATES）

- 改前：标题"唯一没有正式断言的**致命**判据"；"它一旦为负，整条 8 字轨迹都被安全层判为不可行，演示根本跑不起来"。
- 改后：标题改"没有正式断言，须自己算，且别把结论说过头"；新增"负值说明什么、不说明什么"：
  它只意味着名义参考轨迹的部分采样点落在当前静态膨胀圆盘内，**不**证明运行期实际参考/偏置目标
  同样落在里面、**不**证明滤波后执行轨迹被阻断或演示跑不起来、**不**证明契约被违反；
  这些必须分别核对实际生效路径与运行证据（参考怎么生成、偏置与饱和在哪层、安全层实际拦了什么、
  日志与终态）。并补"负值是设计信号不是失败判决；正值也不等于运行期一定安全"。

**② 删除未授权的基线豁免**（GATES）

- 改前：整段"**只在演示主地图上要求为正**"，并给 minimal 一个"它是基线所以可以为负"的说明。
- 改后：整段删除。替换为：官方当前**没有**这条断言，任何地图（含核查基线）出现负值都按**未决**
  登记并交回 Leader；技能**不**为任何地图开例外、不新增或放宽判据、不改基线几何。
- 同步：`GATES` 第 3 节"分段长墙"从"既不占用 8 字空域，也避免…"改为"静态圆盘占用随之下降"，
  并补一句"不能反过来被当作'通长墙一定导致运行失败'的判据"——同一个推断过度问题。

**③ 后端纪律与 headless 表述**（EVIDENCE）

- 改前：纪律第 3 条"演示只用轻量后端"；"headless（`gz sim -s`）不启动渲染客户端，**根本没有画面**"。
- 改后：纪律第 3 条"**演示后端按当前入口默认与当次派工执行**（当前入口默认 `full`；以入口脚本与
  launch 默认值为准，不在技能里写死）；`lightweight` 只在被授权时作快速自检，**不能替代** `full` 的验收"。
  headless 改为"**取不到 GUI 窗口截图**（GUI 服务不存在），但**不等于**出不了图——相机传感器服务端
  渲染仍可出帧，须标注为传感器渲染、不得称作 GUI 截图"。证据分层表同步改写。

**④ 因果关系加限定**（SKILL 末条 / EVIDENCE §4.2、§4.3）

- 改前：SKILL"**规模上限属环境侧**：GUI 常驻内存与地图规模无关"；EVIDENCE"`air_hover_timeout` /
  定位发散 → **PX4 / EKF 侧，与地图几何无关**"、"增长来自 Gazebo GUI 进程本身…**与地图内容无关**"。
- 改后：SKILL 改为"**因果关系要限定条件**：技能里一切实测结论只在当时环境与配置下成立，
  先查配置与日志再谈根因"；EVIDENCE §4.2 标题改"不要把'看起来像'当成根因"，
  PX4/EKF 现象写成"**历史上**在特定后端与特定环境出现过，是**当时条件下**的历史结论，不是普遍因果"，
