# 02 · 五案例走查（改后规则）

走查方法：对每个案例，按**改后文本**逐条判定"Worker 该做什么""何时停""谁批准"，并给出**改前会怎样**做对照。
每条引用都指向改后文件的实际锚点；判定若依赖某个条款，必须能指出来。

---

<a id="case-1"></a>
## 案例 1 · 已知根因修复（本单点名的主场景）

**场景**：Worker 在批次内跑真实实验，第 2 次失败；日志显示是自身脚本把路径当目录传参，改一行即可。此时"T2 已用 2/4 次、已写第 2 轮"。

**走查**：

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 这是新证据吗 | 根因锁定 → 直接可改；"修复+验证"是完整证据单元（[#batch](../../../../README.md#batch) 熔断节注） | ✅ 记为新证据 |
| 次数是否挡住 | **不挡**：T2 次数只记账，主约束是总时长（[#counts](../../../../README.md#counts)、[#run-tiers](../../../../README.md#run-tiers)） | ✅ 可继续 |
| 轮数是否挡住 | **不挡**：N=6 是记录检查点，到点写小结继续（[#batch](../../../../README.md#batch) N 与 K） | ✅ 可继续 |
| 是否要唤醒 Leader | **不唤醒**：属"已明确根因但还需若干次验证"（[#batch](../../../../README.md#batch) 不唤醒情形） | ✅ 自行继续 |
| 动作 | 改脚本 → 重跑 → 取证 → 若通过则继续验收判据；全部满足才交回 | ✅ |
| 何时才算停 | 验收判据全满足（里程碑）/ 总时长耗尽 / 越白名单 / 契约风险 / 连续 4 轮无新证据 | ✅ 四类之一 |

**改前对照**：T2 2/4 虽未用尽，但 P1-4 的形状是"2/2 用满 → 停"；本案例改前若按"有效失败须回报"（旧 [#run-tiers](../../../../README.md#run-tiers)）会被读成交回。**改后明确不停**。

**判据落点**：本案例必须能指出"根因已锁定 + 修复在同范围 + 资源未耗尽"→ 继续。三者缺一（例如根因不明）则转 [案例 2](#case-2)。

<a id="case-2"></a>
## 案例 2 · 未知根因空转

**场景**：Worker 连续几轮换参数重跑同一现象，每轮都没有排除或确认任何假设；第 3 轮又是同样的失败。

**走查**：

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 这算新证据吗 | **不算**：同因失败换参数重跑而无新排除（[#batch](../../../../README.md#batch) "区分性新证据"判据） | ❌ 计为空转轮 |
| 次数是否挡住 | 不挡——**这正是关键**：次数耗尽不是停止理由，所以不能用"T2 用完了"当借口停下 | — |
| 真正挡住的是什么 | **K=4**：连续 4 轮无区分性新证据即熔断（[#batch](../../../../README.md#batch) 熔断节、[worker.md#batch-autonomy](../../../../roles/worker.md#batch-autonomy)） | ✅ 第 4 轮停 |
| 停下后交什么 | 假设台账（假设 / 已排除·未排除 / 判别实验 / 所需授权）+ "按当前授权本问题不可判别" + 最小追加授权 | ✅ |
| Leader 只能做什么 | **三选一**：追加授权 / 判定不可测归档 / 关闭任务；不得派"继续试试"（[leader.md#review](../../../../roles/leader.md#review)） | ✅ |

**改前对照**：改前 Worker 可能在第一次"有效失败"就把现场交回（旧 `T1 失败不自动重跑` 条），也可能在第 6 轮因 N 触发唤醒——**两种都错**：前者太早（假设没穷尽就交回，Leader 重做推理），后者太晚且理由错（按轮数停，不按无进展停）。

**判据落点**：空转的**唯一**停止闸是 K=4。用次数停 = 违规（[#counts](../../../../README.md#counts)）；用"没成功"停 = 违规（[#batch](../../../../README.md#batch) "未达成功不等于不可测"）。

<a id="case-3"></a>
## 案例 3 · 总时间耗尽

**场景**：派工单给 `T2: 4 次 / 3600 s 总墙钟`、离线 600 s。Worker 修复顺利，但在第 3 次真实运行中途，累计墙钟已达 3600 s；此时验收判据还差 1 项。

**走查**：

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 是否继续 | **停**：总时间用尽是主约束（[#batch](../../../../README.md#batch) 停止判据表"总时间"行、[#offline-budget](../../../../README.md#offline-budget)） | ✅ 停 |
| 怎么停 | 置 `待审查`（触发"资源耗尽"类），`send_message` 唤醒 Leader | ✅ |
| 报告写什么 | 已完成项 + **未完成项及原因**（"总时长用尽"，不是"次数用尽"）（[worker.md#batch-autonomy](../../../../roles/worker.md#batch-autonomy) 第 5 条） | ✅ |
| Leader 怎么办 | 追加授权（新总时长）或裁定收口；**不得**把"时间用尽"记成"不可测"（[leader.md#review](../../../../roles/leader.md#review)） | ✅ |
| 能不能"再跑一次就完事" | **不能**：总时长是主约束，不得自行突破；单次运行也仍受单次上限约束（[#run-tiers](../../../../README.md#run-tiers)） | ❌ |

**改前对照**：改前"预算耗尽"同时被 T1/T2/attempt/轮数四种量触发，Worker 无法判断哪种用尽、该不该停；改后只有**总墙钟/总时长/独占资源**触发。

**判据落点**：**时间维度必须留痕到秒**，且要与次数账目分开写。案例 3 与案例 1 的分界是"资源总量到点"，与案例 2 的分界是"是否还有未排除假设"。

<a id="case-4"></a>
## 案例 4 · 文件越界

**场景**：修复需要改 `src/agc_task/**`，但本单白名单只有 `.coordination/**`；或者顺带发现 `AGENTS.md` 有错字想改。

**走查**：

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 能不能改 | **不能**：只允许写本单白名单（[#files](../../../../README.md#files)、[#protocol](../../../../README.md#protocol) 基线与执行边界） | ❌ |
| 并行下更严 | 共享文件由**指定拥有者**写，其他单只读；未指定拥有者先问 Leader（[#parallel](../../../../README.md#parallel) 文件隔离） | ❌ |
| 该怎么办 | 停下，`report.md` 记录"需要改 X + 原因 + 证据"，按**阻塞**唤醒 Leader（[worker.md#batch-autonomy](../../../../roles/worker.md#batch-autonomy) 边界） | ✅ |
| 能不能"先改了再报告" | **不能**：那是越界后再补披露，不是授权（披露义务 ≠ 授权） | ❌ |
| 能不能改别的单的文件 | **不能**：只记录不改（[#parallel](../../../../README.md#parallel) 冲突处置 3、[worker.md#parallel-work](../../../../roles/worker.md#parallel-work)） | ❌ |

**改前对照**：改前规则同样禁止越界，但没有并行下"共享文件拥有者"的概念，也没有"发现别的单改动"的处置条目 → Worker 容易把"别人先改了"当成"我也可以改"。

**判据落点**：越界属"阻塞"类，**必须唤醒**——它不是"次数问题"，新规则没有、也不该有"越界可自主"的余地。

<a id="case-5"></a>
## 案例 5 · 并行资源冲突

**场景**：F1（出生布局）持有仿真运行；F2/F3/F4 零仿真。F3 想把某段日志用 GZ 复现验证，或发现 `.coordination/README.md` 已被 Leader 改过。

**走查**：

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 能不能起仿真 | **不能**：派工单没写"独占 GZ"就不得启动；同一时刻只有一个任务可占用仿真/构建（[#parallel](../../../../README.md#parallel) 独占资源） | ❌ |
| 正在被别人占用时 | 停下，记 `ps`/运行标识，按**阻塞**唤醒 Leader；**不等待轮询、不抢占、不清理**（[#parallel](../../../../README.md#parallel) 冲突处置 2） | ✅ |
| 能不能 `pkill` 掉 F1 的进程 | **不能**：不得终止他人进程、不得清 `/dev/shm`（[#run-tiers](../../../../README.md#run-tiers) T1 ⑤、[#parallel](../../../../README.md#parallel)） | ❌ |
| 共享文件被别人改过 | 记 `git status` 证据报告；**不覆盖、不回滚、不 `git checkout`**（[#parallel](../../../../README.md#parallel) 冲突处置 1、[worker.md#parallel-work](../../../../roles/worker.md#parallel-work)） | ✅ |
| 别的单阻塞了，我要不要停 | **不要**：各链状态独立（[#parallel](../../../../README.md#parallel) 状态隔离） | ✅ |
| 谁写 CURRENT | **Leader 独占**；Worker 不写（[#parallel](../../../../README.md#parallel) CURRENT 单一写入、[#files](../../../../README.md#files)） | ✅ |

**改前对照**：改前只有"同机仿真串行，不能自行终止他人进程"一句，**没有**"派工单须写明独占 X""冲突即停报""共享文件拥有者"三条 → 并行时无从判定。同时旧"单任务链…不创建并行任务"直接与用户授权冲突，Worker 读了会自相矛盾。

**判据落点**：并行冲突的停止类别是**"阻塞"（资源冲突）**，不是"资源耗尽"。二者区分：资源耗尽 = 我的额度到点；资源冲突 = 额度还在但东西被别人占着。

<a id="summary"></a>
## 走查汇总：五案例覆盖停止判据的哪一格

| 案例 | 触发类别 | 改后的停止闸 | 不该用的停止闸 |
|---|---|---|---|
| 1 已知根因修复 | 无（继续） | 只在里程碑/总量/越界时停 | 次数、轮数、单次失败 |
| 2 未知根因空转 | 无进展 | **K=4 连续无区分性新证据** | 次数、轮数、"没成功" |
| 3 总时间耗尽 | 资源耗尽 | **总墙钟/总时长到点** | 次数、attempt 数 |
| 4 文件越界 | 阻塞（越界） | 白名单/共享拥有者 | 任何计数 |
| 5 并行资源冲突 | 阻塞（资源冲突） | 独占资源被占用 | 抢占、轮询、清理他人资源 |

**一致性检查**：五案例分别落在"继续 / 无进展 / 资源 / 越界 / 冲突"五格，覆盖 [#batch](../../../../README.md#batch) 停止判据表的**全部四类触发**（案例 1 = 不触发；案例 4、5 同属"阻塞"，但判据不同，故分列）。
