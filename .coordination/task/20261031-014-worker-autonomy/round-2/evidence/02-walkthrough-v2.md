# 02v2 · 五案例走查（round-2 修订版，权威）

> 本文件**取代** [round-1 走查](../../round-1/evidence/02-walkthrough.md#walkthrough)中案例 1、2 的停止闸表述。
> 修订动因：[round-1 审查](../../round-1/review.md#review) 第 4 条——原版宣称"空转唯一停止闸 K=4"，
> 以及案例 1 未写清"建议次数已用尽但仍有总时长与正向运行授权时可继续"。其余案例保持原判并补强。

<a id="common"></a>
## 前置：四类停止闸**并列**，不是层层兜底

| 闸 | 触发条件 | 是否依赖轮数 |
|---|---|---|
| **契约/范围/文件边界** | 触碰硬约束、越白名单、未知漂移 | **否**，随时生效 |
| **总时间/总资源** | 总墙钟或真实运行总时长耗尽 | **否**，随时生效 |
| **目标** | 验收判据满足（或明确不可再推进） | 否 |
| **无进展（K=4）** | 连续 4 轮无区分性新证据 | 是（**唯一**以轮计数的闸） |

**两条由此推出的硬约束**：

1. **K=4 不是"唯一"闸，更不是"许可"**：前三类与轮数无关，任何时刻都能停。
2. **不得为了凑够四轮而重复无意义实验**：若当轮已能判断"再做也不会有新证据"，**当轮就停**，不必等第 4 轮。

<a id="case-1"></a>
## 案例 1 · 已知根因修复（含"建议次数用尽"的正确处置）

**场景**：Worker 跑真实实验，第 2 次失败；日志显示本地脚本把路径当目录传参，改一行即可。派工单写 `T2: 3600 s 总墙钟，建议 2 次`；此时**建议次数 2 次已用尽**，总墙钟还剩 2400 s。

**走查**：

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 这是新证据吗 | 根因锁定→可改；"修复+验证"是完整证据单元（[#batch](../../../../README.md#batch) 熔断节注） | ✅ |
| **建议次数用尽，能否继续** | **能**：建议次数只是**估算**，超出属**估算差异、不是授权越界**（[#counts](../../../../README.md#counts)） | ✅ **继续** |
| **继续的前提**（三者**同时**成立） | ① **有正向运行授权**（本单是 `T2: 3600 s`，不是 0、不是未写）；② **总时长仍有余额**（剩 2400 s）；③ 修复在本单白名单内 | ✅ 全部满足 |
| 轮数是否挡住 | **不挡**：N=6 是记录检查点（[#batch](../../../../README.md#batch) N 与 K） | ✅ 继续 |
| 是否要唤醒 Leader | **不唤醒**：属"已明确根因但还需若干次验证"（[#batch](../../../../README.md#batch) 不唤醒情形） | ✅ 自行继续 |
| 动作 | 改脚本 → 重跑 → **计本次墙钟** → 取证 → 继续验收判据 | ✅ |
| 何时停 | 总墙钟耗尽 / 越白名单 / 契约风险 / 验收判据全满足 / 判断再无新证据 | ✅ |

**反例（同一场景但缺一项前提）**：

| 缺哪项 | 判定 |
|---|---|
| 派工单是 `T2: 0` 或**未写** T2 | **一次都不能启动**（[#counts](../../../../README.md#counts) 未授权/0 不可运行）→ 停并报阻塞 |
| 总墙钟已耗尽 | 停并交回未完成项（总时间是硬约束） |
| 修复需改白名单外文件 | 停并报阻塞（文件边界与轮数无关） |
| 上级明确写"最多 2 次（外部配额）" | **按上级硬限执行**，不得援引估算差异（同节"唯一例外"） |

**改前对照**：P1-4 r2 的形状是"T2 2/2 用满 → 停"，而两次失败皆自身工装缺陷、根因当轮已明。**改后：建议次数用尽不停；只有总时长与正向授权同时缺失才停。**

<a id="case-2"></a>
## 案例 2 · 未知根因空转

**场景**：Worker 连续几轮换参数重跑同一现象，每轮都没有排除或确认任何假设；第 3 轮又是同样的失败。

**走查**：

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 这算新证据吗 | **不算**：同因失败换参数重跑而无新排除（[#batch](../../../../README.md#batch) "区分性新证据"判据） | ❌ 空转轮 |
| 次数是否挡住 | 不挡，所以**不能**用"次数用完了"当停工借口；但**也不构成继续的许可** | — |
| **是否必须等满 4 轮** | **不必**：已判断"再做也不会有新证据"时**当轮即停**（[#batch](../../../../README.md#batch) "这四行是并列的"注） | ✅ 可提前停 |
| **真正挡住的是什么** | **K=4**（连续 4 轮）**与另外三类并列**：轮次在此**不是**唯一判据 | ✅ 第 4 轮必停 |
| 到达 4 轮时交什么 | 假设台账 + "按当前授权本问题不可判别" + 最小追加授权 | ✅ |
| Leader 只能做什么 | **三选一**：追加授权 / 判定不可测归档 / 关闭任务（[leader.md#review](../../../../roles/leader.md#review)） | ✅ |

**关键更正**：原版写"空转的**唯一**停止闸是 K=4"——**错误**。正确的表述是：

- 空转**不允许**用"次数用完"或"没成功"当停止理由（这两条确实不成立）；
- 但**总时间/资源、契约与范围边界随时可以停**；
- K=4 只是**专门针对"没有新信息"这种情况**的闸，且**是上限不是配额**——不要求用满。

**改前对照**：改前 Worker 可能在第一次"有效失败"就交回（太早），也可能硬撑到第 6 轮按 N 停（太晚且理由错）。**改后：判断无新信息即可停；满 4 轮必停。**

<a id="case-3"></a>
## 案例 3 · 总时间耗尽（补强）

**场景**：派工单给 `T2: 4 次 / 3600 s 总墙钟`。Worker 修复顺利，第 3 次真实运行中途累计墙钟已达 3600 s，验收判据还差 1 项。

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 是否继续 | **停**：总时间用尽是硬约束（[#batch](../../../../README.md#batch) 停止判据表、[#run-tiers](../../../../README.md#run-tiers)） | ✅ 停 |
| **是否因为"4 次还没用完"而可以继续** | **不可以**：次数是估算、时长是硬约束；**剩余次数不能兑换时长** | ❌ |
| 怎么停 | 在 `report.md` 写状态 `待审查`（资源耗尽类），`send_message` 唤醒 Leader | ✅ |
| 报告写什么 | 已完成项 + **未完成项及原因**（"总时长用尽"，不是"次数用尽"） | ✅ |
| Leader 怎么办 | 追加授权（新总时长）或裁定收口；不得把"时间用尽"记成"不可测"（[leader.md#review](../../../../roles/leader.md#review)） | ✅ |

**补强点**：原版只写"停"，未排除"次数还有余额"这条误读。**改后明确：剩余次数不构成继续理由。**

<a id="case-4"></a>
## 案例 4 · 文件越界（补强）

**场景**：修复需要改 `src/agc_task/**`，但本单白名单只有 `.coordination/**`；或顺带发现 `AGENTS.md` 有错字。

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 能不能改 | **不能**：只写本单白名单（[#files](../../../../README.md#files)、[#counts](../../../../README.md#counts) 边界表） | ❌ |
| **"次数只记账"能否授权改文件** | **不能**：记账规则**只管运行次数**，与文件边界无关 | ❌ |
| 并行下更严 | 共享文件由**指定拥有者**写；未指定先问 Leader（[#parallel](../../../../README.md#parallel)） | ❌ |
| 该怎么办 | 停，`report.md` 记"需改 X + 原因 + 证据"，按**阻塞**唤醒 Leader | ✅ |
| 能不能"先改了再报告" | **不能**：披露义务 ≠ 授权 | ❌ |
| 能不能改别的单的文件 | **不能**：只记录不改（[#parallel](../../../../README.md#parallel) 冲突处置 3） | ❌ |

<a id="case-5"></a>
## 案例 5 · 并行资源冲突（补强）

**场景**：F1 持有仿真运行；F3 想用 GZ 复现一段日志；同时发现 `.coordination/README.md` 已被 Leader 改过。

| 步骤 | 改后规则 | 判定 |
|---|---|---|
| 能不能起仿真 | **不能**：派工单没写"独占 GZ"就不得启动（[#parallel](../../../../README.md#parallel) 独占资源） | ❌ |
| **F3 自己写的是 `T2=0`** | **更不能**：明确 0 = 一次都不能启动（[#counts](../../../../README.md#counts) 边界表） | ❌ |
| 已被别人占用时 | 停，记 `ps`/运行标识，按**阻塞**唤醒 Leader；**不等待轮询、不抢占、不清理** | ✅ |
| 能不能 `pkill` 掉 F1 的进程 | **不能**：不终止他人进程、不清 `/dev/shm` | ❌ |
| 共享文件被别人改过 | 记 `git status` 证据报告；**不覆盖、不回滚、不 `git checkout`** | ✅ |
| 别的单阻塞了，我要不要停 | **不要**：各链状态独立（[#parallel](../../../../README.md#parallel) 状态隔离） | ✅ |
| 谁写 CURRENT | **Leader 独占**；Worker 不写也不改状态字段（[#files](../../../../README.md#files)） | ✅ |

<a id="summary"></a>
## 走查汇总

| 案例 | 主触发 | 改后的停止闸 | 明确**不**是停止闸 |
|---|---|---|---|
| 1 已知根因（建议次数用尽） | 无（继续） | 总时长/边界/契约/目标 | 建议次数、轮数、单次失败 |
| 2 未知根因空转 | 无进展 | **K=4**（并列于其余三类，不要求用满） | 次数、"没成功" |
| 3 总时间耗尽 | 资源耗尽 | **总墙钟/总时长** | 剩余次数 |
| 4 文件越界 | 阻塞（越界） | 白名单/共享拥有者 | 任何计数 |
| 5 并行资源冲突 | 阻塞（冲突） | 独占资源/明确 0 | 抢占、轮询、清理他人资源 |

**一致性**：五案例覆盖四类并列停止闸；案例 1 与案例 3 一起划清"估算差异（继续）"与"硬约束（停）"的分界。
