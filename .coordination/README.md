# Leader / Worker 人工交接

用户只与 **Leader**（DSH 高质量模型）讨论项目；Leader 派生 **Worker**（DSH 一般模型）实施，双方通过本目录交接。**交接在同一 DSH 进程内完成**：Worker 用 `send_message` 通知 Leader 审查，Leader 用 `send_message` 复用同一 Worker 会话派下一轮。不等待、不轮询、不接下一单。见 [交接与复用](#auto-wake)。

执行方统一称 **Worker**；历史轮次保留当时署名（Codex / DSH / Trae / DeepSeek），不追溯改写。

<a id="roles"></a>
## 职责与内容归属

- Leader（高质量模型）：梳理进度、定位故障、裁定方案、派工、独立审查证据、安排下一步。见 [Leader 职责](roles/leader.md#role)。
- Worker（一般模型）：按派工单实施、构建、运行指定实验并如实回报；可提诊断与替代方案，范围/口径变更交回 Leader。见 [Worker 职责](roles/worker.md#role)。
- 用户：目标、授权、重大取舍。

## 协作原则

来源：用户 2026-10-27 裁定；2026-10-28 调整为 Leader/Worker 双模型；2026-10-31 并行授权修订见 [并行任务](#parallel)。

- **单任务链**：**一条任务链内**一次只推进一个任务 ID。实现、返工、验证、审查都是该任务的后续轮次；同一链在验收或归档前不创建新任务流或隐含支线。**跨链并行按用户授权与 [并行任务](#parallel) 执行**——并行不是"同一链内插支线"，也不能成为跳过本链验收的理由。
- **批次授权**：审查单元是**批次**而非单轮（见 [批次授权](#batch)）。Leader 一次授权 Worker 在**目标、资源总量与总时间**内连续自主推进；仅在里程碑/阻塞/资源耗尽/契约风险四类事件唤醒。**唤醒次数**是主要成本，不是审查篇幅；**记录轮数不是停止条件**。
- **决策自主与暂停边界**：Leader 可在已批准范围、资源总量、契约、验收口径内自主裁定重大技术方案，并把决定与依据写入任务记录。只有改变范围/契约/资源总量/验收口径、执行破坏性或不可逆外部动作、或用户要求先确认时才暂停等用户。Worker 可提方案，但不能自行改变这些边界。
- **消息来源**：任务、报告、审查、状态变更与关键判断必须标明来源（用户/Leader/Worker）。日志、哈希、命令输出是证据引用，不能替代三方结论或冒充来源。
- **停止与状态完整性**：出现契约硬约束违规、基线未知漂移、guard 拦截、**资源总量或总时间耗尽**、**并行资源冲突**、必要证据缺失、通知失败或越界时，立即停止并回报；不静默重试、不扩大范围、不伪造证据、**不自行改交接状态**、不开下一任务。**建议次数用尽本身不是停止条件**（见 [计数只记账](#counts)），但**它也不授权任何未授权的运行或越界写入**。任务只有经 Leader 独立审查才能验收归档。

真源分层：项目执行以 [项目完成路线](../docs/plan/README.md#plan-index) 为入口；决策归 `docs/adr/`（[索引](../docs/adr/README.md#adr-index)），进度归路线各阶段的出口判据，实验产物归 `experiments/`；历史 Runbook 在 [归档](../docs/archive/ROS2迁移步骤.md#top)（**不是**进度真源）。硬约束只引用 [契约真源](../docs/adr/0020-package-boundaries-and-runtime-topology.md#hard-constraints)。交接文件用稳定锚点引用，不复制规格或硬约束。

**入库范围**：本文件、`CURRENT.md`、`roles/`、`locks/README.md`——即**规则与当前交接状态**。
逐轮过程物（`task/<ID>/round-*/`、`drafts/`、`locks/*.lock`、`STOP-*.md`）**不入库**：
它们是执行期台账与运行时状态，结论按协作协议并入 ADR / `docs/` / `CURRENT.md`
（[ADR-0025](../docs/adr/0025-publishing-boundary-and-retirement.md#top) 同一口径）。纳入 Git 不代表自动提交或推送。

<a id="files"></a>
## 文件与写入归属

```text
.coordination/
├── README.md  CURRENT.md
├── roles/{leader,worker}.md
└── task/<任务 ID>/round-<轮次>/{request,report,review}.md   # 每条任务链一个目录（可并行多条链）
```

- `CURRENT.md`：唯一当前指针与状态；不在别处维护第二份状态表。**由 Leader 独占写入**（含接单/交回后的状态同步），并行批次下可列多行。**Worker 从不在 `CURRENT.md` 里改任何字段**——包括"领取""改执行中""置待审查"，这些一律只写在本轮 `report.md` 头部，由 Leader 据通知同步。
- `request.md`：Leader 写——目标、真源链接、基线、范围、步骤、资源总量、验收、停止条件。
- `report.md`：Worker 写——实际操作、文件差异、命令/退出码、证据位置、偏离与阻塞；未执行明确写"未执行"。**报告头部即该轮的权威状态**（领取时间、执行者、子会话 ID、轮末状态），Leader 据此更新 `CURRENT.md`。
- `review.md`：Leader 写——核查依据、通过项、问题与返工要求；**执行者不能代填验收结论**。

每轮独立保存，不覆盖上一轮；任务 ID 同日递增且不复用。接单必须同时核对任务 ID 与轮次，不能仅凭路径续旧任务。取消任务由 Leader 记录原因，不伪装为验收通过。

**台账归档**：任务验收或明确关闭后，其逐轮 `request/report/review` **不再保留为长期档案**（2026-11-03 起，结论并入 ADR / `docs/` 与 `CURRENT.md`）；`执行中/待审查/待返工/阻塞` 均留在 `task/`；**Worker 不归档、不创建下一任务**。**同一任务链**新任务发布前先归档上一任务；并行链之间互不阻塞（见 [并行任务](#parallel)）。禁止覆盖任务或轮次目录。

<a id="batch"></a>
## 批次授权与熔断

来源：用户 2026-10-29 裁定。**动因**：Leader 每次唤醒重付整个会话上下文（原记录"每次约 22 万 `cacheRead`"，2026-10-29 实测校准为**单 step 上下文重读量级**，一次唤醒含多步，见 [ADR-0026](../docs/adr/0026-leader-worker-collaboration-and-batch-authorization.md#top)(d)），单轮审查使唤醒次数与轮数 1:1。平台验证任务 24 轮 ≈ 530 万 `cacheRead`，其中第 19–24 轮在同一根因上空转、无实质进展。

> **成本原则**：贵的是**唤醒次数 × 每次唤醒步数 × 当前上下文规模**，不是审查篇幅。压缩手段是"一次授权多轮、一次审查一批"并让**每批少做往返**，**不是**缩短审查、更不是取消独立验收。
>
> **2026-10-29 实测校准**（「暂停与基线」「脚本整理」两任务的 Leader 会话）：一次工程唤醒 = 6–10 step、`cacheRead` 200–370 万；每 step 的 `cacheRead` 随会话上下文从约 2.7 万涨到约 36.8 万。**唤醒次数下降不等于 token 下降**——上下文更长的会话里，少一次唤醒只省一次"重读"，省不掉"写得更多"。`cacheRead` 降 75% 仍是**未验证**指标，见 [ADR-0026](../docs/adr/0026-leader-worker-collaboration-and-batch-authorization.md#top)(d)。

### N 与 K

| 参数 | 值 | 含义 |
|---|---|---|
| **N** | **6** | **记录检查点**：累计第 6 轮写一次"本轮小结 + 资源账目"。**不是停止上限、不触发唤醒**；不得因为"到第 6 轮"交回 |
| **K** | **4** | **熔断**：连续 **K** 轮无**区分性新证据**即触发，Worker 必须停止并提交假设台账 |

> **N 为什么不再是停止条件**（2026-10-31 修订，来源：用户裁定"优化已明确根因却因实验次数不足被迫返工"）：ADR-0026 的成本原则是"贵的是**唤醒次数**"，而轮数只是**记录单位**。用轮数触发唤醒，等于把已废弃的成本单元请回来，还会惩罚"已经查明根因、只差把修复验完"的批次。达到 N 时**继续做**，只补记账。

### 停止条件是四类，不是次数

批次内 Worker **只有**下列情形才停止并 `send_message` 唤醒 Leader；其余中间轮次**不唤醒**：

| 触发 | 判据 |
|---|---|
| **里程碑达成** | 派工单登记的验收判据全部满足 |
| **阻塞** | 无可行路径、需越白名单/契约、缺必要来源，或**并行资源冲突**（见 [并行任务](#parallel)） |
| **资源耗尽** | 本批次**总墙钟**用完，或**真实运行总时长**用完，或并行任务占满独占资源 |
| **契约风险** | 任一硬约束（[#hard-constraints](../docs/adr/0020-package-boundaries-and-runtime-topology.md#hard-constraints)）可能被破坏 |

**不唤醒的情形**（Worker 自行继续）：局部失败后按已知根因重试、探针失败但仍有未排除假设、常规证据积累、白名单内同根因修复、**已明确根因但还需若干次验证**、**记录轮数达到 N**、**建议次数用尽但仍有正向运行授权与剩余总时长**。

> **"有明确根因"是最强的继续理由**：根因已被证据锁定、修复在同范围内时，Worker 应**修完并验完**再交回，不因已用次数或已写轮数停工。这条针对「地图/入口」任务第 2 轮（T2 2/2 用满即停，而两次失败皆为自身工装缺陷且根因当轮已明）与「交付物」任务第 2 轮（4/4 时第 4 次是无效样本重试）。
>
> **"根因不明"才是停止理由，但走 K 而不是走次数**：仍可继续试新假设，只有连续 4 轮拿不出能区分假设的新证据才熔断。

### 批次内的轮次记录

批次内每轮**仍写** `request`/`report`（或等价记录），但：

- `request.md` 由 **Worker 自写**（Leader 只写批次首轮的总目标与边界）；
- 轮次目录照常递增，便于追溯；
- **状态只在 `report.md` 里写，且不逐轮改**：批次内中间轮只在 `report.md` 头部记该轮结论，**不标 `待审查`、不通知**；批次末（或四类触发事件）才在该轮 `report.md` 写 `待审查`。
  - **`CURRENT.md` 全程由 Leader 写**：Worker 的接单/执行中/待审查/阻塞都不写进 `CURRENT.md`，由 Leader 依据 `report.md` 与通知同步（[写入归属](#files)）。这条同时消掉了旧版"Worker 自行改交接状态"的口径。

> 这样 Leader 拿到的是一批完整证据，而非 6 次碎片。

### 停止判据：目标 / 资源 / 总时间 / 无进展

批次是否继续，只看下面四行。**计数（T1 次数、attempt 数、已写轮数、提交笔数）一律不进这个表**：

| 判据 | 何时停 | 何时不停 |
|---|---|---|
| **目标** | 验收判据全部满足 → 交回 | 未满足且仍有可行路径 → 继续 |
| **资源** | 批次**总墙钟**或**真实运行总时长**用完；或需越白名单/契约 | 单次运行失败 → 按已知根因重试并留痕，不把失败当"资源已用尽" |
| **总时间** | 派工单给的总时间到点 → 停并交未完成项 | 单轮用时长但总量未到 → 继续（单次时限仍受 [#run-tiers](#run-tiers) 约束） |
| **无进展** | 连续 **4 轮**无区分性新证据 → [熔断](#batch) | 每轮仍有能区分假设的新证据 → 继续，哪怕一直失败 |

**"未达成功"不等于"不可测"**：失败样本、被排除的假设、修好的夹具都是证据。只有**无法再设计出能区分假设的实验**（或所需授权拿不到）才叫不可测。

> **这四行是并列的，不是"只有 K 会停"**（2026-10-31 审查后修正）：总时间/资源耗尽、契约与范围边界**随时生效**，与轮数无关。K=4 管的是"方向还在试但不再有新信息"，**不能替代**上面三行，**也不是"允许先空转三轮"的许可**——**不得为了凑够四轮而重复无意义的实验**；一旦判断"再做也不会有新证据"，**当轮就该停**，不必等到第 4 轮。

<a id="counts"></a>
### 计数只记账（T1 / attempt / 轮数 / 提交）

**先立边界，再谈记账**：次数不是硬限，**不等于**"什么都能做"。下列边界**任何时刻都独立生效**，与次数无关：

| 不可自行突破的边界 | 判据 |
|---|---|
| **未授权不运行** | 派工单**未写**该类运行授权，或**明确写 0**（如 `T1=0`/`T2=0`）→ **一次都不能启动**。不得用"次数只记账"推出可以运行 |
| **文件边界** | 只写本单白名单；共享文件按 [并行任务](#parallel) 的拥有者规则 |
| **契约与硬约束** | 任一 [#hard-constraints](../docs/adr/0020-package-boundaries-and-runtime-topology.md#hard-constraints) 可能被破坏即停 |
| **单次物理边界** | T1 每次 ≤30 s、≤2 进程、不碰共享状态；T2 单次运行时长上限 |
| **总时长/资源总量** | 派工单给的墙钟与真实运行总时长，用尽即停 |
| **上级明确指定的硬限** | 用户或派工单**明确**以"外部配额、费用、硬件占用"等为由指定次数硬限时，**按指定执行**，不得以本节通则绕过；派工单须写明理由 |

在上述边界之内，才轮到"计数只记账"：

| 量 | 地位 | 要求 |
|---|---|---|
| **T1 次数** | 记账观测 | 逐次留痕；**超过建议值属估算差异，不是授权越界**（见下） |
| **T2 次数** | 资源信号 | 逐次留痕；**总时长是硬约束**。超过建议值 → 记"估算差异 + 理由 + 剩余时长" |
| **已写轮数（N）** | 记录检查点 | 第 6 轮写小结，不停止 |
| **提交笔数** | 记账观测 | 一次收尾提交为佳；账目更正按 [追加自查更正](#self-correction)，不为此自增提交 |

> **"建议次数"不是"授权次数"**（2026-10-31 审查后修订）：
> - 当派工单给出**正向运行授权**并规定了**总时长/资源边界**时，其中的"次数"只是**预算估算**，用于让 Leader 判断规模是否合理。**超出估算 = 估算差异**，如实记账并说明理由即可，**不构成授权越界**，也不触发停工。
> - 反过来，**"未授权"与"明确 0"得到同一个结论：不得启动**。没有正向运行授权就没有运行许可，这一点不因"次数只记账"而松动；"次数是估算"只在你**已经获得正向授权**之后才起作用。
> - **唯一例外是上级明确指定次数为硬限**（外部配额、费用、设备占用等）：此时按指定执行，理由写在派工单里，Worker 不得援引本节绕过。

### 熔断（K=4）

连续 **4 轮**未产出**能区分现有假设的新证据**，Worker **必须停止**，不再自行开轮，提交**假设台账**：

| 假设 | 状态（已排除 / 未排除） | 判别实验 | 判别所需授权 |
|---|---|---|---|
| … | … | … | … |

并明确写出：**"按当前授权，本问题不可判别"** 及所需的最小追加授权。

Leader 收到台账后只能三选一：**追加授权** / **判定不可测并归档为已知缺口** / **关闭任务**。**不得**再派"继续试试"式的空转轮次。

> **"区分性新证据"的判据**（供 Worker 预判、Leader 裁定）：本轮结论会让**至少一个未排除假设**的成立概率明显改变，或新排除/新确认一个假设。以下**不算**新证据：同一现象再观测一次、同因失败换参数重跑而无新排除、补充叙述、把已知事实重排一遍。
>
> **反过来说**：**修复 + 验证**是一个完整证据单元——根因已锁定后，把修复跑通（或跑失败并缩小了假设范围）都计入新证据，不因"又试了一次"被记空转。

### 派工单预登记停止条件（强制）

`request.md` **必须**写预登记停止条件。缺此项的派工单**不合规**，Worker 可要求补齐后再接单。

**必写的两条**（2026-10-31 修订）：

1. **资源/总时间**："总墙钟 X 秒、真实运行 Y 秒用尽即停，交回已完成项与未完成项"；
2. **无进展**："连续 4 轮（K=4）无区分性新证据即熔断并提交假设台账"。

**禁止的写法**："若 M 轮内未达成 X，则判定不可测并停止"——它把"**还没成功**"当成"**测不了**"，正是本次要消除的返工动因（「地图/入口」任务第 2 轮与「交付物」任务第 2 轮均以此为停工理由）。

**必须补写一句**："根因已锁定时，允许在同一白名单、同一资源总量内修完并验完，不因次数或轮数停工。"

> 平台验证六轮空转的根因是"没有无进展判据"，**不是**"没有轮数上限"——轮数上限对它无效（它 6 轮都触发不了任何上限，因为上限是 6）。

### 根因分析下放

- **Leader 不写判别逻辑**：批次派工单只给目标、边界、验收判据、资源总量与停止条件。
- **Worker 负责**：排序假设、设计判别实验、判定"根因是否已锁定"，给出建议下一步（写进批次末 `report.md`）。
- **跨轮诊断也归 Worker**：不再"遇跨轮诊断就交回"。只有**新假设需要越出白名单/契约/资源总量**时才交回。
- Leader 只做**选择与裁定**，不重做推理。

> 这一条砍掉 Leader 每轮最重的部分：重读证据 + 重想判别方案。

### 审查输入瘦身

批次末 `report.md` **必须**以 ≤30 行的 **"审查摘要"** 开头：结论、差异清单、证据链接、未决项。长日志只给路径。

Leader 审"摘要 + 抽样证据"；抽样比例与深度由 Leader 定，**独立验收职责不变**。

### 与既有条款的关系

- 本节**取代** [一轮交接](#workflow) 中"每轮必审查"的节奏，其余（接单核对、写入归属、状态完整性）不变。
- **不放松**：独立验收、基线核对、白名单、T2 "未派发不启动"、硬约束红线。
- **不改变**：一条任务链一个 Worker、链内单任务、用户介入用语。
- **2026-10-31 修订只改一件事**：把停止判据从**计数**换成**目标 + 资源总量 + 总时间 + 无进展**。它**不**放宽任何资源边界、文件边界、契约红线或验收标准。

<a id="parallel"></a>
## 并行任务（2026-10-31）

来源：用户 2026-10-31 明确授权"互不影响的任务可并行"，并覆盖旧规则中的全局单任务串行限制。落地约束见 [本批次授权](#parallel)。

**允许**：多条**独立任务链**同时存在，每条一个任务 ID、一个 Worker、一个独立轮次目录；返工复用原会话。

**不算并行授权**（照旧禁止）：

- 同一条链内开并行支线或第二个任务 ID；
- 用并行绕过本链的验收、熔断或预登记停止条件；
- 在未获授权时启动**独占资源**（ROS/GZ/PX4、构建、全链仿真）。

**四条硬边界**：

| 边界 | 要求 |
|---|---|
| **文件隔离** | 每单只写自己的 [写入白名单](#files)。**共享文件由指定拥有者写**，其他单只读；未指定拥有者时先问 Leader |
| **独占资源** | 同一时刻只有一个任务可占用仿真/构建/共享状态。派工单须写明"独占 X"；未写的任务不得启动 X。启动前核对既有运行，**不终止他人进程** |
| **CURRENT 单一写入** | `CURRENT.md` 由 **Leader 独占**（含接单/交回的状态同步）；Worker 只写自己任务的 `report`/`evidence`/`request`，**不写 CURRENT、不改任务状态字段、不归档、不写共享索引** |
| **状态隔离** | 各单状态独立流转，且**状态字段只在 CURRENT 上**（Leader 写）、各链 `report.md` 头部各记自己的轮末状态；某单阻塞不得阻止其他单推进，也不得被解读为整体阻塞 |

**冲突处置（一律先停后报，不自行裁决）**：

1. **写冲突**：准备修改的文件已有其他单的未提交改动 → 停下，在 `report.md` 记录路径与 `git status` 证据，按"阻塞"唤醒 Leader。
2. **资源冲突**：欲用的独占资源正在被其他任务/他人占用 → 停下，记录 `ps`/运行标识，按"阻塞"唤醒 Leader；**不得等待轮询、不得抢占、不得清理**。
3. **不一致发现**：发现其他单的改动与本单口径矛盾 → 只记录，不改别人的文件。

> 并行**不降低**独立性：每单仍需 Leader 独立审查；`subagent-settled` 与 `send_message` 就同一里程碑可能各唤醒一次，成本按"可能重复"计。

<a id="workflow"></a>
## 一轮交接

1. Leader 读项目入口与实际证据，写完整派工单，状态置 `待执行`。
2. **任务链首次派工**：Leader **只能用 `worker`** 创建 Worker（执行者路由由 Host 钉死为 workbuddy 分组 `hy4free` / `reasoningEffort: high`，无需传参；首选 `@huai_xin/dsh-workbuddy/intl` 不可用时由 `worker-route-fallback` 自动切到 `/cn`，再不行才到 trae 的 `deepseek-v4.1-flash`，Leader 不干预），把子会话 ID 记入本轮 `report.md`。**后续轮次复用同一子会话**，用 `send_message` 投递新派工，不重新创建；**阻塞**时按 [阻塞处置](#workflow) 结档并开新 Worker 续做。
3. Worker 先读本规则与当前指针，确认任务 ID、轮次、状态。**只有 `待执行`/`待返工` 可接单**。核对 HEAD、分支、已有改动与文件指纹，**把领取时间、执行者与"执行中"写入本轮 `report.md` 头部**后才开工。一个任务仅由一个执行会话处理。
   > **Worker 不改 `CURRENT.md`、不改任务的交接状态字段**（[写入归属](#files)）；`CURRENT.md` 的状态由 Leader 依据本轮 `report.md` 与 Worker 的交回通知同步。
4. Worker 追加回报、核对差异，**在本轮 `report.md` 头部写明轮末状态**（批次末/触发事件写 `待审查`），用 `send_message` 通知 Leader；随后**结束本轮，不等待、不轮询、不接下一单**。
   > **批次授权下**（见 [批次授权](#batch)）：批次内不逐轮唤醒，Worker 自写下一轮 `request.md` 并继续；**批次内中间轮既不通知、也不改任何状态标记**，只写 `report.md`。仅四类触发事件才通知。
5. Leader 亲自读差异与证据，追加审查结论。通过才设 `已验收`；需返工则写明要求、增轮次并设 `待返工`，再 `send_message` 通知同一 Worker。**同一任务链**验收或关闭前不得创建新任务流（**跨链并行**见 [并行任务](#parallel)）。
6. 无法继续时 Worker 在 `report.md` 写明现场与待裁定项、标注 `阻塞`；由 **Leader** 把 `CURRENT.md` 置 `阻塞`，裁定后才能改 `待返工`/`已关闭`。`执行中` 会话失联不自动重领，先由 Leader 核对进程与已产生改动。
7. Leader 在已验收/已关闭任务**结档**时把结论并入 `docs/`（ADR 或规范）与 `CURRENT.md`，逐轮台账随之删除；暂无任务时 CURRENT 设 `空闲`、ID 与轮次设 `无` 并链接最近结档。`task/` 可不存在；**空闲不接单**。

流转：`待执行 → 执行中 → 待审查 → 已验收`；分支 `待返工`/`阻塞`/`已关闭`。这些仅是交接状态，`已验收` 不代表 workstream 完成或实验 gate 通过。

**这些状态只有两处载体**：`CURRENT.md`（Leader 写）与各轮 `report.md` 头部（Worker 写）。**Worker 不写 `CURRENT.md`，Leader 不改 `report.md` 的既有事实**——两者各写一处，不重复维护状态表。

## 基线与执行边界

- 派工单记录 HEAD、分支与脏文件；HEAD 相同不能证明工作区相同。**已有改动不得重置、覆盖、清理或擅自提交**。影响本任务的未知变化先回报；派工单列明的预期变化可继续。
- 默认只允许修改本单白名单。需构建/实验时须同时明确产物目录、场景/seed/模式、**总时长与重试留痕要求**。**未派发的实验不启动**。运行按 [观测分级](#run-tiers) 授权，**不得把低风险观测与全链实验当作同一档**。
- Leader 审查期间 Worker 不继续改代码；**同机仿真/构建串行**，启动前核对既有运行，**不能自行终止他人进程**；并行任务下的资源冲突按 [并行任务](#parallel) 处置。
- 发现契约问题按项目入口红线停止并报告；需改目标、规格、资源总量或实施范围时回报 Leader。范围内的根因定位与常规修复按 [自主权限](#executor-autonomy)。
- 默认不执行 git commit/push/merge/reset/clean/stash/read-tree，不自动切换分支；需要时由派工单另行明确。并行共享工作区禁止 Worker 用 stash（含 apply/pop/drop）或 read-tree 做基线对比或自行恢复索引；发现误操作立即保存现场并通知 Leader。基线对比使用只读 `git diff <commit> -- <path>` / `git show <commit>:<path>`，不能暂存、移走他人改动。

<a id="run-tiers"></a>
### 观测分级（T0/T1/T2）

来源：用户 2026-10-27 授权。**目的只是把低风险观测与全链实验分开，不放松任何真实实验闸门。**

| 档 | 定义（须全部满足） | 授权方式 |
|---|---|---|
| **T0 零运行** | 静态读取、哈希、已有证据重算、`strings`/`nm`/`grep` 类检查；**不创建进程** | Worker 默认自主，无需派工 |
| **T1 微观测** | ① 墙钟 ≤30 s；② 进程数 ≤2；③ 独占 `/tmp/<本单前缀>-*`；④ **不启动** GZ/PX4/GUI/headless/全链仿真；⑤ **不碰**共享状态（不读 `/dev/shm` 内容、不清理他人进程/资源、不改系统/网络/库/时钟配置）；⑥ 无 root；⑦ 产出写本单产物目录 | 派工单**显式预授权**；写**总时长**（主约束）与**建议次数**（估算）。**未写入授权、或明确写 0 → 不得启动** |
| **T2 真实实验** | 全链仿真、GUI、headless、构建、抓包，或任一不满足 T1 条件 | **批次总量预授权**：**总时长/资源边界（硬）** + **建议次数（估算）**；`未派发不启动`。见 [计数只记账](#counts) |

- **授权的两种合法写法（都成立，不是二选一）**：
  - **写法 A（时长为主）**：`T1: 300 s（单次 ≤30 s），次数只记账`／`T2: 3600 s 总墙钟，次数只记账`——**次数不写也能授权**；
  - **写法 B（时长 + 估算次数）**：`T1: 20 次 / 600 s`／`T2: 4 次 / 3600 s`——其中"次数"是**估算**，用于让 Leader 判断规模，**超出属估算差异、不是越界**（[计数只记账](#counts)）。
- **判定口径（避免把正向时间授权误判为 0）**：
  - **有正向时间/资源授权 → 可以运行**，即使没写次数、或建议次数已用尽；
  - **只写了 0 或完全未授权 → 不得运行**（`T1=0`/`T2=0` 与"未写"同等）；
  - **判"能不能跑"看的是"有没有正向运行授权"，不是"次数还剩几次"**。派工单若只给"构建+运行合计 3600 s"这类时间授权，那就是**有效的正向授权**，不得因为"没写次数"而判 0。
- **按批次总量授权，不按轮切（2026-10-31 重申）**：批次派工单一次性写总量，Worker 在批次内**自行分配**，逐次留痕。
  - 理由：诊断类任务的探针数**本来就不可预知**；按轮切会导致"每轮只够试一点、试完交回"——这正是平台验证第 19–24 轮的形状。
  - **单轮不再有次数硬上限**（原来"单轮 ≤3 次 / ≤90 s"已删除）。
  - **每次运行都要计时**：无论有效、无效、重试、重复，**每个真实进程都计墙钟并计入资源账目**；"次数没超"不改变已消耗的时长（[计数只记账](#counts)）。
  - **重试**：无效样本（进程异常退出、自身工装缺陷、环境未就绪）可重试并留痕，**不设"每次失败只能重试 1 次"的硬闸**；有效失败（真实暴露的缺陷）是**证据**，写进 report 后按已知根因修复与重验，**不因"这是一次失败"而交回**。
- **T1 不自动获得**：派工单未给 T1 正向运行授权，或明确写 `T1=0`，不得运行；已按上述写法给出总时长授权时，不因缺建议次数误判为 0。禁止以"这是 T1"自行升级。
- **必须升级为 T2 的情形**：需要并发共享资源、需要改变他人可见状态、需要超 30 s 观测、或需要 T1 未列的组件。
- **边界不因名称放宽**：T1 仍受基线、白名单、产物目录与 [停止条件](#batch) 约束；T1 不是"小规模 T2"。
- **审查口径**：Worker 在预授权 T1 内执行并留痕属合规；未预授权而执行属越界；用 T1 名义绕 T2 派发属违规。

<a id="offline-budget"></a>
### 离线/静态检查的资源记账（2026-10-29 修订，2026-10-31 统一口径）

来源：Leader 在用户已授权的成本治理范围内裁定，作为「离线预算」的护栏修正。**依据**：「脚本整理」授权"离线检查最多 18 次"实际用到约 32 次，而**总墙钟不足 30 s、时间与资源维度一次未触碰**——次数字面越界成立，但把风险近乎为零的静态动作按次数切成硬限，会挤出"为省一次检查而少验一遍"的反向激励，也在边界附近制造多余唤醒。

| 维度 | 地位 | 要求 |
|---|---|---|
| **总墙钟** | **主约束** | 派工单给本单总秒数；耗尽即停并交回未完成项 |
| **单次时限** | **主约束** | 每次 ≤30 s；需超时必须升级为 T2 派发 |
| **明确资源边界** | **主约束** | 不启动外部真实进程、不碰共享状态、不读写外部树；违反即越界 |
| **次数** | **记账观测** | 逐次留痕、如实计入，**不作硬限、不因次数触发唤醒**；超出建议值属**估算差异**而非授权越界（[计数只记账](#counts)） |

- 适用范围仅限**只读/离线**动作：`pytest` 类离线测试、链接/索引/语法检查、`grep`/`read`、哈希比对。
- **不改变** [观测分级](#run-tiers)：`T1` 的"单次 ≤30 s、进程 ≤2、独占 `/tmp`"照旧；`T2` 仍"未派发不启动"，**未授权或明确 0 依然一次都不能启动**。本段只改"记账方式"，不是 T1 放宽，也不是"小规模 T2"。
- **不追溯豁免**：「脚本整理」的 32 次检查、7 笔提交仍按**当时**授权记为偏离（该批次的逐轮台账已于 2026-11-03 删除，见 [ADR-0025](../docs/adr/0025-publishing-boundary-and-retirement.md#top)）。本段只适用**此后新派的工单**。
- **提交纪律**（同源）：收尾时先完成全部自查与计数核对，**再一次**提交回报；不为修哈希或修账目自增提交，出现事实错误按 [追加自查更正](#self-correction) 如实追加。

<a id="self-correction"></a>
### 事实错误的追加更正

发现本轮回合的事实错误（漏记动作、表述失准、误写入、口径写错）时，可在审查结论出现前向本轮 `report.md` 追加"追加自查更正"段，写明触发来源与时间。该追加**不改状态、不改封存源、不改验收结论**。

<a id="post-archive-sidecar"></a>
### 封存后侧车

首次封存后仍需产生的记录（结束时钟、封存后基线复核、纠错、失败重试留痕）一律写在**封存源根之外**：

| 位置 | 用途 |
|---|---|
| 本轮 `report.md` 追加段 | 纠错、结束时钟、结论说明（首选） |
| `experiments/_archive/<campaign>/<run-id>.post-archive-<主题>.json` | 需机器可读的侧车 |
| `/tmp/<本单前缀>-*` | 过程性输出、归档命令 stdout |

- `_archive` 侧车不会被 `evidence_archive.py` 的 `list_runs()` 重新发现（跳过 `_archive`，只扫 `experiments/<campaign>/`），已验证，不会触发重归档、无需 `--force`。
- 口径：`_archive/<campaign>/<run-id>.tar` 及其同级侧车**不属于**源根；`experiments/<campaign>/<run-id>/` 内任何文件属于源根，封存后只读。
- 误写入源根时**必须**在 report 披露"写-删"事实；仅凭 `root==tar` 相等不足以证明过程未越界。

<a id="executor-autonomy"></a>
## Worker 的日常自主权限

来源：用户 2026-10-27 要求适度放宽；从新派工起生效，历史轮次不改写旧授权。

- **实施**：在已派目标、白名单、产物目录内自主选择实现细节、局部重构、修夹具及相邻同根因问题，无需逐次请示。可在本单目录内加必要的小型测试与诊断记录；冻结文件仍按派工执行。
- **节奏**：在本单**总时间与资源总量**内自主安排静态检查、局部离线测试、失败诊断、修复与重跑，不再限定"两次全套且禁止局部测试"。提交前对指定文件完成一次完整回归；之后改动受测代码须重验或明确标未验证。**T2 真实进程/构建/仿真/通信实验另按本单授权，不因"测试"之名自动获准**；T1 微观测按 [观测分级](#run-tiers) 的批次总量执行。
- **单轮目标（2026-10-31 修订）**：完成当前派工单并交回高质量证据。**根因已明确时，把修复做完并验完再交回**——不因"已用次数""已写轮数"停工。只有下列情形回报 Leader：**需越白名单/契约/资源总量**、**无法再设计出能区分假设的实验**、或**跨任务链的取舍**。
  - **根因分析归你**：排序假设、设计判别实验、判定根因是否锁定，都属本单范围（见 [根因分析下放](#batch)）；不再"遇跨轮诊断就交回"。定不了根因就走 [熔断（K=4）](#batch)，而不是走次数。
  - **不得以"自主诊断"扩大任务**：诊断必须落在本单目标范围内；跨目标的新方向属范围变更，须回报。
- **批次内自定下一轮（2026-10-29 新增，2026-10-31 修订）**：在 [批次授权](#batch) 的**目标、白名单、资源总量与停止条件**内，Worker **可自行决定下一轮做什么**并自写 `request.md`，无需 Leader 派工。
  - 边界：**不得**改变目标/白名单/验收判据/契约口径/资源总量，不得越过 [熔断](#batch) 的 K 轮判据，不得跳过预登记停止条件。
  - **轮数不构成边界**：N=6 是记录检查点，到点写小结后继续。
  - 若下一步需要越出上述任一边界，属"阻塞"类，必须唤醒 Leader。
  - 每轮仍须留痕；批次末 `report.md` 须含假设台账与"下一轮建议"。
- **留痕**：每次行为验证用唯一编号，保留命令、起止、退出码、完整输出与要求的 guard；**不得覆盖或删除失败记录**。离线诊断沿用相同隔离与假依赖边界，不用额外脚本绕过 guard。
- **可继续 vs 必停**：白名单内、资源总量内、**有明确根因**的局部修复可自行继续（含连续重验）；仅在需白名单外改动、改契约/验收口径、增共享资源动作、缺必要来源、未知保护变化、**总时间耗尽**或 guard 触发时停止回报。
- **重复尝试照常计入（2026-10-31 审查后修正）**：**没有"免费的重试"**。每一次真实运行——有效、无效、重试、重复同一实验——都**计入真实墙钟与资源消耗**，并**计入 [无进展台账](#batch)**。次数只是估算，**消耗是按秒算的**，不能因为"次数没超"就当作没花。
  - 由此得出的推论：**无区分性新证据的重复尝试不该做**——不是"做了不罚"，而是"做了既烧资源、又推进熔断计数"。正确做法是先设计能区分假设的实验，再做。
- **既有线索优先**：开工先查项目内已有记录（历史 `report`、`offline_comparison`、ADR、证据索引）是否已给出候选机制或已知约束；有线索就从线索继续，不重复从零推导。**引用既有文档必须读全相关条目，不得只取支持当前假设的那段**。
- **如实计入**：回报的"实际改动"必须覆盖全部写操作，含 typo 修正、误写入后的删除、被放弃的中间产物；"命令尝试次数"与"成功产物数"不得混用。

Leader 派工说明目标、边界与可判定验收，不逐个限制无风险的编辑/诊断动作；新单若有更严限制须说明原因。本节不改变写入归属、共享资源所有权、工具权限与独立验收职责。

## 后续任务写法

- `request.md`：任务 ID/轮次/日期 → 目标 → 真源与相关文件链接（按需：契约锚点、plan 文件、历史规格）→ 已学习的同类实现 → HEAD/分支/工作区基线 → 修改白名单与产物目录 → 步骤及资源授权 → 可判定验收 → 停止条件。
  - **资源授权必写**，两种写法都合法（[观测分级](#run-tiers)）：**时长为主**（如 `T1: 300 s，次数只记账`）或 **时长 + 建议次数**（如 `T1: 20 次 / 600 s`，次数是估算）。**明确 0 或未写 = 不得启动**。
  - **不要只写次数不写时长**：时长是硬约束，缺时长的派工单视为不合规。
  - **批次首轮额外必写**：`N=6`（记录检查点）、`K=4`、**批次总时长/资源总量**（次数可估算）、**预登记停止条件**。缺停止条件或总时长视为不合规。
  - **预登记停止条件的正确写法**：主判据写**总时间/总资源耗尽**与**连续 M 轮无可区分证据**；**不得**写"若 M 轮未达成 X 则判定不可测"（见 [派工单预登记停止条件](#batch)）。同时写明"**根因已锁定时允许同范围修完并验完**"。
  - **并行批次额外必写**：独占资源名、与其他单的文件边界、共享文件的拥有者（见 [并行任务](#parallel)）。
  - **批次内后续轮**：由 Worker 自写，只需写本轮目标/假设/判别实验/资源消耗，继承首轮边界。
- `report.md`：任务 ID/轮次/执行者/Worker 子会话 ID/起止时间 → **审查摘要（≤30 行）** → 接单基线 → 实际改动（区分原有改动）→ 命令、退出码与结果 → 证据路径 → 未执行项 → 偏离/阻塞/待裁定。长日志留产物目录，报告只链接；指标无法计算写明原因。
  - **批次末额外必写**：假设台账（假设 / 已排除·未排除 / 判别实验 / 所需授权）、下一轮建议、累计资源消耗（T1 次数、T2 次数与**总时长**、墙钟；次数如实列账，**不用次数解释停工**）。
- `review.md`：任务 ID/轮次/审查日期 → 实际核查的差异/命令/证据 → 验收条件逐项结果 → 结论 → 返工范围或下一步。**不得仅依据执行者自述宣告通过**。

## 交接与复用

来源：用户 2026-10-28 裁定——Leader 与 Worker 同属 DSH，不再需要外部叫醒脚本。

**机制**：两者在同一 DSH 进程、同一工作区，通过原生工具交接：

| 方向 | 工具 | 语义 |
|---|---|---|
| Leader → Worker（首轮） | `worker` | 创建子会话，执行者模型由 Host 钉死 |
| Leader → Worker（后续轮） | `send_message` | 复用同一子会话，冷恢复并保留上下文 |
| Worker → Leader | `send_message` | 通知审查，只表示"回报已就绪" |

- **一个任务一个 Worker**：同一任务链内不重新 `spawn`。子会话一轮结束只是 inactive，下轮 `send_message` 会恢复它。**例外**：任务被判 `阻塞`（或执行会话失联/被判死）时，先结档再为该链开新 Worker，见 [阻塞处置](roles/leader.md#blocked-handoff)。
- **执行者模型钉死**：`worker` 工具在 Host 侧固定 `@huai_xin/dsh-workbuddy/intl` / `hy4free` / `reasoningEffort: high`（与 Leader 同款）；`intl` 不可用时按 `worker-route-fallback` 链 `intl(hy4free) → cn(hy4free) → trae(deepseek-v4.1-flash)` 自动回退，Leader 不干预。**trae 是有意的混模型例外**：其目录不服务 `hy4free`，故该跳固定 `deepseek-v4.1-flash`。该路由写进子会话 descriptor，冷恢复沿用，与 Leader 当下所选模型无关。**现行值以 `~/.dsh/profiles/web/cordis.patch.yml` 为准；历史上写的 `deepseek-v4.1-flash` 全链、`cn` / `max`、以及含 `codearts` 的回退链均已过期。**
- <a id="worker-model-macro"></a>**Worker 模型只改一处（2026-11-07 起）**：`~/.dsh/profiles/web/cordis.patch.yml` 用 YAML 标量锚点把四处配置（钉死路由 / `subagent-model-selection-settings` 白名单 / `worker-route-guard` 白名单 / `worker-route-fallback` 链）收敛成一个宏。**换 Worker 模型只改 `&WORKER_MODEL` 那一行**，其余自动同步；`&TRAE_MODEL` 是 trae 例外的独立一行。约束：只锚标量、不用 `<<: *base`（patch 由 `js-yaml` 的 `JSON_SCHEMA` + `!!js` 方言解析，不支持 merge key）；别名不要指向映射（避免共享引用污染）。核对用 `dsh --profile web --dump-config`（以 noRefs 展开别名）。**改完只对新派工生效，现存 Worker 会话 descriptor 已固化**。CodeArts 适配器不可用，已全部删除，不得复活。
- **Leader 不得用 `subagent` 派工**（用户 2026-11-02 裁定）：Leader 派生执行者**只走 `worker`**。`subagent` 继承 Leader 当下模型，会让"一般模型 Worker"变成高质量模型，既破坏双模型分层，也会绕过钉死路由（实测：视觉最小闭环的子会话因此跑在 `totokens/gpt-6.1-sol` 上并撞余额不足）。
- **一次性任务用临时 Worker**：只读调研、单点核查等"原本用 `subagent` 的活儿"，改为开一个**临时 `worker`**（`prompt` 写清一次性范围与"不改文件/不跑仿真"），完成后不续用。临时 Worker 不受"一链一个 Worker"约束，因为它不承载任务链。
- **孙代路由受守卫约束**：白名单只在派工工具里检查显式选择；`workflow` 的 `agent()` 与裸继承会绕过它。`worker-route-guard` 挂在 `llm/stream`，`delegationDepth >= 2` 的会话只允许白名单路由，其余在发出前拒绝（`ROUTE_NOT_ALLOWED`），不花 token。孙代**可以**继续派，只是模型不能升级到 Leader 级。
- **只通知不等待**：`send_message` 返回的是"已入队"，不是"已处理"。发出后结束本轮，不读 `review.md`、不轮询、不接下一单。
- **派工后结束本轮**：`worker`/`subagent` 工具立即返回子会话 ID，不阻塞；子会话跑完由运行时把 `subagent-settled` 消息投进 Leader 收件箱（空闲时 `queue`、忙碌时 `steer`），作为下一步输入。**正确流程是派工即结束本轮**，靠结算通知唤醒；不要用 `sleep` 轮询。
- **轮询代价（2026-10-28 实测，2026-10-29 校准）**：Leader 每醒一次都要重付整个会话上下文。实测 14 次空转轮询共 4,354 输入 token，但每次 `cacheRead` 约 22 万 token（该数是**单 step 重读量级**；一次唤醒含多步，故实际唤醒成本更高，见 [ADR-0026](../docs/adr/0026-leader-worker-collaboration-and-batch-authorization.md#top)(d)）；而 idle 时零消耗，被结算通知唤醒只需 1 次短请求。空闲等待不是"免费"的，扇出多个任务应在同一条消息里并发派出，而不是串行醒来等。
- **不自动接单**：Worker 被唤醒只表示派工已就绪，不构成验收结论，也不代表可以自行开下一任务。
- **通知失败处置**：`send_message` 失败或状态未知时，如实记录在回报里、保持原状态、结束本轮；不得为了"通知成功"伪造状态推进。Leader 下次与用户讨论时按记录续查。
- **无跳数限制**：原 Codex/DSH 跨进程链的 4 跳硬闸随外部叫醒一并取消。防无人工回路改由 Leader 在每个审查点亲自裁定；Leader 不得连续自动派工超过用户授权范围。
- **历史工具已删除**：`coordination_wake.py`、`start_dsh_web.py`、`dsh_workspace.py`、`wake/targets.json`、`wake/chain.json` 及其测试已移除，见 [机制迁移说明](../docs/adr/0026-leader-worker-collaboration-and-batch-authorization.md#top)。

## 用户介入用语

自动交接是常态；下面用于手动介入（通知失败、需人工判断、任务阻塞）。

给 Leader：

> 继续当前交接任务，按 `.coordination/README.md` 决定验收或返工并安排下一步。

给 Worker（仅在需要时，通常由 Leader 用 `send_message` 完成）：

> 读取 `.coordination/README.md` 和 `.coordination/CURRENT.md`，按交接规则执行当前任务；完成或阻塞后把结论与状态写进本轮 `report.md` 并通知，**不改 `CURRENT.md`、不自行开始下一任务**。
