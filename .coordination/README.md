# Leader / Worker 人工交接

用户只与 **Leader**（DSH 高质量模型）讨论项目；Leader 派生 **Worker**（DSH 一般模型）实施，双方通过本目录交接。**交接在同一 DSH 进程内完成**：Worker 用 `send_message` 通知 Leader 审查，Leader 用 `send_message` 复用同一 Worker 会话派下一轮。不等待、不轮询、不接下一单。见 [交接与复用](#auto-wake)。

执行方统一称 **Worker**；历史轮次保留当时署名（Codex / DSH / Trae / DeepSeek），不追溯改写。

<a id="roles"></a>
## 职责与内容归属

- Leader（高质量模型）：梳理进度、定位故障、裁定方案、派工、独立审查证据、安排下一步。见 [Leader 职责](roles/leader.md#role)。
- Worker（一般模型）：按派工单实施、构建、运行指定实验并如实回报；可提诊断与替代方案，范围/口径变更交回 Leader。见 [Worker 职责](roles/worker.md#role)。
- 用户：目标、授权、重大取舍。

## 协作原则

来源：用户 2026-10-27 裁定；2026-10-28 调整为 Leader/Worker 双模型。

- **单任务链**：一次循环只允许一个任务 ID。实现、返工、验证、审查都是该任务的后续轮次；验收或归档前不创建新任务流、并行任务或隐含支线。
- **批次授权**：审查单元是**批次**而非单轮（见 [批次授权](#batch)）。Leader 一次授权 Worker 连续自主推进最多 **N=6** 轮，仅在里程碑/阻塞/预算耗尽/契约风险四类事件唤醒。**唤醒次数**是主要成本，不是审查篇幅。
- **决策自主与暂停边界**：Leader 可在已批准范围、预算、契约、验收口径内自主裁定重大技术方案，并把决定与依据写入任务记录。只有改变范围/契约/预算/验收口径、执行破坏性或不可逆外部动作、或用户要求先确认时才暂停等用户。Worker 可提方案，但不能自行改变这些边界。
- **消息来源**：任务、报告、审查、状态变更与关键判断必须标明来源（用户/Leader/Worker）。日志、哈希、命令输出是证据引用，不能替代三方结论或冒充来源。
- **停止与状态完整性**：出现契约硬约束违规、基线未知漂移、guard 拦截、预算耗尽、必要证据缺失、通知失败或越界时，立即停止并回报；不静默重试、不扩大范围、不伪造证据、不改状态、不开下一任务。任务只有经 Leader 独立审查才能验收归档。

真源分层：项目执行以 [Runbook](../docs/ROS2迁移步骤.md#usage) 为入口；规格归 `.trae/specs/<ws>/`，决策归 `docs/adr/`，进度归 [状态表](../docs/ROS2迁移步骤.md#status)，实验产物归 `experiments/`。硬约束只引用 [契约真源](../docs/ROS2迁移交接文档.md#hard-constraints)。交接文件用稳定锚点引用，不复制规格或硬约束。

本目录纳入 Git；`.trae/`、`experiments/` 沿用本地保留规则。纳入 Git 不代表自动提交或推送。

<a id="files"></a>
## 文件与写入归属

```text
.coordination/
├── README.md  CURRENT.md
├── roles/{leader,worker}.md
├── task/<任务 ID>/round-<轮次>/{request,report,review}.md   # 唯一当前任务链
└── archive/README.md + <任务 ID>/round-<轮次>/{request,report,review}.md
```

- `CURRENT.md`：唯一当前指针与状态；不在别处维护第二份状态表。
- `request.md`：Leader 写——目标、真源链接、基线、范围、步骤、预算、验收、停止条件。
- `report.md`：Worker 写——实际操作、文件差异、命令/退出码、证据位置、偏离与阻塞；未执行明确写"未执行"。首次派工时在此记录 Worker 子会话 ID。
- `review.md`：Leader 写——核查依据、通过项、问题与返工要求；**执行者不能代填验收结论**。

每轮独立保存，不覆盖上一轮；任务 ID 同日递增且不复用。接单必须同时核对任务 ID 与轮次，不能仅凭路径续旧任务。取消任务由 Leader 记录原因，不伪装为验收通过。

归档由 Leader 在验收或明确关闭后进行，见 [归档说明](archive/README.md#archive)。`执行中/待审查/待返工/阻塞` 均留在 `task/`；**Worker 不归档、不创建下一任务**。新任务发布前先归档上一任务，禁止覆盖任务或轮次目录。

<a id="batch"></a>
## 批次授权与熔断

来源：用户 2026-10-29 裁定。**动因**：Leader 每次唤醒重付整个会话上下文（实测每次约 22 万 `cacheRead`），单轮审查使唤醒次数与轮数 1:1。W8 验证任务 24 轮 ≈ 530 万 `cacheRead`，其中 6 轮（19–24）在同一根因上空转、无实质进展。

> **成本原则**：贵的是**唤醒次数**，不是审查篇幅。压缩手段是"一次授权多轮、一次审查一批"，**不是**缩短审查、更不是取消独立验收。

### N 与 K

| 参数 | 值 | 含义 |
|---|---|---|
| **N** | **6** | 单次授权 Worker 连续自主推进的**最大轮数**；达上限必须唤醒 Leader |
| **K** | **4** | 连续 **K** 轮无**区分性新证据**即触发熔断，Worker 必须停止并提交假设台账 |

### 唤醒触发（四类，缺一不可省）

批次内 Worker **只有**下列情形才 `send_message` 唤醒 Leader；其余中间轮次**不唤醒**：

| 触发 | 判据 |
|---|---|
| **里程碑达成** | 派工单登记的验收判据全部满足 |
| **阻塞** | 无可行路径、需越白名单/预算/契约、或缺必要来源 |
| **预算耗尽** | 本批次 `T1`/`T2`/attempt 预算用完，或达 N 轮上限 |
| **契约风险** | 任一硬约束（[#hard-constraints](../docs/ROS2迁移交接文档.md#hard-constraints)）可能被破坏 |

**不唤醒的情形**（Worker 自行继续）：局部失败后按已知根因重试、探针失败但仍有未排除假设、常规证据积累、白名单内同根因修复。

### 批次内的轮次记录

批次内每轮**仍写** `request`/`report`（或等价记录），但：

- `request.md` 由 **Worker 自写**（Leader 只写批次首轮的总目标与边界）；
- 轮次目录照常递增，便于追溯；
- **状态不逐轮改 `待审查`**：批次内保持 `执行中`，批次末统一置 `待审查`。

> 这样 Leader 拿到的是一批完整证据，而非 6 次碎片。

### 熔断（K=4）

连续 **4 轮**未产出**能区分现有假设的新证据**，Worker **必须停止**，不再自行开轮，提交**假设台账**：

| 假设 | 状态（已排除 / 未排除） | 判别实验 | 判别所需授权 |
|---|---|---|---|
| … | … | … | … |

并明确写出：**"按当前授权，本问题不可判别"** 及所需的最小追加授权。

Leader 收到台账后只能三选一：**追加授权** / **判定不可测并归档为已知缺口** / **关闭任务**。**不得**再派"继续试试"式的空转轮次。

### 派工单预登记停止条件（强制）

`request.md` **必须**写"若 M 轮内未达成 X，则判定不可测并停止"。缺此项的派工单**不合规**，Worker 可要求补齐后再接单。

> W8 六轮空转的根因之一：派工单只有预算、没有"多久没结果就停"。

### 根因分析下放

- **Leader 不写判别逻辑**：批次派工单只给目标、边界、验收判据、预算与停止条件。
- **Worker 负责**：排序假设、设计判别实验、给出建议下一步（写进批次末 `report.md`）。
- Leader 只做**选择与裁定**，不重做推理。

> 这一条砍掉 Leader 每轮最重的部分：重读证据 + 重想判别方案。

### 审查输入瘦身

批次末 `report.md` **必须**以 ≤30 行的 **"审查摘要"** 开头：结论、差异清单、证据链接、未决项。长日志只给路径。

Leader 审"摘要 + 抽样证据"；抽样比例与深度由 Leader 定，**独立验收职责不变**。

### 与既有条款的关系

- 本节**取代** [一轮交接](#workflow) 中"每轮必审查"的节奏，其余（接单核对、写入归属、状态完整性）不变。
- **不放松**：独立验收、基线核对、白名单、T2 真实实验闸门、硬约束红线。
- **不改变**：一个任务一个 Worker、单任务链、用户介入用语。

<a id="workflow"></a>
## 一轮交接

1. Leader 读项目入口与实际证据，写完整派工单，状态置 `待执行`。
2. **任务链首次派工**：Leader 用 `worker` 创建 Worker（执行者路由由 Host 钉死为 workbuddy / `deepseek-v4.1-flash` / `max`，无需传参），把子会话 ID 记入本轮 `report.md`。**后续轮次复用同一子会话**，用 `send_message` 投递新派工，不重新创建。
3. Worker 先读本规则与当前指针，确认任务 ID、轮次、状态。**只有 `待执行`/`待返工` 可接单**。核对 HEAD、分支、已有改动与文件指纹，写入领取时间与执行者，状态改 `执行中` 后才开工。一个任务仅由一个执行会话处理。
4. Worker 追加回报、核对差异，状态改 `待审查`，用 `send_message` 通知 Leader；随后**结束本轮，不等待、不轮询、不接下一单**。
   > **批次授权下**（见 [批次授权](#batch)）：批次内不逐轮唤醒，Worker 自写下一轮 `request.md` 并继续；仅四类触发事件才置 `待审查` 并通知。
5. Leader 亲自读差异与证据，追加审查结论。通过才设 `已验收`；需返工则写明要求、增轮次并设 `待返工`，再 `send_message` 通知同一 Worker。验收或关闭前不得创建新任务流。
6. 无法继续时 Worker 写明现场与待裁定项，设 `阻塞`；Leader 裁定后才能改 `待返工`/`已关闭`。`执行中` 会话失联不自动重领，先由 Leader 核对进程与已产生改动。
7. Leader 将已验收/已关闭任务移入 `archive/<任务ID>/` 再发布下一任务；暂无任务时 CURRENT 设 `空闲`、ID 与轮次设 `无` 并链接最近结档。`task/` 可不存在；**空闲不接单**。

流转：`待执行 → 执行中 → 待审查 → 已验收`；分支 `待返工`/`阻塞`/`已关闭`。这些仅是交接状态，`已验收` 不代表 workstream 完成或实验 gate 通过。

## 基线与执行边界

- 派工单记录 HEAD、分支与脏文件；HEAD 相同不能证明工作区相同。**已有改动不得重置、覆盖、清理或擅自提交**。影响本任务的未知变化先回报；派工单列明的预期变化可继续。
- 默认只允许修改本单白名单。需构建/实验时须同时明确产物目录、场景/seed/模式、attempt 与重试预算。**未派发的实验不启动**。运行按 [观测分级](#run-tiers) 授权，**不得把低风险观测与全链实验当作同一档**。
- Leader 审查期间 Worker 不继续改代码；同机仿真串行，启动前核对既有运行，**不能自行终止他人进程**。
- 发现契约问题按项目入口红线停止并报告；需改目标、规格、实验预算或实施范围时回报 Leader。范围内的根因定位与常规修复按 [自主权限](#executor-autonomy)。
- 默认不执行 git commit/push/merge/reset/clean，不自动切换分支；需要时由派工单另行明确。

<a id="run-tiers"></a>
### 观测分级（T0/T1/T2）

来源：用户 2026-10-27 授权。**目的只是把低风险观测与全链实验分开，不放松任何真实实验闸门。**

| 档 | 定义（须全部满足） | 授权方式 |
|---|---|---|
| **T0 零运行** | 静态读取、哈希、已有证据重算、`strings`/`nm`/`grep` 类检查；**不创建进程** | Worker 默认自主，无需派工 |
| **T1 微观测** | ① 墙钟 ≤30 s；② 进程数 ≤2；③ 独占 `/tmp/<本单前缀>-*`；④ **不启动** GZ/PX4/GUI/headless/全链仿真；⑤ **不碰**共享状态（不读 `/dev/shm` 内容、不清理他人进程/资源、不改系统/网络/库/时钟配置）；⑥ 无 root；⑦ 产出写本单产物目录 | 派工单**显式预授权** `T1: N 次`；Worker 在根因明确时自主执行，逐次留痕 |
| **T2 真实实验** | 全链仿真、GUI、headless、构建、抓包，或任一不满足 T1 条件 | 维持现状：逐轮派发，未派发不启动 |

- **T1 不自动获得**：派工单未写 `T1: N` 即视为 0 次，与 T0 同等。禁止以"这是 T1"自行升级。
- **T1 按批次授权（2026-10-29 调整）**：批次派工单一次性写 **批次总量**（如 `T1: 20 次 / 600 s 总墙钟`），Worker 在批次内**自行分配**，逐次留痕。
  - 理由：诊断类任务的探针数**本来就不可预知**；按轮切会导致"每轮只够试一点、试完交回"——这正是 W8 第 19–24 轮的形状。
  - 批次内仍受单次约束：每次 ≤30 s、进程 ≤2、不启 GZ/PX4/GUI、不碰共享状态。
  - 批次总量耗尽即触发唤醒（预算耗尽类），**不得**自行追加。
- **T1 硬上限（单轮）**：单轮累计 ≤3 次、≤90 s 总墙钟；批次内单轮仍受此限，但批次总量可跨轮累计。
- **T1 失败不自动重跑**：仅进程异常退出（无效样本）且根因明确时重试 1 次；有效失败须回报。
- **必须升级为 T2 的情形**：需要并发共享资源、需要改变他人可见状态、需要超 30 s 观测、或需要 T1 未列的组件。
- **边界不因名称放宽**：T1 仍受基线、白名单、产物目录、attempt 上限与 [停止条件](#protocol) 约束；T1 不是"小规模 T2"。
- **审查口径**：Worker 在预授权 T1 内执行并留痕属合规；未预授权而执行属越界；用 T1 名义绕 T2 派发属违规。

<a id="self-correction"></a>
### 事实错误的追加更正

发现本轮回合的事实错误（漏记动作、表述失准、误写入、口径写错）时，可在审查结论出现前向本轮 `report.md` 追加"追加自查更正"段，写明触发来源与时间。该追加**不改状态、不改封存源、不改验收结论**。

<a id="post-archive-sidecar"></a>
### 封存后侧车

首次封存后仍需产生的记录（结束时钟、封存后基线复核、纠错、失败重试留痕）一律写在**封存源根之外**：

| 位置 | 用途 |
|---|---|
| 本轮 `report.md` 追加段 | 纠错、结束时钟、结论说明（首选） |
| `experiments/_archive/<campaign>/<run-id>.post-archive-<主题>.json` | 需机器可读的侧车 |
| `/tmp/<本单前缀>-*` | 过程性输出、归档命令 stdout |

- `_archive` 侧车不会被 `evidence_archive.py` 的 `list_runs()` 重新发现（跳过 `_archive`，只扫 `experiments/<campaign>/`），已验证，不会触发重归档、无需 `--force`。
- 口径：`_archive/<campaign>/<run-id>.tar` 及其同级侧车**不属于**源根；`experiments/<campaign>/<run-id>/` 内任何文件属于源根，封存后只读。
- 误写入源根时**必须**在 report 披露"写-删"事实；仅凭 `root==tar` 相等不足以证明过程未越界。

<a id="executor-autonomy"></a>
## Worker 的日常自主权限

来源：用户 2026-10-27 要求适度放宽；从新派工起生效，历史轮次不改写旧授权。

- **实施**：在已派目标、白名单、产物目录内自主选择实现细节、局部重构、修夹具及相邻同根因问题，无需逐次请示。可在本单目录内加必要的小型测试与诊断记录；冻结文件仍按派工执行。
- **节奏**：在总预算内自主安排静态检查、局部离线测试、失败诊断、修复与重跑，不再限定"两次全套且禁止局部测试"。提交前对指定文件完成一次完整回归；之后改动受测代码须重验或明确标未验证。**T2 真实进程/构建/仿真/通信实验另按本单授权，不因"测试"之名自动获准**；T1 微观测按 [观测分级](#run-tiers) 的预授权次数执行。
- **单轮目标**：完成当前派工单并交回高质量证据。遇无明确根因、跨轮诊断、范围/口径/预算取舍时回报 Leader，由其负责根因分析、下一轮派工与推进；**不得以"自主诊断"扩大任务**。
- **批次内自定下一轮（2026-10-29 新增）**：在 [批次授权](#batch) 的 N 轮、白名单、预算与停止条件内，Worker **可自行决定下一轮做什么**并自写 `request.md`，无需 Leader 派工。
  - 边界：**不得**改变目标/白名单/验收判据/契约口径/实验预算，不得越过 [熔断](#batch) 的 K 轮判据，不得跳过预登记停止条件。
  - 若下一步需要越出上述任一边界，属"阻塞"类，必须唤醒 Leader。
  - 每轮仍须留痕；批次末 `report.md` 须含假设台账与"下一轮建议"。
- **留痕**：每次行为验证用唯一编号，保留命令、起止、退出码、完整输出与要求的 guard；**不得覆盖或删除失败记录**。离线诊断沿用相同隔离与假依赖边界，不用额外脚本绕过 guard。
- **可继续 vs 必停**：白名单内、预算内、有明确根因的局部修复可自行继续；仅在需白名单外改动、改契约/验收口径、增真实实验/共享资源动作、缺必要来源、未知保护变化、预算不足或 guard 触发时停止回报。无新增证据的重复尝试不消耗整轮预算。
- **既有线索优先**：开工先查项目内已有记录（历史 `report`、`offline_comparison`、ADR、证据索引）是否已给出候选机制或已知约束；有线索就从线索继续，不重复从零推导。**引用既有文档必须读全相关条目，不得只取支持当前假设的那段**。
- **如实计入**：回报的"实际改动"必须覆盖全部写操作，含 typo 修正、误写入后的删除、被放弃的中间产物；"命令尝试次数"与"成功产物数"不得混用。

Leader 派工说明目标、边界与可判定验收，不逐个限制无风险的编辑/诊断动作；新单若有更严限制须说明原因。本节不改变写入归属、attempt 上限、共享资源所有权、工具权限与独立验收职责。

## 后续任务写法

- `request.md`：任务 ID/轮次/日期 → 目标 → Runbook 与三件套链接 → 已学习的同类实现 → HEAD/分支/工作区基线 → 修改白名单与产物目录 → 步骤及预算（**含 `T1: N 次` 预授权或明确 0**）→ 可判定验收 → 停止条件。
  - **批次首轮额外必写**：`N=6`、`K=4`、批次总量预算、**预登记停止条件**（"若 M 轮未达成 X 则判定不可测"）。缺停止条件视为不合规。
  - **批次内后续轮**：由 Worker 自写，只需写本轮目标/假设/判别实验/预算消耗，继承首轮边界。
- `report.md`：任务 ID/轮次/执行者/Worker 子会话 ID/起止时间 → **审查摘要（≤30 行）** → 接单基线 → 实际改动（区分原有改动）→ 命令、退出码与结果 → 证据路径 → 未执行项 → 偏离/阻塞/待裁定。长日志留产物目录，报告只链接；指标无法计算写明原因。
  - **批次末额外必写**：假设台账（假设 / 已排除·未排除 / 判别实验 / 所需授权）、下一轮建议、累计预算消耗。
- `review.md`：任务 ID/轮次/审查日期 → 实际核查的差异/命令/证据 → 验收条件逐项结果 → 结论 → 返工范围或下一步。**不得仅依据执行者自述宣告通过**。

## 交接与复用

来源：用户 2026-10-28 裁定——Leader 与 Worker 同属 DSH，不再需要外部叫醒脚本。

**机制**：两者在同一 DSH 进程、同一工作区，通过原生工具交接：

| 方向 | 工具 | 语义 |
|---|---|---|
| Leader → Worker（首轮） | `worker` | 创建子会话，执行者模型由 Host 钉死 |
| Leader → Worker（后续轮） | `send_message` | 复用同一子会话，冷恢复并保留上下文 |
| Worker → Leader | `send_message` | 通知审查，只表示"回报已就绪" |

- **一个任务一个 Worker**：同一任务链内不重新 `spawn`。子会话一轮结束只是 inactive，下轮 `send_message` 会恢复它。
- **执行者模型钉死**：`worker` 工具在 Host 侧固定 `@huai_xin/dsh-workbuddy/cn` / `deepseek-v4.1-flash` / `reasoningEffort: max`，与 Leader 当下所选模型无关；该路由写进子会话 descriptor，冷恢复沿用。需换模型时才用 `subagent` 显式传参，白名单只放行 workbuddy/trae 两条 `deepseek-v4.1-flash`。
- **孙代路由受守卫约束**：白名单只在派工工具里检查显式选择；`workflow` 的 `agent()` 与裸继承会绕过它。`worker-route-guard` 挂在 `llm/stream`，`delegationDepth >= 2` 的会话只允许白名单路由，其余在发出前拒绝（`ROUTE_NOT_ALLOWED`），不花 token。孙代**可以**继续派，只是模型不能升级到 Leader 级。
- **只通知不等待**：`send_message` 返回的是"已入队"，不是"已处理"。发出后结束本轮，不读 `review.md`、不轮询、不接下一单。
- **派工后结束本轮**：`worker`/`subagent` 工具立即返回子会话 ID，不阻塞；子会话跑完由运行时把 `subagent-settled` 消息投进 Leader 收件箱（空闲时 `queue`、忙碌时 `steer`），作为下一步输入。**正确流程是派工即结束本轮**，靠结算通知唤醒；不要用 `sleep` 轮询。
- **轮询代价（2026-10-28 实测）**：Leader 每醒一次都要重付整个会话上下文。实测 14 次空转轮询共 4,354 输入 token，但每次 `cacheRead` 约 22 万 token；而 idle 时零消耗，被结算通知唤醒只需 1 次短请求。空闲等待不是"免费"的，扇出多个任务应在同一条消息里并发派出，而不是串行醒来等。
- **不自动接单**：Worker 被唤醒只表示派工已就绪，不构成验收结论，也不代表可以自行开下一任务。
- **通知失败处置**：`send_message` 失败或状态未知时，如实记录在回报里、保持原状态、结束本轮；不得为了"通知成功"伪造状态推进。Leader 下次与用户讨论时按记录续查。
- **无跳数预算**：原 Codex/DSH 跨进程链的 4 跳硬闸随外部叫醒一并取消。防无人工回路改由 Leader 在每个审查点亲自裁定；Leader 不得连续自动派工超过用户授权范围。
- **历史工具已删除**：`coordination_wake.py`、`start_dsh_web.py`、`dsh_workspace.py`、`wake/targets.json`、`wake/chain.json` 及其测试已移除，见 [机制迁移说明](../docs/adr/0102-leader-worker-dual-model-handoff.md)。

## 用户介入用语

自动交接是常态；下面用于手动介入（通知失败、需人工判断、任务阻塞）。

给 Leader：

> 继续当前交接任务，按 `.coordination/README.md` 决定验收或返工并安排下一步。

给 Worker（仅在需要时，通常由 Leader 用 `send_message` 完成）：

> 读取 `.coordination/README.md` 和 `.coordination/CURRENT.md`，按交接规则执行当前任务；完成或阻塞后写回报告并更新交接状态，不自行开始下一任务。
