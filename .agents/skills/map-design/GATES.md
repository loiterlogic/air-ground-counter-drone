# 几何可行性闸门（按需资源）

本文件回答："这个候选布局能不能用？"所有口径都**复刻自代码**，不是本文发明的。
阈值属于**验收口径**：要改就交回 Leader 裁定，别在核验器里偷偷放宽。

> 本文只给**公式与判据**，不给"当前值"。当前值跑：
> `python3 tests/w6_geometry_check.py --out /tmp/geom.json`（约 15 s，只读，退出码 0 = PASS）。

## 0. 先复刻，再设计

**做法**：写一个**只读**脚本，对候选布局算下面全部闸门，迭代到全绿才写真源。
要求：

- 口径必须与 [`tests/w6_geometry_check.py`](../../../tests/w6_geometry_check.py) **逐项一致**，
  否则你在"假绿"上做设计；
- 沙箱路径独占（`/tmp/<本单前缀>-*`），脚本**入库**到 `tests/` 或 `scripts/`
  （历史版丢在 `/tmp` 被清理，最危险的判据因此整轮无法复现）；
- 核验器写完先**自测**：喂一个故意违规的用例，确认它会报 FAIL。

**两个历史上真实发生过的偏松错误**（会让核验器"看起来在跑"）：

1. `cylinder` / `sphere` 的 `size[0]` 是**半径**。当直径用再除以 2 → 重叠与净空**全部偏松**，
   比偏严更危险（它会掩盖问题）。
2. 复合体里 part 的 `yaw` 是**相对量**。再叠一次实体 yaw → 布局错位、重叠检测失真。
   世界系朝向 = 实体 yaw + part yaw。

## 1. 安全层圆盘（派生量，很多闸门都建在它上面）

空中安全层是**二维静态圆盘**模型（`safety_shield.cpp`），圆盘半径：

```text
disk_r(entity) = safety_radius + obstacle_margin + extra
extra         = reaction_time_s × max_speed_mps + reachability_margin
```

`obstacle_margin` / `reaction_time_s` / `max_speed_mps` / `reachability_margin` 是**安全余量参数**，
读 `agc_air/config/air.yaml` 的 `trajectory_tracker.safety`，**不要**在核验器里写死。
`safety_radius` 是**几何**派生量，规则见
[SCHEMA-AND-DERIVATION.md](./SCHEMA-AND-DERIVATION.md#safety-radius)。

**待机环带**（standoff 驻留的径向区间）半径：

```text
ring_r = target_min_dist + target_margin + extra
```

注意：**`target_min_dist`（`air.yaml` 的安全参数）与 `safe_min` / `safe_max`
（`standoff_follower` 的距离带）是两条不同来源的参数**，数值会随标定漂移。
核验器里用 `[safe_min, safe_max]` 做**可行单元**统计、用 `ring_r` 做**圆盘判定**，别混、也别抄数字。

## 2. 七个设计闸门

### (1) 8 字轨迹净空 —— **没有正式断言，须自己算，且别把结论说过头**

`w6_geometry_check.py` **只查待机环带**，不查参考轨迹是否被静态膨胀圆盘切到。
所以设计时要自己算；算出来的**含义**必须说准。

轨迹形状以 `agc_air/config/air.yaml` 的 `traj.rx / traj.ry` 与 `agc_control` 的
`Figure8Trajectory` 实现为准（形状的契约语义见
[硬约束](../../../docs/ROS2迁移交接文档.md#hard-constraints)，此处**不复述条文**）：

```text
x(θ) = center_x + rx · sinθ
y(θ) = center_y + ry · sinθ · cosθ        （= (ry/2)·sin2θ）
```

**判据（与安全层同口径，推荐）**：在轨迹上密采样 θ，对每个实体算

```text
min_θ [ ‖p(θ) − anchor(entity)‖ − disk_r(entity) ]  ≥ 0
```

历史核验器记录的最紧实体是小型标志物这类**边缘件**，说明最优点常出现在轨迹与实体的
"擦边"处——采样要密，别只查端点。

**辅助口径（几何，不是安全层）**：`点到实体水平足迹的距离 − 足迹外伸 ≥ 0`。
两条口径**不等价**（圆盘是外接圆，比足迹保守得多），报告时写清用的是哪一条。

**负值说明什么、不说明什么**：它只意味着**名义参考轨迹**的部分采样点落在
**当前静态膨胀圆盘**内。它**不**证明：

- 运行期实际使用的参考 / 偏置后的跟踪目标同样落在里面；
- 经安全滤波后的执行轨迹一定被阻断、演示一定跑不起来；
- 契约已被违反。

这些必须**分别核对实际生效路径与运行证据**（参考轨迹怎么生成、偏置与饱和在哪一层、
安全层实际拦了什么、跑起来后的日志与终态）才能下结论。**负值是设计信号，不是失败判决；
正值也不等于运行期一定安全。**

**登记口径**：官方当前**没有**这条断言，所以任何地图（含核查基线）出现负值都按**未决**
登记并交回 Leader 裁定。技能**不**为任何地图开例外、不新增或放宽判据、不改基线几何。

### (2) 待机环带可行解 —— 核查断言 (i)

在 `ring_r` 的圆周上做**密集角向采样**（数千点，脚本里是 `3600`）；某样本被任一实体圆盘覆盖即"阻塞"。

```text
可行率 = 未阻塞样本 / 总样本                 （> 0）
最长连续可行弧（环形遍历） ≥ 90°             （够 standoff 驻留）
```

"相对 minimal 新增多少阻塞单元"**只登记、不参与 pass**：中央加了内容后环带受挤压是**预期**
（但增加多少要实测，不要预设）；判据是"仍存在可行解"，不是"不比 minimal 多"。

### (3) C7 出生净空 —— 核查断言 (g)

与 `scenario_reset.validateCandidate` **同一判据**：用逐**图元足迹**距离，
不是实体中心距离。

- 每个实体 ↔ 车 / 目标 / 己方机的**足迹净空 > 0**；
- 车 ↔ 目标 ≥ C7 标定下限（阈值在核查脚本里，与 `scenario_reset.validateCandidate` 同判据）；
- 车仍在作业区边界内缩范围内。

出生点常量在核查脚本里（`CAR_XY` / 目标 / `OWN_XY`）+ `scenarios.yaml` 的 `scenario_reset`。
**改了出生点要同时核这两处**，别只改一处。

### (4) 实体互不重叠 —— **只在离线核验器里**

用逐图元**SAT**（分离轴）判，不是包围盒相交。官方核查**不查这一项**：
加新实体（尤其参照物）时最容易压到既有足迹上。

### (5) 地面激光可见性 —— 核查断言 (h)

地面激光是**单一水平面**（扫描面高度是脚本里的 `LASER_PLANE_Z_M`，由车体 `lidar_link`
安装高度决定，随车体模型变）。每个实体必须在 `z ∈ [z0, z1]` 区间内
**穿过该平面**（有一个 part 的绝对高度区间包含该高度）。

- 复合体：绝对 z = 锚点 z + part 局部 z（锚点 z 必须为 0，见 schema 资源）；
- **矮墙 / 悬空结构 / 薄片对它不可见**。若确实要加，必须在文档里如实标注
  "该障碍对地面激光不可见"，**不得假装能避**。
- ⚠ **可见性只决定"怎么披露"，不决定"放哪儿"**：要成为真实障碍，就得进几何真源并接受
  可见性核查；**不能**因为"反正看不见"就把它改写成视觉层。归属规则见
  [SCHEMA-AND-DERIVATION.md](./SCHEMA-AND-DERIVATION.md#visual-vs-obstacle)。

### (6) 并集覆盖率 + 多样性 —— 核查断言 (o)

```text
覆盖率 = 并集投影面积 / 作业区面积
```

- **并集**，不是图元和：同一实体多图元堆叠只应计一次（旧"图元和"口径把堆叠重复计数）；
- 栅格 `res = 0.2 m`，逐图元多边形（box 4 角 / cylinder、sphere 用 16 边形近似）做点在多边形内；
- 区间与实体上限是**验收口径**，断言名与阈值以核查脚本为准（不在本文抄数字）。

同类断言还要求**尺寸 / 高度 / 朝向 / 形状长尾**与"中央有内容"——它们是"真实感"的量化来源，
不是审美：全部等大 = 玩具感。阈值见核查脚本，**不要**在核验器里另设一套。

**加任何物件之前先算面积余量。** 覆盖率上限很紧，等核查 FAIL 才发现就晚了。

### (7) 明度带 —— 核查断言 (q)

```text
屋面 albedo 亮度 L − 基层地面 albedo 亮度 L ≥ 阈值（在核查脚本里，不是本文）
L = 0.2126·r + 0.7152·g + 0.0722·b
```

且屋面必须用 `roofpanel` 档（低金属度）。**关键实测结论**：无环境贴图时
`metalness` 才是亮度杠杆——给高金属度件"提亮 albedo"几乎无效。
判据取 `finish: roofpanel` 图元 `color` 的最小亮度；地面若带 `albedo_map`，
基色要去 `src/agc_sim/materials/manifest.json` 的 `base_srgb` 取（不是 SDF 里的白）。

## 3. 闸门之间会互相踩（所以是联合求解）

| 动作 | 连带后果 |
|---|---|
| 中央加内容 | 挤掉待机环带可行弧、压到 8 字带的采样点 |
| 加建筑 / 加参照物 | 顶爆并集覆盖率上限 |
| 拉一根通长围墙 | 细长实体的安全圆盘 ≈ 半长 → 静态圆盘可能覆盖大块空域（见下） |
| 改作业区尺寸 | 覆盖率、栅格数、复位边界、三图一致性**同时**变 |

**分段长墙是本项目已裁定的结构选择**：现实围墙本就按柱距分段；分段后每段圆盘半径小，
静态圆盘对空域的占用随之下降。这是**布局结构**上的取舍，不是审美偏好，
也不能反过来被当作"通长墙一定导致运行失败"的判据。

## 4. 设计侧布局范式（判据之外，决定"像不像真的"）

现实工业场站 = **功能分区 + 网格对齐 + 道路留白 + 尺寸长尾 + 中央留空**，不是均匀随机撒点
（[ADR-0106](../../../docs/adr/0106-work-area-100x100-and-yard-layout-paradigm.md)）。

- **分区**：北外环生产仓储 / 东区罐区管廊 / 南外环堆场 / 西区维修办公 / 中央南北两条带 / 周界；
- **对齐**：同类构件成排、yaw 取少数正交与个别特殊角，不做"全随机"；
- **留白**：主路与场坪成环，中央保留空场；
- **长尾**：最长/最短边比与高度比都要拉开，全等大 = 玩具感；
- **配色分族**：同族一致、族间可辨（生产仓储=冷灰+银灰蓝屋面 / 办公=暖灰+深色玻璃 /
  罐区=银白钢+仅一台标识色 / 集装箱=同排同色且**留一个空位**）。

**学范式，不抄资产**：能迁移的是"分区 + 对齐 + 留白 + 长尾"；
别人地图的尺寸、分区、资产都不适用于本项目的室外场站。
"先学后做"的取证顺序与真实来源见 [SKILL.md](./SKILL.md#工作循环) 与
[EVIDENCE.md](./EVIDENCE.md#11-先学后做的取证顺序)。
