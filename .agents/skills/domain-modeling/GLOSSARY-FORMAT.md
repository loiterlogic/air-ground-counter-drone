# GLOSSARY.md 写法（本仓库）

本仓库是**单上下文**仓库：只有根目录一个 [GLOSSARY.md](../../../GLOSSARY.md)，没有 `GLOSSARY-MAP.md`，也不需要多上下文映射。若将来真的拆出多个上下文，再引入映射文件。

## 结构

```md
# {项目/上下文名}

{一两句说明这个上下文是什么、为什么存在。}

## 语言

**术语键**:
{一两句释义—— 定义它**是什么**，不写它怎么实现}
_Avoid_: 被否的同义词、容易混淆的说法

**另一个术语**:
...
```

本仓库实际写法：

- 二级标题用 `## 语言`；
- 术语键加粗保留原始形式（`**AGC**`、`**LQR**`、`**DQN**`），释义用中文；
- 每条术语下用 `_Avoid_:` 列出被否的说法；
- 释义里需要指向决策时用稳定锚点链接到对应 ADR。

## 规则

- **要有主见。** 一个概念有多个说法时，选最好的那个，其余列进 `_Avoid_`。
- **定义要短。** 一到两句，说清"是什么"，不展开"怎么实现"。
- **只收本项目特有的概念。** 通用编程概念（超时、异常、工具函数）哪怕用得多也不收。判断方法：它是这个项目独有的概念，还是通用编程概念？只有前者进表。
- **术语表不是规格。** 不写实现细节、不当草稿本、不当决定仓库—— 实现决定进 ADR 或规格。
- **约束只引用不复述。** 坐标系、唯一执行口、参数入口、硬约束、终态语义只在 [契约真源](../../../docs/ROS2迁移交接文档.md#hard-constraints) 里定义；术语表最多写一句"语义以契约为准"并给锚点。
- **成簇时可分组**：自然形成几组时加三级标题；只有一组时平铺就好。
- **过时术语不删，要标注。** 已退役/研究期的术语保留，但明确写"历史""研究期术语，当前阶段非必读"，避免读者按它做当前决策。

## 新增术语的流程

1. 先在 `GLOSSARY.md`、`docs/`、[ADR 索引](../../../docs/adr/README.md#adr-index) 里查是否已有名字；
2. 已有的就复用，不要造同义新词；
3. 确实新的才加，并写清与相邻概念的**边界**；
4. 加完检查释义里有没有把约束复述了一遍—— 有就改成引用。
