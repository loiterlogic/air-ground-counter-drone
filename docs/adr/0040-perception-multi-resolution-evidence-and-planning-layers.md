# 感知地图的多分辨率表示：证据层与规划层分离

## 背景

`dense_map` 的障碍是 box 0.6–1.2 m、cylinder r 0.25–0.40 m，而 `/agc/map` 只有 0.5 m 格。
ADR-0039 的整改把面积比从 1.801 降到 1.230，但**误覆盖率仍是 0.668**，稳定性 p99 仍有 104。
两个数字同时指向同一件事：

> 剩下的误差不是"地图整体膨胀"，而是**一个 0.5 m 格只能回答 0 或 100，
> 回答不了"这一格只有 31% 被障碍占据"**。

具体后果（都是 1–3 格宽的小目标才有的）：

1. 直径 0.5–0.8 m 的圆柱本身只覆盖 1–2 个 0.5 m 格；
2. 边界点稍微偏移，相邻格就被占据 —— 同一障碍在不同帧落入不同格；
3. 两个相距几格的障碍互相"借格"，边界误差互相叠加；
4. 观测足迹是连续点集，最终被强制压成离散的二值决策。

`shape_jitter = 0` 已经失去区分能力，也印证了这一点：该指标统计的是 OBB 形状，
而地图早已主要由 footprint 逐点累积产生 —— **形状稳定不等于足迹稳定**。

## 决策

### (a) 证据层 0.25 m，规划层 0.5 m，**整数倍 2**

`perception_resolution`（默认 0.25 m）是证据累积与 carving 的分辨率；
`/agc/map` 的 `resolution`（0.5 m）是**规划消费格式**，由证据层派生。

**为什么是 0.25 而不是 0.20**：`0.5/0.2 = 2.5` 是**非整数倍**。Nav2 的
`CostmapDownsampler::_downsampling_factor` 是 `unsigned int`、RACER 的 `UniformGrid` 用
`resolution_[i] *= 0.5` 的循环 —— 两者都只能表达整数倍。非整数倍会让聚合重复计入或漏计，
且错位量随坐标漂移；那种错误在指标上只表现为"偶发的边界误差"，极难归因。
0.25 让 2×2 子格与 0.5 m 格**格点严格对齐**，聚合无需重采样。

**启动期强制校验**：`perception_resolution` 必须是 `resolution` 的整数分之一，
否则节点**拒绝启动**（抛 `std::runtime_error`）。参数声明必须在校验**之前** ——
实测踩过：先声明在校验之后，`perception_resolution:=0.2` 会**静默通过**校验并照常启动。

### (b) 三层语义严格分开，**每层只有一个含义**

| 层 | 取值 | 用途 | 规则 |
|---|---|---|---|
| 几何占据率 | `[0,1]` | 评价 / 可视化 | 粗格内被占据子格的**比例**（分母固定 `factor²`） |
| 感知置信度 | `[0,1]` | 生命周期 / 迟滞 | log-odds 概率（`LogOddsGrid::probAt`） |
| 规划占据 | `{0,100}` | 只服务规划安全 | **max-pool**（任一子格确认占据 ⇒ 粗格占据） |

三者**不得互相冒充**。参照实现里的两个反面教材：

- ego-planner 把"已知自由"定义成 `occupancy_buffer_[adr] >= clamp_min_log_ && occupancy_buffer_inflate_[adr] == 0`
  —— 于是"分辨率变更"与"膨胀变更"不可区分；
- Fast-Planner 的 ESDF 由**膨胀后**的 buffer 构建，安全余量被烘进每一次距离查询。

Nav2 的 `cost_values.hpp` 用数值序（`LETHAL_OBSTACLE=254` > `INSCRIBED_INFLATED=253` > 其余）
在**单一 master grid** 里保住"占据不被膨胀覆盖"，那是对的；但本仓选择**显式分 buffer**，
因为 0.5 m 下 1 格障碍的膨胀会吃掉整条通道，混在一个 buffer 里无法诊断。

### (c) 规划层派生规则 = 保守四态合并（`planningCellValue`）

合并优先级：**占据 > 有证据未跨门限 > 未知 > 自由**。

- **占据最高**：任一子格确认占据 ⇒ 整格占据（规划安全优先，宁可放大）。
- **概率次之**：有子格带证据但未跨门限时报最大值 —— 丢掉它会让"差一点就确认"的区域
  退化成 unknown，规划器失去"这里可疑"的信息。
- **未知高于自由**：只要还有子格没看过，就不能对规划器承诺"这格确认安全"。
- **全自由才报 0**。

`1–99` 的语义保持本仓既有口径（消费者当 unknown，见 `planning_policy.hpp` 的
`classifyCell`）。这与 Nav2 默认行为**有意不同**：Nav2 默认 `trinary_costmap=true` 会把
`1–99` 折叠成 `FREE_SPACE`，只有精确等于 `unknown_cost_value`（默认 255）才是 unknown。
**集成风险（已登记）**：任何 Nav2 消费者订阅本仓 `/agc/map` 时必须显式设
`trinary_costmap: false`，否则本仓的"不确定"会被读成"可通行"。

### (d) 膨胀按**米**，不按格

`inflation_robot_radius_m`（0.6）与 `inflation_radius_m`（1.0）都是米，
与 `agc_ground/config/costmap.yaml` 的 `robot_radius` / `inflation_radius` 同值。

**为什么不能用格数**：ego-planner 的 `inf_step = ceil(obstacles_inflation_ / resolution_)`
在 `0.099/0.1` 下恰好等于 1 格，参数看上去"是米"，实际效果是"一格"。一旦分辨率从 0.1
换成 0.5，同一参数会静默变成 0.5 m 的余量 —— **2.5 倍**设计意图，且没有任何报错。
Nav2 的 `InflationLayer::computeCost(distance)` 才是与分辨率无关的写法，本仓按它做。

距离场用 **Felzenszwalb 一维平方距离变换**（两轴各一遍，O(N)），取自 Fast-Planner / RACER
的 `plan_env/src/sdf_map.cpp` 的 `fillESDF` —— 本机唯一零依赖的精确 EDT
（Nav2 没有 EDT，只有缓存的 `hypot` + 四邻域 BFS；ego-planner 完全没有距离场）。

**哨兵值**：参照实现用 `numeric_limits<double>::max()`。它在本仓规模下**实测不会**溢出
（已用 1×1–9×9 全尺寸单/多种子与暴力 O(N³) 对拍确认数值精确），但"靠浮点溢出恰好不发生"
不该是正确性的前提 —— 一旦 `q²` 与 `DBL_MAX` 同量级，`inf − inf = NaN` 会让包络静默退化。
改用有界哨兵（`kSeedInf = 1e18`），让该失效模式**不可达**。

**分辨率下限（如实登记）**：距离场取值是"格心到最近占据格心"的欧氏距离，
故分辨率 r 下**最小非零距离就是 r**。0.5 m 规划层上只能取 0 / 0.5 / 0.707 / 1.0 …
需要更细的边界度量时应提高栅格分辨率或在连续几何上直接算，**不是**给距离场插值。

### (e) 障碍实例层：两个正交布尔 + 上升沿

新增 `InstanceTracker`：观测点集 → 实例拟合 → 实例级跟踪 → 稳定几何模型。

生命周期照 RACER `GridInfo` 的形状：`alive`（结构上存在）与 `confirmed`（内容上可信）
是**两个正交位**，而 `justConfirmed()` / `revived()` / `justDied()` 是**上升/下降沿事件**。
`prev_alive` / `prev_confirmed` 必须在拍首**整体快照**，不能在吸收观测时就地覆盖 ——
同一实例一拍内更新两次会把 prev 覆盖成本拍值，边沿永久丢失。

几何用**指数滑动平均**（α=0.5）而非直接覆盖：单帧拟合的质心会随可见像素集合变化而抖动
（参照实现里同一物体尺寸跨度实测可达 3 m），直接覆盖等于把单帧噪声 1:1 传导给实例。
朝向用**最短角差**插值（179° 与 −179° 的中点是 180° 而非 0°）。

**不采用** RACER 的 `frontier_num_` / `frontier_cell_nums_`：那两个字段在参照实现里
声明后从未被写入，是死字段（活跃判定实际用 `contained_frontier_ids_.empty()`）。
照抄死字段等于照抄一个不存在的行为。

### (f) 评价口径分三层，**几何指标不得在规划层算**

- **几何重建**（对真值几何）：precision / recall / IoU / 双向边界距离（米）/ 实例中心误差；
- **规划可用性**（规划层）：`missed_danger`（真值障碍被标成可通行 —— 会撞）与
  `over_blocked`（规划占据但离真值超过车半径 —— 只是绕远）**分开报**；
- **实例稳定性**：连通域中心位移（米）+ 集合 IoU。

拿规划膨胀图去和几何真值算 precision/IoU，等于把"为规划安全而做的保守化"记成
"感知画错了" —— 那正是误覆盖率 0.668 里相当大的一部分。

**既有六项判据（`GATES`）保持不动**：它们是预登记的，事后调整等于伪造结论。
新增的三层指标**只做诊断、不参与 verdict**。

## Considered Options

- **只把全局 `resolution` 从 0.5 改成 0.25** —— 被否：`/agc/map` 的消息体积变 4 倍、
  costmap 全域栅格同步变 4 倍，而规划并不需要那个精度；且"感知精度"与"规划消费格式"
  仍绑在一起，换规划需求就会连带改感知。
- **用 0.20 m 证据层** —— 被否：与 0.5 m 非整数倍（2.5×），两个参照实现都表达不了，
  必须自己发明重采样并承担随坐标漂移的半格错位。
- **规划层也用占据率过门限** —— 被否：0.5 m 格里只有 25% 被占时，车（半径 0.6 m）
  照样撞上去；用阈值过滤小障碍是拿规划安全换指标好看。
- **照抄 ego-planner 的 `inf_step = ceil(radius/res)`** —— 被否：分辨率绑定的写法，
  换分辨率就静默改变物理余量。
- **让 `1–99` 对齐 Nav2 的 `trinary_costmap`** —— 被否：ADR-0035 已裁定与 Nav2 解绑；
  且把"不确定"折成"可通行"是安全方向的错误。改为登记集成风险。
- **保留 `frontier_num_` 式的死字段** —— 被否：参照实现里它们从未被写入。

## Consequences

### 正面（实测）

同一次 `dense_map` 整链运行（`experiments/demo/20261110-174135`，265 次地图重建）：

| 指标 | ADR-0039 记录 | 本轮实测 |
|---|---:|---:|
| 规划层稳态 \|Δoccupied\| p99 | 104 | **79** |
| 证据层证据格数 | —（单层，最大 4 万） | 46193（0.25 m 层） |
| 规划层尺寸 | 200×200 @ 0.5 m | 200×200 @ 0.5 m（**不变**） |

`/agc/map` 的话题、消息类型、几何与四态语义**完全不变**，下游零改动。

### 代价 / 限制（如实登记，不得外推）

- **规划层 p99 = 79 仍未达到预登记判据 ≤50**。本轮不宣称该项通过。
- **六项既有判据仍有 3 项未通过**（实跑，108 帧采样，`experiments/demo/20261110-190404`）：

  | 判据 | 实测 | 阈值 | 结果 |
  |---|---:|---:|---|
  | 面积覆盖率 | 0.937 | ≥0.55 | ✅ |
  | 误覆盖率 | 0.696 | ≤0.35 | ❌ |
  | IoU | 0.298 | ≥0.45 | ❌ |
  | 面积比 | 1.123 | ≤1.60 | ✅ |
  | 稳定性 p99 | 60 | ≤50 | ❌ |
  | 形状抖动 p95 | 0.000 | ≤0.25 | ✅ |

  稳定性 p99 在三次采样中分别为 **79 / 129 / 60**，**方差很大** —— 本轮只报实测值，
  不宣称该项改善或达标（改造前记录为 104，落在该区间内，**无法据此判定改善**）。

- **分层指标首次取得实跑数字**（同一批 108 帧）：

  | 层 | 指标 | 实测 |
  |---|---|---|
  | 几何重建 | precision / recall / IoU | 0.304 / 0.495 / 0.232 |
  | 几何重建 | 边界距离 地图→真值 | p90 0.91 m，最大 2.24 m |
  | 几何重建 | 边界距离 真值→地图 | p90 4.34 m |
  | 规划可用性 | 漏掉危险障碍 | 0.032（42 格） |
  | 规划可用性 | 误阻塞 | 0.278（585 格） |
  | 实例稳定性 | 中心抖动 | p90 0.00 m，最大 5.97 m |

  **这组数字解释了"误覆盖率 0.696 却面积比只有 1.123"这个长期矛盾**：
  误覆盖率把"贴着真值障碍的边界格"也算错，而 FP 分档显示
  **60.2% 的 FP 在真值 1 格内、38.8% 在 1–3 格内、仅 1.0% 超过 3 格**。
  换成"离真值超过车半径（0.6 m）才算误挡"的规划口径，同一份地图的误阻塞率只有
  **0.278** —— 差 2.5 倍。**这不是地图画错了，是 0.5 m 二值化对 0.6–1.2 m 障碍的
  边界代价**，正是本篇要解决的问题。
- **实例层已实现并有 15 条单测，但尚未接入 `map_adapter` 的在线链路**：
  `InstanceTracker` 目前是可供消费的纯逻辑，实例级栅格化未进主链。这是**已知未完成项**，
  不得表述为"实例化表示已上线"。
- **0.5 m 规划层的距离场只有 0.5 m 粒度**，没有亚格余量（见 (d)）。
- **Nav2 消费 `1–99` 的集成风险**已登记（见 (c)）。

### 可回滚

`perception_resolution: 0.5` 即退回改造前行为（证据层与规划层重合），
`planningSnapshot` 退化为恒等映射。但**分层本身不可静默退化**：
`test_perception_map_consistency.py` 的 `test_evidence_layer_is_finer_than_planning_layer`
会在两者相等时报错。

### 防复活闸门

| 闸门 | 断言 |
|---|---|
| `test_multi_res_grid.cpp`（22 条） | 占据率分母固定 `factor²`；规划层 max-pool 保守；距离变换与暴力对拍；米制风险分档顺序 |
| `test_obstacle_instances.cpp`（15 条） | 单帧不确认；一次漏检不撤销确认；上升沿是事件；死亡实例不抢新观测 |
| `test_grid_geometry.py`（14 条） | Python 侧 EDT 与 C++ 同值同口径；边界距离是米；实例抖动抓位置跳变 |
| `test_perception_map_consistency.py` | 证据层必须更细且整数倍；规划层必须派生；膨胀必须米制；参数声明必须在启动校验之前 |
| `test_perception_quality_diagnostics.py` | 三层指标不参与 verdict；实例稳定性看中心位移而非数量差 |

上述闸门**逐条实测"能红"**（注入违规 → 报错 → 撤销），不是"看着有保护"。
