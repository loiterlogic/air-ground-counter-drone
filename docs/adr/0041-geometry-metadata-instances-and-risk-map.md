## 背景

ADR-0040 之后，temp.md 的方向 2/3/4/5 只完成到"有纯逻辑 + 有单测"，
**主链行为没有变化**。核对的硬证据：

```
grep InstanceTracker src/*.cpp      → 空（实例层从未被调用）
grep riskField       src/*.cpp      → 空（风险图从未被调用）
grep covariance|instance_id 证据层  → 空（那些字段没存）
```

"有 149 条 gtest 全绿"不等于"主链变了"—— 判据覆盖的是**纯函数**，
而没有任何代码路径在运行期调用它们。这是本篇要修的东西。

另外两处与 temp.md 的差距：

1. **几何层是匿名的**：`ObstacleFootprintArray` 只带一批点和批次级属性，
   点不知道"我属于哪个障碍"、"我是屋顶还是墙"。temp.md 的原话是
   "footprint 不再是地图输入的临时中间产物，而是感知地图的第一等公民"。
2. **`/agc/map` 是裸占据**：`100 = occupied` 同时承担"感知认为这里有障碍"与
   "规划器必须不可通行"两种语义（temp.md 方向四的原话），而对 0.5 m 格里的小障碍
   这两者不该等价。

## 决策

### (a) 几何层携带点级元数据（方向二）

`ObstacleFootprintArray` 增两个**并行数组**（与 `points` 等长）：

| 字段 | 含义 |
|---|---|
| `string[] point_instance_id` | 该点所属实例 id（与 `/agc/obstacles` 的 `obstacle_id` 同一命名空间）；空串 = 未归属 |
| `uint8[] point_class` | `0` 未分类 / `1` 屋顶 / `2` 墙·侧墙 / `3` 边缘 / `4` 遮挡 |

**为什么用并行数组而不是嵌套消息或改 `ComponentPoint`**：
`points` 与屋顶带掩码 `kept` 的"同下标"纪律已经存在（`nadir_geometry.hpp` 明确写了
"搬点最容易让掩码与点错位"）。并行数组沿用同一纪律；而给 `ComponentPoint` 加字段会
撑大热路径上的紧凑数组（24 B/点 × 10 Hz × 3–7 MB/s），label 却只在发布时用一次。

**`point_class` 与 `kept` 用同一个 `z_cut`**，但**兜底时不改类别**：
立面为主时 `kept` 会全部置 1（否则地图开洞），而那些点的类别仍是"墙" ——
`kept` 表达"我用了它们"，`point_class` 表达"它们其实是墙"。若在兜底处把类别也改成屋顶，
就等于用一次兜底把语义抹掉，评价与诊断再也看不出"这批点不可信"。

**发布必须移到跨帧关联之后**：改造前 `publishFootprints` 在 `associateNearest` **之前**
调用，于是点永远拿不到实例 id。这是"几何层不是第一等公民"的具体表现。

**`aggregateObbs` 必须显式输出每个 OBB 的连通域 label**：它按 `i in [1, labels_n)`
遍历但会跳过 `count==0` 与"保留点数不足"的段 ⇒ **OBB 下标 ≠ label**。
用下标猜会把实例 id 贴到错误的点上，而且错得很安静。

### (b) 障碍实例层接入主链，与逐点累积**取并集**（方向三）

`map_adapter` 消费 `point_instance_id`：按 id 分组 → `fitInstanceObservation`
（质心 / 半径 / 半长 / 朝向 / 高度 / 中心不确定度）→ `InstanceTracker` 跨帧跟踪 →
已确认实例栅格化后**并进证据层**，再与逐点证据一起派生规划层。

**关键取舍：并集，不是替换。**

| | 逐点累积擅长 | 实例层擅长 |
|---|---|---|
| 大建筑被画幅切成碎片 | ✅ 天然跨帧合并 | ❌ 每片各自成实例（会分裂） |
| 1–3 格宽的小障碍 | ❌ 边界点在相邻格之间跳 | ✅ 跨帧一致的几何模型 |

两者各补对方拿不到的那一半。**替换会让覆盖率崩掉**（实例分裂），
**只有逐点则小障碍不稳**（这正是稳定性 p99 偏高的来源）。

**半径取到质心的 90% 分位，不是最大值**：单个错位点就能把最大半径撑大。
这与 `roofReferenceHeight` 用 90% 分位是同一思路（"保守但不脆弱"）。
**中心不确定度用质心标准误 `σ/√n`，不是点的散布**：用散布当 σ 会把
"大障碍"误判成"中心不确定"——那是两件不同的事。

**实例栅格化用按朝向的椭圆**（`(u/hx)² + (v/hy)² ≤ 1`），**不是外接圆**。

这是**实测修正，不是口味**。第一版用外接圆（`hypot(dx,dy) ≤ boundingRadius()`），
而 `boundingRadius()` 是 box 的**对角半径**：对 0.6×0.15 m 的长条 box，
外接圆面积是矩形的 **3.34 倍**；整图 occupied 实测从 2230 涨到 **4622（2.07×）**。
那已经不是"稳定小障碍"，而是**凭空造障碍**，直接推高误覆盖率。

椭圆保留朝向、面积与矩形同量级（box 0.6×0.3：椭圆 0.565 m² vs 矩形 0.72 m²，
甚至略小）。修正后稳态 occupied 为 **~2873**（基线 2230，增量 29% 而非 107%），
剩余增量是实例层对真实障碍的真实贡献。

**仍偏保守**：椭圆外接于矩形之外的四角会被多算，但量级与矩形相当，方向安全。

### (c) `/agc/map` 输出**规划风险图**（方向四 C，用户指定接入本体）

`/agc/map` 的取值从"四态占据"改为风险分档（仍是 `int8`、同一话题、同一消息、同一几何）：

| 值 | 语义 | 判据 |
|---|---|---|
| `-1` | 未知 | 该格从未被观测 |
| `0` | 可通行 | 距离 > `inflation_radius_m` |
| `1–98` | 有代价但可通行 | `robot_radius < d ≤ inflation_radius`，指数衰减 |
| `99` | 车心进入即擦碰 | `0 < d ≤ robot_radius` |
| `100` | 格内即占据 | 几何占据（逐点 ∪ 实例） |

**为什么把代价压进 1–98 而不是 Nav2 的 0–252 代价域**：`/agc/map` 的既有语义是
`OccupancyGrid`（-1/0/1–99/100），RViz 的 costmap 着色与 `planning_policy.hpp` 的
`classifyCell` 都按它读。换域会同时破坏两者。压进 1–98 让"有代价"仍落在既有的
"非 0 非 100"区间里。

**未知格必须短路成 `-1`**：距离场只对有占据的图有意义；把未观测区按距离判成 free
是对规划器的过度承诺（ADR-0035 的三态纪律）。

**代价映射与 Nav2 `InflationLayer::computeCost` 同构**（指数衰减、以 inscribed 为平台边），
但**不借用**它的 `cost_scaling_factor` 参数值 —— 本仓自己给 `risk_cost_scaling`。
取指数而非线性：贴近车半径时代价陡增、远离时迅速趋零，规划器不会因"远处一点点代价"
而绕大圈。

### (d) **消费端必须关 `trinary_costmap`**（本决策的强制配套）

`agc_ground/config/costmap.yaml` 的 `static_layer` 设 `trinary_costmap: false`，
`lethal_cost_threshold: 100`。

**为什么这是强制的**：Nav2 `StaticLayer::interpretValue` 在 `trinary_costmap: true`
（默认）下把 `1–99` 一律折成 `FREE_SPACE`。不关它，我们算出来的"贴车半径有代价"
会被读成"完全可通行"—— 安全膨胀**静默失效**，而日志里看不出任何异常。
关掉后才走 `scale = value / lethal_threshold` 的比例代价分支（1→2、50→127、98→249）。

**这一条不是可选项**：它与 (c) 是同一决策的两半，任何一半缺失都让风险图失去意义。

### (e) 评价尺度补齐 temp.md 的全部子项（方向五）

| 套 | 指标 | 状态 |
|---|---|---|
| 几何重建 | precision / recall / IoU | ADR-0040 已有 |
| 几何重建 | boundary distance（双向，米） | ADR-0040 已有 |
| 几何重建 | **Hausdorff distance** | 本篇新增 |
| 几何重建 | **obstacle center error** | 本篇新增 |
| 几何重建 | **obstacle area error** | 本篇新增 |
| 规划可用性 | 漏掉危险障碍 / 误阻塞率 | ADR-0040 已有 |
| 规划可用性 | **是否碰撞**（判 free 但真值是障碍） | 本篇新增 |
| 规划可用性 | **安全间隙**（最小 / p05） | 本篇新增 |
| 规划可用性 | 规划成功率 | **离线不可得**（无规划器），如实标注不伪造 |
| 稳定性 | occupied 数量变化 / 集合 IoU / 进出格数量 | ADR-0039/0040 已有 |
| 稳定性 | 实例中心抖动 | ADR-0040 已有 |
| 稳定性 | **边界 Hausdorff 抖动** | 本篇新增 |
| 稳定性 | **实例面积抖动** | 本篇新增 |

**三套都只是诊断，不参与既有判据**：`GATES` 是预登记的，事后调整等于伪造结论。

**逐障碍配对用"质心最近"而不是 IoU**：小障碍在 0.5 m 栅格上只有 1–3 格，
边界一偏 IoU 就掉到 0，按 IoU 会大量配对失败（表现为"全部漏检"）。

**安全间隙只在"非碰撞"的自由格上统计**：碰撞格到真值障碍的距离必然是 0
（它自己就是障碍），算进去会让 `clearance_min_m` 恒为 0、失去区分力。
两个量回答两个问题："我有没有撞上去"（collision）与"我没撞的地方留了多少余量"（clearance）。

## Considered Options

- **给 `ComponentPoint` 加 `label` / `class` 字段** —— 被否：那是热路径上的紧凑数组
  （24 B/点，10 Hz 下 3–7 MB/s），label 只在发布时用一次；且加字段会让"搬点"风险回归。
- **用 OBB 下标猜连通域 label** —— 被否：`aggregateObbs` 会跳过空段，
  下标与 label 不一一对应，猜错时点还是那些点、只是归属错了，**错得很安静**。
- **实例层替换逐点累积** —— 被否：大建筑被画幅切碎时实例会分裂，覆盖率会崩。
  两者擅长的是不同场景，必须取并集。
- **实例半径取最大值** —— 被否：单个错位点就能把半径撑大（实测用例：一个 5 m 外的
  离群点把半径从 0.30 m 撑到 5 m）。
- **`/agc/map` 保持裸占据、另发一个风险图话题** —— 被否：用户明确裁定"接入 /agc/map"；
  且两个话题会让"规划器看哪张图"变成第二个真相来源。
- **用 Nav2 的 0–252 代价域** —— 被否：会同时破坏 RViz costmap 着色与
  `planning_policy.hpp` 的 `classifyCell`。
- **`trinary_costmap` 保持默认 true** —— 被否：那会让 `1–98` 被读成 free，
  安全膨胀静默失效（见 (d)）。

## Consequences

### 正面

- 几何层从"一批匿名点"变成"每个点有归属与类别"，下游可按类别决定信多少。
- 实例层进主链：小障碍的跨帧一致性由实例模型提供，而大建筑的跨帧合并仍由逐点累积提供。
- `/agc/map` 从"裸占据"变成"风险分档"，安全膨胀第一次有了载体；
  未知/可通行/有代价/内切/占据五档语义在同一话题上可区分。
- 评价口径补齐到 temp.md 的全部子项（除"规划成功率"离线不可得，已如实标注）。

### 代价 / 限制（如实登记）

- **`1–98` 与既有的"量化概率"语义冲突**：ADR-0035 (c) 让 `/agc/map` 的 `1–99`
  表示"量化占据概率"，本篇改成"风险代价"。两者都落在同一数值区间但含义不同。
  **消费端只按数值判**（`planning_policy.hpp` 把 1–99 一律当 unknown；
  Nav2 关掉 trinary 后按比例代价读），所以现状安全；但**任何按"1–99 就是概率"写的
  新消费者都会读错**，须以本篇为准。
- **实例层与逐点累积的权重未标定**：并集是"各取所需"，没有可调权重。
  若将来发现实例层在某些场景（大建筑碎片）贡献错误格，需要新决策来决定是否加权。
- **`instance_confirm_hits` 等参数未按 0.25 m 证据层重新标定**：
  它们沿用 0.5 m 时代的量级（ADR-0040 已登记同一问题）。
- **规划成功率离线不可得**：`perception_quality.py` 不运行规划器，
  该项**没有**实测值。不得用"碰撞格为 0"冒充"规划成功"。
- **风险图的 `99` 与 `100` 都算"不可通行"，但语义不同**：`100` 是格内有障碍，
  `99` 是车心会擦碰而格内没有障碍。消费者若把两者合并处理，会丢失"障碍在哪"的信息。

### 实跑取证（2026-11-10）

`/agc/map` 末帧取值分布（`experiments/demo/20261110-195127`，59 帧采样）：

| 取值 | 格数 |
|---|---:|
| `unknown(-1)` | 25330 |
| `free(0)` | 3857 |
| **`cost(1–98)`** | **962** |
| **`inscribed(99)`** | **1577** |
| `lethal(100)` | 8274 |

五档**全部出现**，证明风险图真的在 `/agc/map` 上生效（不是只编译进去）。
实例层同时在跑：`帧统计` 日志每帧报告"带实例 id"的点数（实测约 16 万/帧）。
