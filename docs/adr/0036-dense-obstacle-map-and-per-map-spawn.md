# 小障碍高密度地图、出生位按地图派生、环带判据门控化

## Status

accepted（2026-11-10，用户逐条裁定；6 轮 grilling 定案）

**⚠ 修订**：本篇 (a) 的布局范式与地面约定已由
[ADR-0037](0037-dense-map-random-layout-and-plain-ground.md#top) 取代（2026-11-10，用户裁定）——
改为**随机撒点**、间距加宽 15%、地面按地图纯色化。本篇其余条款（实体数 620 / 高度 ≤3 m /
出生位 per_map / 环带门控判据 / 断言 (r)）**继续有效**。

**相关**：

[ADR-0010](0010-safety-thresholds-and-failsafe.md#top)（垂直门控；本篇 (c) 把它接进核查判据）、
[ADR-0012](0012-spawn-clearance-and-reset-transaction.md#top)（出生净空）、

[飞行高度分层](../conventions/飞行高度分层与按地图定高.md#flight-altitude)（高度是地图属性，本篇 (b) 把同款论证用到出生位）。

## 背景

用户 2026-11-10 要求「设计第二张地图，要求是高密度小障碍，类似 `refs/Fast-Planner` 里的那种」，
并明确「这张地图不需要做的太精致」「跟无人机没关系，无人机还是飞14m，测得是感知和规划」。
这不是临时起意：用户 2026-11-02 已把「小障碍高密度图」写进地图类规划（原话「因为后面会做
小障碍高密度和大障碍低密度等图」，已落 ADR-0007 的三图 `flight_altitude` 注释）；
[ADR-0035](0035-perception-map-representation-and-unknown-policy.md#top) (p) 的「实验 D」也记着
「用户裁定：明日配合新的高密度地图做」。⇒ 本篇同时消掉两个欠账。

访谈中查出三条与"高密度铺满"直接冲突的**既有几何事实**（都不是本篇引入的）：

1. **出生位是全局的**：`spawn_layout.yaml` 一处定义车/目标/己方机，所有地图所有场景共用，
   核查 (g) 也用同一组坐标判**每一张**图。实测：车 (−34,−6) 若强加到 `yard`，会压进
   `workshop_w`（足迹净空 **−6.50 m**）。⇒ 新图需要不同的出生位，但改全局值会改掉
   `yard` / `minimal` / `open_field` 的出生位与全部历史证据基线。
2. **核查 (i) 不建模垂直门控**：`safety_shield.cpp` 的 `deriveRings` 在
   `z_gate ≥ z_top + c_clear` 时**根本不把该障碍放进圆盘集**，而核查 (i) 是**纯二维圆盘**口径。
   实测：本图 620 个障碍在 14 m 下 **100% 被门控移除**，但二维口径环带可行率 **0.0%**、
   最长可行弧 **0°**（判据要 ≥90°）。⇒ 判据与运行语义不符，且 `yard` 的登记值
   （二维口径 58.6%，注释里更早的 81.53% 是 36 实体时代的旧值）同样不代表运行期行为。
3. **"不留走廊"与跟踪终态互斥**：地面规划是**占位直连**（不避障），`collision_monitor`
   碰撞档 2.0 m、安全档 4.0 m；而 `TRACKING_SUCCESS` 要求 `dist(车,目标) ≤ d_track = 3.0 m`。
   实测：不留走廊时车在 **5.3% 行程**处进碰撞档停车 ⇒ 跟踪终态**几何上不可达**。

## 决策

### (a) 新增地图 `dense_map`（能力/实验图，**不是**演示主地图）

> ⚠ **布局范式已被 [ADR-0037](0037-dense-map-random-layout-and-plain-ground.md#top) 取代**：
> 由"六角错排 60×60"改为"**随机撒点 70×70**（固定种子）、最小间距 2.3 m"；
> 地面改为 `ground_style: plain` 纯色。以下原描述保留供追溯。
>
> ⚠ **间距与实体数又被 [ADR-0044](0044-dense-map-second-gap-widening.md#top) 取代**：
> 第二轮 +15% ⇒ 最小间距 **2.645 m**、实体 **486**（区域仍 70×70）。
> 本篇下文出现的"620"一律是**当时的快照值**，现行值跑核查读 JSON。

- 文件 `src/agc_sim/config/maps/dense_map.yaml`，在 `world_map.MAP_GEOMETRY_FILES` 加一行；
- **定位**：ADR-0035 实验 D 的承载图 + 压测地面 `collision_monitor` 在密排小件下的行为；
  演示主地图仍是 `yard`（s04 的终态基线不动）。
- **布局**：目标 (0,0) 在作业区正中；密集区 **60×60 m**（x,y ∈ [−30,30]）六角错排
  （行距 3.0 m / 排内 2.0 m / 奇偶行错开 1.0 m）；目标口袋 **r=6 m**；
  **不留走廊**（用户原话「不需要走廊和净空」）。
- **尺度**：box 0.6–1.2 m / cylinder r 0.25–0.40 m；高度 0.6–3.0 m（**上限 3 m**，用户裁定）；
  单图元、**无 `parts`**、材质只 2 档（concrete / paint）、无窗带勒脚等细部。
- **属性变化是确定性的**（对 (行,列) 取模），**不是随机撒点** —— ADR-0007 已否决"随机撒点做多样性"。
  生成器 `scripts/gen_dense_map_map.py` 只是**作者工具**；生成后 **yaml 即真源**，
  核验器只读 yaml。

### (b) 出生位升格为**地图属性**（`spawn_layout.per_map`）

与 `flight_altitude` 同款论证：某张图上"车从哪出发"是**地图事实**，写进全局文件就是第二来源。

- 顶层 `car/target/own_uav` 仍是**完整缺省**；`per_map.<map>` **只写要覆盖的键**（深合并一层）；
- 解析口径单一实现：`agc_task/launch/scene_spawn.py` 的 `load_spawn_layout(world_map=…)`；
- `per_map` 的**结构无条件校验**（拼错实体段一律拒绝运行，不必等到选中那张图）；
- 未在 `per_map` 登记的地图 → 回落顶层缺省 ⇒ `minimal` / `yard` / `open_field` **逐值不变**；
- `main.launch.py` 与 `tests/check_scene_geometry.py` (g) 都走这一条路径（核查不再拿
  `yard` 的出生位去验别的图）。

本图坐标：车 **(−34,−6)**、目标 **(0,0)**、己方机 **(−34,−2)**；
派生任务目标 **(−2.5, 0)**（沿用 `goal_offset_m` 缺省，距目标 2.50 m ≤ `d_track` 3.0）。
三条设计目标全部满足（未放宽判据）：车↔目标 **34.53 m** ≥30、己方机↔目标 **34.06 m** ≥25、
车↔己方机 **4.00 m** ∈[3,8]。

### (c) 环带判据 **(i) 改为门控口径**，二维口径并列登记

**判据换成运行期真实生效的那条**：先按 `z_gate ≥ z_top + c_clear` 移除障碍，再算环带
可行率与最长连续可行弧。二维口径（旧判据）**并列登记**在 JSON 的
`two_d_feasible_pct` / `two_d_max_free_arc_deg`，**不参与 pass**。

- 为什么改：`safety_shield.cpp` 的 `deriveRings` 就是这么做的；判据与实现不符会让
  "核查绿了但运行期不成立"或反之，两者都是证据失真。
- **能力收窄（如实登记，不得外推）**：改为门控口径后，任何"最高障碍顶 + c_clear ≤ 飞行高度"
  的地图都会自动 100% 通过 ⇒ (i) **从此只能抓"有高于飞行高度的障碍挡在环带上"这一种情况**。
  它不再能证伪"二维圆盘把空域吃光"。想看那一面，读 `two_d_*` 两列。
- **历史证据仍可追溯**：`yard` 的 81.53%（36 实体时代）/ 58.6%（42 实体现值）都是二维口径值，
  现由 `two_d_feasible_pct` 列承载。

### (d) 新增场景 `dense_scene` 作为本图消费者

`world_map: dense_map`、`expected_terminal: MISSION_FAILED` / `TIMEOUT`。
场景 id 用短名 `dense_scene`（用户 2026-11-10 裁定「就改成 dense_scene 就行，又不是没有注释」），
**不**遵循 `s<NN>_<…>` 长式 —— 语义由场景段注释承载。
**为什么是 MISSION_FAILED**：本图不留走廊，车进不去 ⇒ 跟踪终态几何上不可达，这是**设计意图**
（写成 `TRACKING_SUCCESS` 会让回归永远红着）。场景**不覆盖出生位**（ADR-0036 (b)：随地图派生）。

### (e) 新增断言 **(r) 高密度** —— "高密度"第一次可判定

此前**没有任何断言**能判"高密度"：(o) 是 `yard` 专属（≤46 实体 / 覆盖率 5–12%），
套用到本图会直接判"超标"。故**按图**立独立断言，判据四条：

| 判据 | 阈值 | 依据 |
|---|---|---|
| 实体数 | ≥ **200** | ≥ `yard` 上限（46）的 4 倍 —— "高密度"不是"稍多几个" |
| 最近邻中位数 | ≤ **3.0 m** | "密"是**间距**属性，不是数量属性 |
| 水平尺寸最大 | ≤ **2.5 m** | "小障碍" |
| 顶面高度最大 | ≤ **3.0 m** | 用户 2026-11-10 裁定「不要超过 3 m」 |
| 复合体 | **0** 个 | "不需要做的太精致"的量化形态 |

覆盖率**不套用** `yard` 的 5–12%（那是 `yard` 专属），只要求 > 0。

### (f) 地图白名单不再各写一份

`scripts/demo/main.py` 原写死 `('yard','open_field','minimal')`，
`test_scene_config_invariants.py` 两处写死三图元组 —— 新图**不受这些守护**，
是"加了图但没被任何断言覆盖"的静默缺口。现一律经 `world_map.MAP_GEOMETRY_FILES` / `WORLD_MAPS`
单一清单派生（核查 (m) 的纪律本来就这么要求，这两处是漏网的）。

## 不做什么

- **不改** `yard` / `minimal` / `open_field` 的任何几何、出生位、高度值（逐值不变，已核查验证）。
- **不改** `s04` 的主地图与终态基线；本图不顶替演示位。
- **不**为某张地图开例外（不写"dense_map 豁免 (i)"之类）。判据是**全局改**，不是按图开洞。
- **不**新增路线分支：没有 `dense_*` 开关、没有"同一功能两套实现由开关选择"。
- **不**追求随机撒点（ADR-0007 已否决）；**不**引入贴图 / mesh / 外部资产。
- **不**宣称本图能测空中避障：全部构件 ≤3 m、飞行 14 m ⇒ 全部被门控移除（见 (g)）。

## Consequences

**正面**：
- 「小障碍高密度图」与 ADR-0035 实验 D 两个欠账同时销账，且新图有活跃消费者（`dense_scene`）；
- 出生位与高度**同属地图属性**，换图不再需要动代码或复制整份布局；
- 环带判据第一次与 `safety_shield.cpp` 的实现同口径；
- "高密度"第一次可判定，被改稀了会被 (r) 抓住；
- 设计期核验器 `tests/check_dense_map_layout.py` **入库**（含正式核查没有的
  "实体互不重叠 SAT"与"8 字净空"两条，见技能 `map-design` GATES.md）。

**代价 / 限制（如实登记）**：
- **(i) 能力收窄**（见 (c)）：它不再能证伪"二维圆盘吃光空域"。
- **本图不提供空中避障证据**：620 个障碍在 14 m 下 100% 被门控移除。
  这是"无人机飞 14 m + 构件 ≤3 m"的几何后果，不是缺陷。
- **本图跟踪终态不可达**（设计意图）：车沿直连 goal 在 5.3% 行程处进碰撞档。
  本图**不能**当 `TRACKING_SUCCESS` 的证据。
- **8 字净空为负**（实测 −3.32 m，最紧 `crate_285`）：密集区覆盖了 `traj` 的 8 字足迹。
  按技能 GATES.md 的口径，负值**只**说明名义参考轨迹压到静态膨胀圆盘，
  **不**证明运行期必然失败；本图也不跑预设轨迹（反无人机场景本就禁用）。
- **覆盖率 4.54%**（并集口径）：低于 `yard` 的 11.48%。高密度 ≠ 高覆盖 ——
  620 个小件铺开的总占地不如 42 个大件。**不得**用覆盖率代替密度作为"高密度"的判据。
- **渲染 / 物理开销未实测**：620 个静态模型 vs `yard` 的 42 个。开销只在
  T2 真实实验（起 GUI / 全链）时才能量，**本轮未做**，不得据设计推导宣称 RTF 可接受。
- **未做真实 GUI 取证**：布局正确性由只读核验器 + 正式核查的派生一致性证明；
  视觉观感（是否"看起来像"）**未取证据**，交付图不得冒充。
