# 出生净空与场景复位事务

## Status

accepted（2026-11-02 由 0023 / 0029 合并；出生净空下限为可标定量、候选校验为「实体对 + 边界」的统一口径均未变）

## 背景

契约硬约束 C7 原为「场景生成须保证出生间距 ≥ 2.4 m；复位失败最多重试 3 次且不占 episode 预算」。核对溯源：`2.4 m` 与已作废的旧地面距离阈值组 `0.7 / 0.9 / 2.4 m` **同源**——它是旧标度（40×40 m 小场地 + 慢速平台）下的**避障安全档**，被挪用为「出生间距」，并且**糅合了两种不同语义**：起飞净空（无人机起飞 / 悬停所需净空）与避障安全档（实体间避障安全距离）。作业区放大到 80×80 m、平台换装并重标定 C2 之后，旧值既无推导依据也语义不清。

随后的评审指出：承载实现又**退化**为单一标量代理——只检查 `hypot(car, target) ≥ spawn_clearance_min_m`（6.0 m），己方 UAV、静态立柱、作业区边界、各实体的几何外伸都不参与判断，随机搜索（`spawn_randomize`）也不复核这些约束，于是「目标远但车压立柱 / 车与己方机近邻 / 车出界」仍能通过。

## 决策

### (a) 语义拆分：出生净空 与 复位重试预算

C7 拆为两条**独立**语义：

1. **出生净空**（场景设计约束）：任意两实体出生后**互不侵入各自的初始安全包络**。
2. **复位重试预算**：复位失败**最多重试 3 次**且**不占 episode 预算**——此条与具体净空数值无关，保持不变。

### (b) 出生净空下限 = 可标定量，不再写死 2.4 m

下限按新标度实测 / 新 C2 口径推导，并以**地面安全包络**为最紧约束：地面安全包络半宽 ≈ 新 C2 安全档 `4.0 m` + 车体半长 `0.5 m` + 载荷（网面 / 发射器）外伸 `1.0 m` ≈ `5.5 m`，叠加最小裕度 → 暂定**下限 ≈ 6 m**（落地参数 `spawn_clearance_min_m = 6.0`）。

- 实际 spawn 分离（W3 打补丁后 `agc_car` / `intruder_uav` 分离 ~30 m）**远大于**该下限 → 下限的作用是**约束场景随机化**（不得使间距低于下限），**不**约束常态布局。
- 数值随实跑标定回填；暂定值须标注「待实测回填」。
- **表述纪律**：文档 / 报告**不得**再引用 `2.4 m` 作为出生间距现行值。

### (c) 统一候选校验 `validateCandidate`

`scenario_reset` 对**每个候选**（含随机搜索的每一轮）按序检查，任一不满足即拒并给出 `reason`：

1. **边界**：车、目标各自中心须落在「作业区边界内缩自身几何外伸」区间内（`x_min + r ≤ x ≤ x_max - r`）→ 否则 `boundary_out_car` / `boundary_out_target`。
2. **车↔目标**：`≥ spawn_clearance_min_m`（C7 标定值 6.0）→ 否则 `car_target_clearance`。
3. **己方 UAV 对**（仅当 `own_uav_present`）：车↔己方、目标↔己方 → `car_own_uav_clearance` / `target_own_uav_clearance`。
4. **静态障碍**（逐障碍）：车↔障碍、目标↔障碍 → `car_obstacle_clearance:<name>` / `target_obstacle_clearance:<name>`。

全部候选非法 → 返回 false（保留最后一次 `reason`）。函数签名为 `validateCandidate(cx, cy, tx, ty, reason)`。

### (d) 按实体对类型取几何外伸或安全档

- **静态障碍对（车/目标↔立柱）**：用**几何不重叠**口径——下限 = 两实体几何外伸之和（车半长 `0.5037` + 立柱半宽 `0.15`；UAV 半宽 `0.25` + 立柱半宽 `0.15`）。立柱是刚性几何体，要求是「不嵌入」。
- **车↔目标**：**沿用 C7 标定值 6.0 m**（地面安全包络口径）。二者为动态实体且车携网，须以安全包络而非几何不重叠为准。
- **己方 UAV 对（车/目标↔己方机）**：用**几何外伸**口径（两 UAV 半宽之和 / 车半长 + UAV 半宽）。
- **显式覆盖参数**：`clearance_min_car_own_uav_m` / `clearance_min_target_own_uav_m` / `clearance_min_car_obstacle_m` / `clearance_min_target_obstacle_m`；当覆盖值 `< 0` 时**按两实体外伸之和推导**（`r_a + r_b`），即默认走几何口径。
- **数值纪律**：`0.5037` / `0.25` / `0.15` 与上述对下限均为**暂定值，待实测回填**，不得据作长期标定。

### (e) `own_uav_present` 为显式运行模式

语义对齐「实体缺席不得推定」原则：**仅当**该参数为 true 才校验己方 UAV 对，**不得**由实体缺席推定。`backend:=full` 起真实空中链路时置 true 并透传己方机 spawn 位（`px4_own_pose` → `own_uav_x` / `own_uav_y`，world ENU）；轻量栈（`m0_skeleton`，无空中链路）保持基参默认 false。

### (f) 配置自洽

`obstacle_names` / `obstacle_x` / `obstacle_y` 三数组按索引对应；**长度不一致视为配置错误**，返回 `obstacle_config_invalid` 并**拒全部候选**（不静默截断）。

### (g) 应答与参数注入

- 服务应答失败改为 `reset rejected: <reason>`（reason 见上，可含 `:<障碍名>`），日志同步打印；成功为 `reset ok`。
- 参数单一注入：`config/w6_base.yaml` 增补实体外伸 / 实体对下限 / 边界 / 己方机 / 静态障碍清单。
- **不**新增 / 修改任何冻结消息或服务 ABI（沿用 `std_srvs/Trigger`）；门控逻辑（`isResettable` / bypass）不在本篇范围，见 [ADR-0014](0014-task-fsm-and-scenario-transaction.md#top)。

## 不做什么（边界）

- 不沿用 `2.4 m`，也不等比放大 / 拍一个更大的常数（同样无推导依据）。
- 不保留单一标量代理（只查车↔目标）；不对所有实体对生硬套 6 m。
- 不由实体缺席推定 `own_uav_present`；不静默截断长度不一致的障碍配置。
- 暂定数值不得当作长期标定值引用。

## Considered Options

- **沿用旧值 `2.4 m`** —— 被否：与已作废的旧阈值同源、语义糅合、在新标度下无依据。
- **等比放大 / 拍一个更大常数** —— 被否：无推导依据。
- **语义拆分 + 下限可标定（由新 C2 + 实体外伸推导）** —— 采纳。
- **延续单一标量代理** —— 被否：己方机 / 障碍 / 边界 / 随机复核均缺失。
- **全部实体对生硬套 6 m** —— 被否：6 m 是地面安全包络口径，对刚性立柱、对 UAV-UAV 过紧，会破坏默认场景（默认 spawn 距 `pole_1` 仅 5.0 m）与既有场景登记表。
- **实体对 + 边界统一校验，按对类型区分几何 / 安全口径** —— 采纳。

## Consequences

- **正面**：C7 语义落地完整（实体对 + 边界），随机化与常态布局都受同一校验；拒绝原因可定位到具体实体对 / 障碍名；「重试不占预算」与净空数值解耦。
- **代价 / 限制**：暂定外伸与下限值需实测回填；`validateCandidate` 的检查顺序成为语义的一部分，调整顺序会改变 `reason` 归属。
- **未决 / 后续**：净空下限与外伸参数的实测回填；门控逻辑由任务 FSM 侧承担。

## 实施回填

以下结论曾写在 `src/agc_task/config/spawn_layout.yaml` 的注释里，现收敛到此：

- **布局意图**：车 / 目标各贴 `apron_center`（40×20 m 作业坪，中心原点）一条短边内侧约 5 m，
  己方机在车一侧附近；车↔目标 30.15 m、己方机↔目标 26.17 m、车↔己方机 4.00 m。
  C7 净空下限 6.0 m 只增不减。三张地图同坐标，保证跨图可比较。
- **净空口径**：核查用的 `footprint_radius` 取实体水平外接圆（分段长墙 ≈ 半长 15 m），
  对 yard 两侧长围墙极保守；同点位的**真实几何净空**（点到图元表面）约 8–10 m，仍 > 0。
  若需更大裕度应改围墙的 footprint 口径，不要把出生点挪回中央（会破坏布局意图）。
- **目标世界放置高度 0.12 m**：PX4 第二实例在 `intruder_px4_delay_s=35 s` 才 attach，
  此前无电机控制且 x500 `base_link` 受重力，原 2.0 m 会自由落体约 0.64 s 砸地穿地、
  在地面停留约 20 s 再被拉到巡航高度（用户可见"目标突然掉下来"）。0.12 m 使落体不可见，
  且 PX4 attach 后位置环行为不变。该值**不是**出生高度、巡航高度，也不与
  `intruder_driver.cruise_alt_m` 叠加（后者是相对 episode 原点的上升量，ADR-0007）。
- **固定任务目标偏移**：默认场景的任务目标 = 目标出生位 + `goal_offset_m`（-2.5, 0），
  避免改了布局却忘改 `task_manager.goal_x/goal_y` 导致 `d_track` 不可达。
  场景显式给 goal 时以场景值为准。
- **PX4 错峰不动**：`own_px4_delay_s=25` / `intruder_px4_delay_s=35` 由 ADR-0027 为规避
  uXRCE participant 创建超时而定，缩短会重新引入 DDS 启动风暴。
