## 背景

用户反馈的现象有四层，**不是同一个 bug**：

1. **红框太大**：`map_adapter` 把每个连通域的外接旋转矩形（OBB）再栅格化成障碍。
   实测框面积 / 真实足迹 = **1.65×**，且框边界随"连通域恰好切在哪"逐帧跳变。
2. **形状一直在变**：单帧只看到建筑的**一个角 + 侧墙斜带**（14 m 高度看 100×100 m 场地时，
   42 个障碍里 **0 个能拍全、38 个完全在视场外**）。这种碎片的外接框形状取决于画幅边缘
   恰好切在哪里，而 UAV 在跟踪目标、一直在动 ⇒ 单帧估计再稳也稳不住"本来就在变的碎片"。
3. **幅度特别大**：侧墙点被纳入 XY 包络。同一物体 `sx` 实测在 **2.50..3.05 m** 间变
   （真实屋顶 2.0 m），偶尔某帧侧墙整片断开 → 形状大幅跳再回归。
4. **地图只增不减**：只有"障碍点"观测、没有负证据，旧形状永不擦除。

四层叠加后，规划器看到的是一个**比真实障碍大 65%、且每帧都在变形**的地图。

## 决策

### (a) 障碍框层**整体退役**，RViz 只显示栅格

用户裁定原话：**"红框其实没有存在的必要，直接显示栅格，这样最真实，车用的是什么就看到什么"**。

- 删除 `mergeFragments` / `extractBoxesFromGrid` / `merged_pub_` / `box_tracks_` / `box_ids_` /
  `box_next_id_` / `merge_gate_m` / `expireDynamic` / `collectCells` / `collectCellsFor`；
- 话题 `/agc/map/obstacles`（合并后的障碍框）**退役**，`viz_markers.py` 的 `on_obstacles()` /
  `confidence_color()` / `safety_obstacle_margin` / `safety_extra` 一并删除；
- `agc_demo.rviz` 的 `Map` 显示 `Enabled: true`，Alpha 0.85；
- **不保留**"只发不画"的僵尸话题，也不保留任何"顺手接回来"的参数入口
  （留一个没有消费者的参数等于留一个复活入口）。

### (b) 障碍表示 = **足迹点 + log-odds 增量累积**

- `nadir_projection` 新增第 10 个消息 `ObstacleFootprintArray`（`points` + `obstacle_id` +
  `confidence` + `source`），发 `/agc/obstacle_footprints`。
  **这是新增消息，不改动契约里 9 个既有消息的字段与顺序** —— 契约保护的是"字段/顺序"，不是消息数量。
- `map_adapter` 逐点落格（`floor((p.x - ox_) / res_)`），**不做"连通域 → 框 → 栅格化"**。
  表示误差归零：不再有 AABB 包大、不再有框边界跳变。
- 栅格内容来自 `LogOddsGrid` 累积（参照 ego-planner `plan_env/src/grid_map.cpp`）：
  `p_hit=0.70` / `p_miss=0.35` / `p_init=0.30` / `occupied_threshold=0.60` /
  `p_decay=0.48`。**单帧毛刺画不出来**（从 0.30 起步需约 2 次连续命中才跨过门限）。
- 新增 `carveRay()`（Bresenham，参照 `plan_env/src/raycast.cpp`，降到 2D）：
  对「相机地面投影 → 障碍落点」的射线途经格打**真实负证据**，**终点格不 carve**。
  这是"地图只增不减"的根因修复。

### (c) `OccupancyGrid` 输出**量化概率**，不再三态

- `snapshot()` 输出：`-1 = unknown`、`0 = free`、`1–99 = 概率×100`、`100 = occupied`。
- `nav_msgs/OccupancyGrid.data` 的语义本来就是"占据概率×100"，压成三态是对该消息的浪费；
  连续值让 RViz 直接显示梯度，也让消费者能按自己的阈值判"算不算障碍"。
- 两个门限仍保留，但只用来**保证两端语义**：≥ `occupied_threshold` 饱和为 100、
  ≤ `free_threshold` 为 0，其余量化到 1–99。
- **不借用 Nav2 的 `lethal_cost_threshold`**：用户裁定"我们要和 Nav2 解绑的"。
  判据落在本仓自己的 `planning_policy.hpp`。

### (d) 屋顶带过滤：z 直方图剔除侧墙

- 门限 = `max(0.25 m, 0.15 × 该连通域高度)`。两个分量各有其职：绝对下限托住矮障碍
  （薄板按比例会算出 0 门限、把顶面剔光），比例项自适应高建筑（10 m 楼允许 1.5 m 屋顶起伏）。
- 基准取 z 的 **90% 分位**，**不是** `z_max`：侧墙最顶一行与屋顶只差一个深度噪声的量级，
  以 `z_max` 为基准时那一行稳稳落在门限内，它的 XY 已外扩，足以把包络从 1.0 m 撑到 2.0 m
  —— 过滤形同虚设。
- 实测效果：`sx` 跨度 **2.900 m → 1.200 m（59% 抑制）**，130/300 点保留。
- **方法边界（如实登记）**：墙与屋顶在交界处 z 相同，**没有纯 z 判据能分开**；
  只有墙**体**被剔除。立面为主的连通域（斜视看墙）会触发"退回全部点"兜底 ——
  以墙面当足迹虽不精确，但方向安全（障碍只会被高估）。

### (e) `min_area_px`（像素）→ `min_obstacle_side_m`（物理量）

- 物理门限 `0.24 m`，**每帧按 GSD 实时换算**成像素：`min_area_px = (min_side / GSD)²`，
  `GSD = H/f`，`H = 机体 z + kCamMountZ`。
- **为什么必须改**：`min_area_px` 的单位是像素，但它的**物理含义**是"最小可测障碍尺寸"。
  一旦高度可变（自主定高），固定像素门限会让判据**随高度漂移**：飞低了突然多出一堆
  0.05 m 碎片，飞高了细杆被静默吞掉。
- 高度无效（odom 未就绪）时退回 **1 像素**（= 不额外过滤，让下游按 OBB 尺寸兜底），
  **不**退回一个猜的高度 —— 那会让门限静默变成另一个物理含义。
- 退化输入（GSD≤0 / 尺寸≤0）返回 **≥1**，**绝不返回 0**（0 会让所有碎片通过门限）。

### (f) 相机口径：**1152×1152 @130° @10 Hz**

- 正下视透视恒等式 **GSD = 2R/N**（与高度、FOV 都无关）⇒ 给定像素数，
  "覆盖半径 / 最小可测尺寸"的比值恒定；**FOV 只决定在哪个高度上拿到它**。
- 选 1152² 的理由：`GSD = H/f = 5.30 cm/px`，**恰好保持改造前的精度口径**
  （`min_area_px=20` ↔ 0.24 m 不变），而覆盖半径从 12.73 m 提到 **30.5 m**。
- **为什么不是 2048²**：整链实测 2048²@30Hz RTF 0.191、@10Hz 仍 0.322 且
  `map_adapter` 的地图重建只打了 1 行（640² 时 1114 行）—— 感知链基本不出结果，终态
  INFRA_FAILURE。早期"2048²@30Hz RTF=1.00"的压测是**裸 gz 无订阅者**，不代表整链。
- **为什么 10 Hz 够**：下游 `map_adapter` 发布 `/agc/map` 是 **2 Hz**、costmap
  `update_frequency` 是 **5 Hz**，10 Hz 已是需求的两倍。渲染量 1152²×10 = 13.3 MP/s
  已高于改造前 640×480×30 = 9.2 MP/s（RTF 0.655→0.546 对得上）。
- 原 640×480@100° 的实际覆盖是 **33.9 × 25.5 m 矩形**（垂直半高仅 12.73 m），
  README 里"半径 17 m"是**水平半宽**、一直偏乐观。改正方形后各向同性。
- **不用鱼眼**：正下视透视的地面与像面**平行**，GSD 全场均匀；鱼眼（equidistant）
  反而让边缘 GSD 恶化 `1/cosθ`（130° 时 2.4×）。

### (g) 未知空间策略：`allow_unknown: false` 语义 + 目标在未知区走**直连兜底**

用户裁定原话：**"如果没覆盖到目标点就从已知区域边缘直接连一条直线到目标点，
这一步本来就是生成粗糙路径"**。

- **不依赖 Navfn 的 `allow_unknown`**：它是 Navfn 的私有参数，而项目正与 Nav2 解绑
  （[ADR-0003](0003-nav2-paradigm-absorption.md#top)）。"未知不可走"由
  `include/agc_ground/planning_policy.hpp` 的**端点判定**表达，换规划器仍成立。
- 判据（纯逻辑，可单测）：`classifyCell(v)` → `v == 0` 为 `kFree`、`v < 0` 为 `kUnknown`、
  `v ≥ 100` 为 `kOccupied`、`1–99` 为 `kUnknown`。
  - 起点在未知区 → **明确拒绝**（车不能从没看过的地方出发）；
  - 终点在未知区 → 走直连兜底，不直接判失败。
- 直连兜底三条约束：① 直连段不得穿过**已知占据**格；② 两端必须都在已知自由区；
  ③ 直连段在 costmap 里按可通行处理（否则规划器根本走不出来，兜底失效）。

### (h) 聚合复杂度：O(C·N²) → O(N²)（2026-11-09 性能修复）

- **问题**：`aggregateObbs` 原实现对**每个连通域各扫全图两遍**。640×480 时 C 小、N² 小，
  完全掩盖了它；换到 1152² 后，10 Hz 的单帧预算是 100 ms，而 **C ≈ 30 就是临界点**。
- **临界点不是假设，是实测命中的**：整链运行实测真实连通域数 **25.5 个均值 / 35 个峰值**，
  障碍像素 17 万（16.8% of 1152²）。按这组参数复算旧实现：C=33 时 **71 ms/帧（14.0 Hz）**
  —— 10 Hz 预算只剩 29% 余量，场景再密一点就会跌破。
- **做法**：一次 CC + 一次光栅扫描，把每个连通域的 3D 点按段存进扁平数组
  （`collectComponentPoints`）；下游按段读取。同一份点池同时供 OBB 聚合与足迹点发布使用，
  顺带消掉原先的**第二次 CC**（`publishFootprints` 曾对同一张 mask 再跑一遍）。
- **等价性**：段内保持光栅顺序（与原实现推进顺序一致），段内只存 z 有限的像素
  （正是原实现唯一会累加的那批）⇒ `minAreaRect` 的输入点序列逐元素相同。
  单测 `PointPoolMatchesPerComponentScan` 逐字段对拍，另做 200 组随机用例验证。
- **实测**：71 ms → **15 ms**，整链帧率 **9.65 Hz 均值（8.91–10.14）**，余量从 29% 提到 85%。
- `nadir_projection` 每 5 s 打一行 `帧统计`（实测帧率 / 连通域数 / 障碍像素数）。
  **为什么必须有**：`map_adapter` 的"map 重建"行是**内容变化率**、不是帧率（内容收敛后
  自然下降），据此反推会得出错误结论。

### (j) 相机几何**单一来源** + 严格时间同步（2026-11-09 补正）

**根因**：`nadir_projection`（投影端）与 `map_adapter`（地图端）**各算一套相机几何**。
投影端按机体姿态反投影出障碍点的 world 坐标；地图端只取 odom 的 `x/y/z`，
把画幅当成"以相机地面投影为中心的轴对齐矩形"、把相机当成永远正下视无旋转。
相机一转向/倾斜就错位：障碍点落在一处、carving 射线从另一处出发、画幅边界与
真实视场不符 —— 误覆盖随姿态周期性变化。同时标签/深度/odom 是三个独立流，
此前只存"最新一条"，三者可能对应三个不同时刻。

- **几何唯一来源**：新增 `include/agc_perception/camera_geometry.hpp`（**不依赖 OpenCV**），
  承载 `kCamMountZ` / `Quat` / `CamPose` / `CamIntrinsics` / 轴映射 `opticalRayToBody` /
  `cameraWorldOrigin`（含**姿态旋转后的安装偏移**）/ `cameraGroundPoint` / `pixelDepthToWorld` /
  `pixelToGround` / 位姿时间查询 `poseAtTime`。`nadir_geometry.hpp` 只 include 它，
  不再重新定义任何几何；`map_adapter` 直接 include 它 —— 不再本地复制 `kCamMountZ_`。
- **画幅是四边形**：`footprint_geometry.hpp` 的 `footprintFromCamera(pose, k, w, h)` 把
  图像四角（主点 ± 半幅）经同一套几何投影到地面，得到凸四边形（倾斜时是梯形）。
  边界距离用**多边形射线求交**，内外判定用**同号判据**，边缘带用**点到边界距离**。
  轴对齐重载 `footprintFromCamera(h, fx, fy, w, h)` 只保留给单测/诊断。
- **射线起点是光轴落点**：`cameraGroundPoint(pose)`，不是机体位置、也不是安装点。
  姿态异常（光轴不落地）时本帧**不做负证据**。
- **障碍高度用稳健值**：每个角度箱取 z 样本的**中位数**，不用单个最近点的 z。
  阴影长度 `d_o·H/(H−H_obs)` 对高度极敏感，单点噪声会让阴影远边跳数米。
- **严格时间同步**（`nadir_projection`）：深度存**环形缓冲**（`depth_buffer_n`），
  按标签时间戳选**最近**一帧；odom 存**环形缓冲**（`odom_buffer_n`），按同一时间戳
  **插值**（位置线性 / 姿态球面）。超出 `odom_pair_tolerance_s` 即**丢帧**，
  不拿"最新 odom"凑。四元数做有限性 + 单位范数校验，不合法丢帧。
- **地图端同口径**：`map_adapter` 按**足迹帧时间戳**查位姿（同一个 `poseAtTime`），
  超时则跳过负证据（只做正证据）。`camera_info` 的 `cx/cy` 一并保存（画幅四角依赖主点），
  并校验其 `width/height` 与图像一致 —— 内参与像素不配套会让点**系统性**偏移。
- **深度空间一致性**：与右/下邻像素的轴向深度跳变超过 `depth_edge_m`（0.5 m）即判边缘、
  不进点池。深度边缘是"墙深被套到地面像素"的主要来源。

### (k) 负证据只作用于**有效视野**，发布与更新解耦

- **视野外不参与时间衰减**：`LogOddsGrid::decayMissMasked(inside)` 只在
  `decay_inside_footprint_only=true` 时对**本帧画幅覆盖**的格施加 `p_decay`。
  画幅外的格，"本帧没看到"是必然的、不携带信息 —— 每帧衰减等于"不盯着看就消失"，
  正是"消失—重新出现"周期的来源。`decayMiss()`（无掩码）保留为旧口径，供单测对照。
- **发布值量化（deadband）**：`publish_deadband`（缺省 5）把 1–99 的中间概率按步长量化后
  再比较/发布；`0/100/-1` 原样保留。否则任一格从 48 变 47 就让整图"变化"并重新发布。
- **证据更新与地图发布解耦**：感知回调只更新累积层；`/agc/map` 由 timer 按 `rate_hz`
  （2 Hz）发布。改造前回调里 `if (rebuild()) publishMap();` 让地图实际按感知帧率（10 Hz）
  重建与发布，而 `rate_hz` 只控制 timer —— 配置与实际行为不一致，稳定性指标因此虚高。
- **参数口径统一**：`perception.yaml` 的 `log_odds_p_miss` 由 **0.35 改为 0.25**，
  与 `LogOddsParams::p_miss` 默认值及设计推导（擦回门限需 3 帧而非 5 帧）一致。
  注释、默认值、YAML、推导四者从此必须同值。

### (m) carve 射程 = **可信测量半径**，不是几何视场边界（2026-11-09 实测修正）

**(j) 的遗留缺陷**：把画幅改成"四角投影的四边形"后，carve 直接射到那个边界。
但**几何视场边界 ≠ 可信测量边界**：机体悬停时约有 1–2° 姿态倾斜，倾斜把画幅沿该
方向拉长（实测 2° 时 bbox 半宽从 30.0 涨到 32.5 m、四角最远 46 m），而真实可信半宽
只有 30 m。carve 射到拉长后的边界 ⇒ 射线穿过"几何上在视场内、但实际测不准"的区域。

**实测后果（整链，`perception_quality.py`）**：

- 911 个真值障碍格被标成 free，其中 **86% 从未进入过任何一帧画幅**；
  它们距相机 40–50 m（真实可信半宽 30 m）—— 是 carve 顺手擦的，不是漏检。
- 误覆盖 74% 落在 30.5 m 之外。

**修正**：新增 `trustedRadius(cam_h, fx, img_w)`（`footprint_geometry.hpp`），
由**正下视 GSD 恒等式**给出可信半径：

```text
r_trust = cam_h · (N/2) / f × edge_ratio(0.95)
```

- 与**姿态无关**（姿态只影响几何视场，不影响"多大范围内测得到"）；
- 随**高度线性缩放**，自主定高上线后判据自动跟随（与 (e) 把 `min_area_px` 改成
  物理量是同一条理由；**不**用手填常数 `carve_max_range_m`）；
- carve 射程取 `min(可信半径, 画幅边界, carve_max_range_m)`；
- "视野内衰减"（(k)）的掩码同样受它约束 —— 否则几何画幅外那个"测不准环带"
  仍会被当成"看过"而衰减陈旧证据。

**实测改善**（同一场景、同一采集脚本，前后对照）：

### (n) hit 与 carve **同一道闸** + 画幅合理性（2026-11-09 实测修正，(m) 的补全）

**(m) 的缺陷**：只给 carve（负证据）加了可信半径，**忘了 hit（正证据）**。

**实测后果**：1502 个真值格被标成 occupied，却**从未进入过任何一帧画幅**；
过渡段大前倾时画幅算出 `123.9 × 188.2 m`（俯仰约 18°），甚至 `0.0 × 0.0`，
而 occupied 反而单帧涨 **719 格** —— hit 只做越界检查，对"这点是否测得到"不设防。
最终 occupied 涨到 **6829 格**（真值 4590），误覆盖率 0.561。

**修正三条**：

1. **hit 也过可信半径**：与 carve 同口径，超出 `trustedRadius` 的点直接拒。
2. **无位姿 ⇒ 整帧不写 hit**：没有位姿就没有可信半径，无法判断点是否可测。
   宁可少画（unknown 不是障碍，规划器可以走），也不要把测不到的地方画成障碍。
3. **画幅合理性 `footprintPlausible`**：包围盒半宽超过正下视半宽的
   `kFootprintMaxTiltRatio`（1.6）倍即判不可信 —— 大前倾时四角投影发散，
   "视场边界"这个前提已失效。实测正常悬停（1–2°）比值 1.10–1.15，留足余量；
   18° 前倾比值 4 倍以上，会被明确拦下。

**实测改善**（全程 205 帧采样，覆盖 51.2% 作业区，修正前→后）：

| 指标 | 修正前 | 修正后 |
|---|---|---|
| 误覆盖率 | 0.561 | **0.308** ✅ |
| IoU | 0.426 | **0.641** ✅ |
| 面积覆盖率 | 0.932 | 0.892 ✅ |
| 形状抖动 p95 | 0.034 | 0.029 ✅ |
| 稳定性 p99 | 454 | **140**（未达标）|
| **TP 落在画幅内的比例** | **49.4%** | **95.6%** |
| 最终 occupied 格 | 6829 | 2043 |

**诚实性判据（新增，必须守住）**：地图上的 occupied 格必须有**观测依据** ——
TP 落在画幅并集内的比例是最直接的泄漏检测器。修正前 49.4%（一半 TP 没有观测依据，
说明 hit 在视场外乱标），修正后 95.6%。这条判据比"覆盖率"更能识别真值泄漏或几何失控。

**诊断计数**（每帧日志）：`拒点`（超可信半径被拒的足迹点）、`跳过hit帧`
（无位姿而整帧不写 hit）、`画幅异常帧`（`footprintPlausible` 判否）。
实测本轮：拒点 7311、跳过hit帧 0、画幅异常帧 29。

### (o) 证据单位 = **每格每帧一次** + 状态推进按地图帧（2026-11-09 稳定性根因修复）

**(b) 的遗留缺陷**：`map_adapter` 对每个足迹点直接 `observeHit(idx)`，**没有按格去重**。
一个 0.5 m 格通常覆盖大量像素，于是同一格在一帧内被 hit 数十次。

**为什么这是缺陷**：证据强度于是取决于**像素采样密度**而不是时序观测。
栅格中心一帧打满、障碍边缘只命中一两次；分割边缘移动半个像素，某些格就从几十次 hit
变成 0 次。边缘格反复经历"大量重复 hit → 100 → 被 carve/decay 拉低 → 再次出现 → 100"，
这正是 `|Δoccupied| p99 = 140`（判据 ≤50）的直接来源 —— 而同期 IoU 0.641、
形状抖动 0.029 都已达标，说明**几何正确性不是瓶颈，证据计量才是**。

**决策四条**：

1. **hit 去重**：`LogOddsGrid` 按帧号记账（`hit_frame_`），同一格同一帧重复
   `observeHit` 幂等。`map_adapter` 侧也先判 `hitThisFrame` 再记账，并收集唯一格集合。
2. **负证据同帧互斥**：`observeMiss` / `decayMissMasked` / `markStale` / `carveRay`
   共用**一个**每帧负证据槽位（`neg_frame_`），且**同帧已被 hit 的格不再吃负证据**。
   这同时修掉两件事：hit 与 miss 在同一帧互相抵消、以及 stale/decay/carve 三重叠加。
3. **迟滞状态按地图帧推进**：感知回调（10 Hz）**不再**调 `rebuild()`；
   `rebuild()`（内含 `snapshot()`，它推进 `occupied_now_`）只在 `tick()`（`rate_hz`，2 Hz）里调。
   改造前"内部迟滞 10 Hz、对外地图 2 Hz"—— 两次发布之间的 occupied→non→occupied
   翻转被内部吃掉，而稳定性指标是按 `/agc/map` 帧统计的，口径与实现脱节。
4. **诊断三量分开报**：`unique_hit`（唯一格数）/ `points`（原始点数）/ `dup`（重复点数）。
   改造前 `carve/hit` 的分母是**原始足迹点数**，随像素密度放大 ⇒ 负证据强度被系统性低估。
   `carve/unique_hit` 才是可解读的比值。

**`publish_deadband` 不是稳定性手段**（口径边界，须防止误用）：它只量化 1–99 的中间概率，
而 `perception_quality.py` 把 1–99 一律算 unknown —— 只有 99/中间值 ↔ 100 的跨门限翻转
才影响 p99。deadband 改善的是**消息与 hash 的更新频率**，对 p99 无作用。

**稳定性诊断（判据不动，只加诊断）**：`perception_quality.py` 的 `|Δocc|` 无法区分
"空间抖动"与"数量波动"，故新增**集合级诊断量**（不参与 verdict）：
`exit_p99` / `enter_p99` / `set_iou_p50` / `churn_ratio_p50` / `exit_dist_p90` / `edge_frac_p50`。
判据仍是预登记的 `delta_p99 ≤ 50`，**不得据此事后调整**。

**离线复算的保真度修正（如实登记，含未通过项）**：
`map_stability_recompute.py` 此前**没有**建模 `carveRay()` 的"射线遇 occupied 即停"，
于是 carve 会一路穿过历史障碍去擦它后面的格 —— occupied 长期被压在 ~505 格
（真值 4590，覆盖率仅 11%），抖动自然小（p99=48）。补齐后 occupied 稳定在 ~1600 格
（TP 1514 / FP 0，**覆盖率高 3.4 倍且误覆盖仍为 0**），代价是增长期更长、p99 升到 **112**。

因此 48 是**模型失真**的产物，不是系统改善：它对真实链路的 140 不构成有效下界
（48 ≪ 140），而 112 是（112 < 140）。

**口径细化（2026-11-09 用户裁定）**：统计窗口从"仅排除冷启动帧"细化为
"排除冷启动帧 **+** 增长期"。增长期 = occupied 首次达到本圈峰值
`GROWTH_SETTLE_RATIO`（90%）之前的帧 —— 那里每帧新进入画幅的障碍是**合法增长**，
不是用户反馈的"形状面积一直在变"。边界由 occupied 序列**推出**，不是手填帧数。
**阈值 `≤ 50` 未改**（预登记纪律）。

细化后 **p99 112 → 54，仍未达标**（54 > 50），闸门如实返回非 0。
剩余差距来自饱和段仍缓慢爬升（occupied 从 1599 继续涨到 1796），
属"新进入画幅的障碍"而非门限抖动 —— **不得**据此再放宽阈值。

### (l) 碎片合并：面积门限不得吞掉同一障碍的碎片

`min_area_px` 按"单个连通域面积"判定。大建筑被深度噪声 / 遮挡 / 画幅边缘切成多块时，
每块单独都可能低于门限，整块真实障碍被丢掉 —— 覆盖率因此有与算法无关的天花板。

- `collectComponentPoints(..., FragmentMergeParams)` 先算每段形心与 z 包络，
  把**面积未达标**的碎片并入最近的**达标母体**：形心水平距离 ≤ `fragment_merge_gap_m`（1.5 m
  ≈ 3 格）且 z 包络间隙 ≤ `fragment_merge_dz_m`（1.0 m）。
- 用**并查集分组**（`group_of`）：合并只改归属、**不搬点**，`points` 与 `kept` 的下标
  始终一一对应 —— 搬点最容易让屋顶带掩码与点错位。
- **不合并孤立噪声**：只有已达门限的母体才能收碎片；孤立碎片仍按原口径丢弃。
- **高度一致判据是必须的**：否则贴着高楼的矮台会借用高楼的高度，把阴影算长。
- `fragment_merge_gap_m=0` 即关闭（与改造前逐字节等价，单测用它做对照）。

### (i) DDS SHM segment 与深度图时间容差

- `segment_size = 16 MB`（`scripts/demo/dds_transport.py`，用户裁定 Q33）。
  实测：16.78 MB 消息默认配置下 **0.12 Hz**，配 16 MB 后 **30.0 Hz**（大消息提升 250×，
  小消息不退化）。`segment_size` 只能通过 XML profile 设置，没有对应环境变量。
- `depth_pair_tolerance_s = 0.15`（原 0.10）。标签与深度来自两个传感器，10 Hz 下
  帧间隔 100 ms，0.10 s 容差会把正常抖动判成错位。

## 不做什么

- **不**做物体级跟踪 / 多目标数据关联的语义升级（`associateNearest` 保持现状）；
- **不**引入 Nav2 的 `lethal_cost_threshold` 或任何 Nav2 私有参数作为判据来源；
- **不**做"感知失效回退静态先验"的第二条路（丢包 / 遮挡时地图开洞是**已登记边界**）；
- **不**承诺"墙与屋顶能被完全分离"（见 (d) 方法边界）；
- **不**承诺 1152² 能走到 `TRACKING_SUCCESS` —— 实测只到 `GROUND_APPROACH`，
  且被 `--duration 90` 截断，**不是失败也不是成功**。

## Considered Options

- **保留框层、只做平滑** —— 被否：框面积/真实足迹 1.65× 是表示误差，平滑只能让错的东西
  更稳定地错。用户裁定"红框没有存在的必要"。
- **用 2048² 提精度** —— 被否：整链实测 RTF 0.191/0.322、感知链几乎不产出、终态 INFRA_FAILURE。
  且 `GSD = 2R/N` 说明提 N 与扩 R 是**同一个旋钮的两端**，1152² 已在"精度不变"前提下把覆盖翻倍。
- **用 Navfn 的 `allow_unknown=false`** —— 被否：私有参数，与解绑方向冲突；
  且它单独不足以表达"未知区不可走"（`track_unknown_space` 与 `allow_unknown` 会互相抵消）。
- **`min_area_px` 保持不变** —— 被否：单位是像素、物理含义是尺寸，高度一变判据就漂移。
- **不修 `aggregateObbs`、只把帧率降到 5 Hz** —— 被否：下游 costmap 要 5 Hz，
  降帧率等于把感知变成瓶颈；且成本与 C 成正比意味着"场景一变就崩"，不是可接受的设计。

#### 待裁定与待办

- **【待用户裁定】真值栅格化口径**：现口径（格中心）把"小于一格的障碍"判成 FP。
  若改为"任意接触"（与地图侧一致），误覆盖率 0.387→0.155、IoU 0.455→0.562，
  **六项可全过**。但这是**改判据**，按预登记纪律不得由实现方自行决定。
- **【实验 D 待办】**：不同轨迹/初始姿态验证。s18 不可用（障碍轴 `none`，世界无实体，
  `obstacles: []`）—— 它是"同一张 yard 地图 + 无实体障碍"，不是"不同地图"。
  用户裁定：**明日配合新的高密度地图做**。
- **【不得做】**：在真值口径未裁定前调 `p_hit` / carving / `min_area_px`。
  面积比仅 0.178–0.220（远小于 1）说明地图**不是整体膨胀**，收紧只会同时压低覆盖率与 IoU。

### 已知缺口（如实登记）

- **1152² 未跑到 `TRACKING_SUCCESS`**：实测 RTF 0.546、感知链正常（`帧统计` 稳定 9.65 Hz）、
  终态 `GROUND_APPROACH`，被 `--duration 90` 截断。**不能**据此宣称"1152² 能完成任务"。
- **连通域数的上界未知**：实测峰值 35，但那是当前场景 / 当前 UAV 位置。修复后成本与 C 解耦，
  所以这不是风险，但"峰值 35"不能当作设计上限。
- **墙/屋顶同 z 处不可分**（见 (d)）。
- **稳定性 p99（140）仍未达标**（判据 ≤50）：由 **FP 格的 hit/miss 竞争**主导，
  实测稳态每帧真实障碍格几乎不动、FP 格大幅正负抵消。这是当前唯一的未达标项。
  **2026-11-09 已修证据单位（见 (o)），但修复后尚未重新实测 p99** —— 不得据设计推导
  宣称已达标；须以 `perception_quality.py` 的实跑数字为准。
- **离线稳定性闸门当前未通过（p99=54，判据 ≤50）**：这是**保真度修正**的结果
  （补齐 `carveRay` 的"射线遇 occupied 即停"），见 (o)。旧值 48 是模型失真的产物，
  对真实链路不构成有效下界。排除增长期后 112 → 54，剩余 4 格来自饱和段缓慢爬升
  （新进入画幅的障碍），**不得**据此放宽阈值。
- **误覆盖未通过（见 (p)）**：2026-11-09 审核轮 4 次重复实测 0.368–0.387（均值 0.375），
  **4/4 全部超过判据 0.35**。分解见 (p)：62.1% 的 FP 在真值 1 格内、68.4% 紧贴小障碍。
  此前记录的 0.308 是**单次采样**结果，重复实验未能复现。
- **IoU 与覆盖率余量不足**：4 次重复中各有 1 次跌破判据（IoU 0.409 < 0.45、
  覆盖率 0.544 < 0.55），**不得**据单次通过宣称达标（见 (p) 实验 C）。
- **本轮只跑了 110 s 的 s04 场景**：数值改善是该场景、该轨迹下的实测，
  不得外推到其它场景或更长航时。
- **采样窗口必须覆盖建图全过程**：只采运行末尾会测到"已建好的地图"，
  曾据此得出过偏高的覆盖率（0.912）并误判为改善 —— 那是**采集口径错误**，
  不是算法改善。判据：采样跨度须覆盖从 occupied≈0 到收敛的全程。
- **碎片合并门限是几何先验**（1.5 m / 1.0 m）：它假设"同一障碍的碎片间距 ≤ 1.5 m 且
  高度相近"。两个**真实相邻**但独立的障碍（间距 < 1.5 m）会被并成一个 —— 已登记边界。
- **倾斜时画幅是梯形，但地图端仍按"光轴落点 + 多边形"近似**：四边形由四角投影得到，
  是**真实视场边界**；然而 carve 的 miss 仍按 2D 直线施加，未建模倾斜带来的
  "近边与远边分辨率不同"。
- **WSL2 + Wayland 下无法截取 X root 像素**：可验证"无 GLSL 错误"，**不可**宣称"栅格确实渲染了"。

### 与旧 ADR 的关系

- [ADR-0007](0007-scene-geometry-single-source-and-layout.md#top) (e) 的"数据契约不变：
  `0=free / 100=occupied / -1=unknown`" 被 **(c) 量化概率**取代；其余（内容身份 hash、
  单调更新序号、逐字节比较）**仍有效**。
- [ADR-0009](0009-perception-truth-derived-and-vision-path.md#top) (c) 的障碍族可见性边界
  **仍有效**（它讲的是**车的激光** z≈0.48 m 单平面，与本篇讲机载相机不冲突）。
  本篇 (d)/(e) 补充的是**机载相机侧**的可见性与最小可测尺寸。
- [ADR-0013](0013-ground-planning-path-contract.md#top) (b) 的地图签名口径（只计 `== 254`
  的 `LETHAL_OBSTACLE`）**仍有效**：`/agc/map` 现在有 1–99 的中间值，但 costmap 的
  `static_layer` 按自己的阈值判 lethal，签名只看 `== 254`，**不受影响**。
- [ADR-0030](0030-nadir-camera-capability.md#top) 的相机参数（`horizontal_fov 1.745`、
  `640×480`、`update_rate 30`）与"不接任务链"结论被本篇 **(b)/(f)** 取代；
  其挂载范式（独立 link + fixed joint）、`pitch=+1.5708`、`camera_info` 显式命名、
  opt-in 结论**仍有效**。

### 2026-11-10 演进：多分辨率（补充 by ADR-0040，非取代）

[ADR-0040](0040-perception-multi-resolution-evidence-and-planning-layers.md#top) 修订本篇 **(b)** 的
「单一分辨率 log-odds 栅格即地图真源」：证据累积改在 0.25 m 的**证据层**，
0.5 m 降为由它派生的**规划层**。本篇 (c) 的四态输出语义（`-1 / 0 / 1–99 / 100`）
与 (g) 的三态规划策略**逐字不变**，只是现在由派生规则产生。

本篇 (b) 记录的 `p_hit=0.70` / `p_miss=0.35` / `p_init=0.30` / `occupied_threshold=0.60` /
`p_decay=0.48` 等参数**全部保留且仍生效**（后续由 ADR-0039 把 `p_miss` 修为 0.25）。

**新增的集成风险（本篇未预见，现登记）**：本篇 (c) 让 `/agc/map` 输出 `1–99` 作为
"量化占据概率"，本仓消费者把它读作 **unknown**（`planning_policy.hpp` 的 `classifyCell`）。
而 Nav2 默认 `trinary_costmap=true` 会把 `1–99` 折叠成 `FREE_SPACE`（只有精确等于
`unknown_cost_value`，默认 255，才是 unknown）。因此任何 **Nav2** 消费者订阅本仓
`/agc/map` 时必须显式设 `trinary_costmap: false`，否则会把"不确定"读成"可通行" ——
这是安全方向的错误。本仓主链不走 Nav2 的 `static_layer` 判据（(c) 已裁定与 Nav2 解绑），
故不影响现状。
