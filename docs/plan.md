# AGC 演示流程规整与对抗语义计划

## 目标
把 `./run_demo.sh` 变成可解释、可复现的单入口：三机按就绪条件进入任务；目标默认悬停，显式参数才逃逸；RViz 只显示车辆轨迹及三机颜色/方向；捕获和运行结果按场景登记判定。

## 实施边界
不新增第二套启动编排，不把可视化写入控制链，不把 Gazebo 装饰物作为传感器或捕获依据；不并行启动 Gazebo。目标逃逸先采用受参数控制的、受边界约束的目标规避控制，不改变默认场景行为。Gazebo 光圈不参与物理计算；优先移除会造成误解的 RViz 安全盘，保留模型高亮仅作显示。

## 出口判据
- `./run_demo.sh` 支持 `--escape`，无参数时目标 `static` 语义不变；目标起飞完成后才允许任务开始，失败能明确指出目标未起飞。
- 目标逃逸有明确参数、速度/区域上限和日志证据；默认场景无逃逸回归。
- RViz 不发布安全禁飞盘；车辆轨迹仅车辆一条；车辆绿色、己方机蓝色、目标红色，三者有方向箭头。
- 结果判定读取场景 `expected_terminal/expected_reason`，捕获命中不因命中瞬间任务状态变化而丢失。
- 离线测试、语法检查和至少一次受控 full 仿真验证通过；启动仿真前清理残留，任意时刻最多一个 Gazebo worker。

## 依赖与并行
两个只读 worker 已完成启动链/参数/捕获/可视化调研，未启动仿真。后续实现由主链完成；Gazebo 验证必须先清理本项目记录的进程并独占执行，其他 worker 不得启动仿真。永久决策归档到 ADR/规范后，本文件按项目规则删除。
