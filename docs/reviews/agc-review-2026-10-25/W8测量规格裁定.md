## 二、核心判断：`feasible=false` 这个结论不成立，它是由固定 seed 造成的假象

[ADR-0096](../../adr/0096-w8-gui-headless-equivalence-design-bounds-and-gate.md) 把「δ≤0.05、n≤40 下不可行」当作平台性质写进决策。我打开原始的 `summary.json` 逐条重算，没有接受它引用的聚合报告里的数字。结论是：这个不可行不是平台的性质，而是实验设计的产物。

### 证据 1：40 次 pilot 只有 4 个独立条件，2 个 seed

`distinct (batch, scene, seed)` = `(v1,p1,5)`、`(v1,p2,0)`、`(gpu,p1,5)`、`(gpu,p2,0)`。

每个单元格里的 5 次「重复」，用的是同一个 seed，只是重跑。[ADR-0096:48](../../adr/0096-w8-gui-headless-equivalence-design-bounds-and-gate.md:48) 说 pilot「只用于估计 within-mode 散布」，但同一 seed 下的重跑根本估计不了这种散布：它只能测出执行级非确定性。这个量被当成了「平台噪声」。

### 证据 2：该非确定性的量级是决策门槛的 3–14 倍

同一 seed、同一模式、同一场景，active FCO 逐次实测：

| 单元格 | 5 次重复的 FCO | 极差 |
|---|---|---|
| GPU p2 GUI | 0.001 / 0.025 / 0.274 / 0.013 / — | 0.273 |
| GPU p1 GUI | 0.088 / 0.000 / 0.201 / 0.036 / 0.004 | 0.201 |
| GPU p1 headless | 0.000 / 0.022 / 0.069 / 0.032 / 0.007 | 0.069 |
| v1 p2 GUI | 0.032 / 0.018 / 0.021 / 0.034 / — | 0.016 |

`seeding.py` 的 docstring 写明「物理步进调度不承诺 bitwise 一致」（[seeding.py:19-20](/home/chen/AGC/src/agc_rl/agc_rl/seeding.py:19)，另见 [seeding.py:100-101](/home/chen/AGC/src/agc_rl/agc_rl/seeding.py:100)），这是已知边界，但从来没有人量过它的量级。现在量出来了：同一个 seed 下的重复跑，可以差出 0.27 的火控机会率，而 MME 是 0.10，等价 δ 是 0.02。已知边界被当成噪声吸收掉了，没有当作需要处置的缺陷。

### 证据 3：可行性公式用错了输入

pilot 汇总的 `formal_design_inputs`（由 [w8_gui_headless_pilot.py:885](/home/chen/AGC/scripts/w8_gui_headless_pilot.py:885) 生成，结果见 [software pilot JSON](../../../experiments/w8-parity/20261025-w8-gui-headless-pilot/metrics/gui_headless_pilot.json) 与 [GPU-GUI pilot JSON](../../../experiments/w8-parity/20261025-w8-gui-gpu-pilot/metrics/gui_headless_pilot.json)）用 `δ − |Δ_pilot|` 作分母。把一次 pilot 的实测差当作效应量，在 `Δ_pilot` 本身噪声极大时就会机械地判「不可行」。同时，闸门规则判定「`|Δ_pilot| ≥ δ` 就不可行」的组合，在两模式真实没有差异、只是重复跑有散布时，判为不可行的概率是：

| 组合 | SE(Δpilot) | P(误判不可行 \| Δ真值=0) |
|---|---|---|
| v1 p1 | 0.061 | 74% |
| GPU p2 | 0.072 | 78% |
| GPU p1 | 0.039 | 61% |

也就是说，这个闸门在无差异时也有三到四分之三的概率判「不可行」。

### 证据 4：ADR-0096 内部算术自相矛盾

[ADR-0096:65-67](../../adr/0096-w8-gui-headless-equivalence-design-bounds-and-gate.md:65) 同时写了：δ≤0.05、n≤40/模式、n 由公式 `(z+z)²σ²/δ²` 计算。这三者不能同时成立：

| 指标 | σ | n=40 时实际可达的最小 δ | 达到 δ=0.02 所需 n |
|---|---|---|---|
| active FCO | 0.06 | 0.027 | 141（≈3.3 h/模式/场景） |
| active 可见率 | 0.30 | 0.133 | 3,532（≈83 h，不可行） |
| 率类 (p=0.86) | 0.347 | 0.154 | 756（≈18 h） |

n≤40 在数学上就无法验证 δ=0.02。可见率这个 co-primary 在任何预算下都不可能等价。这不是「预算不够」，而是规格写错了。

## 三、第二个缺陷：active FCO 的分母受终态污染

这一点必须现在提出，因为它已经影响了一个 co-primary。

[run_logger.cpp:791-800](/home/chen/AGC/src/agc_task/src/run_logger.cpp:791)：episode 窗口在 active 时开、终态或 IDLE 时关。实测：

| 终态 | n | 窗口 ticks 中位 | FCO 均值 | sim 秒中位 |
|---|---|---|---|---|
| INTERCEPT_CONFIRMED | 31 | 538 | 0.064 | 81 |
| MISSION_FAILED (超时) | 5 | 3,659 | 0.000 | 146 |

超时回合的窗口长度约是捕获回合的 2 倍，而 FCO 恒为 0。于是「超时」这一个事件机械地压低 active FCO 约一半。而 [ADR-0096:63](../../adr/0096-w8-gui-headless-equivalence-design-bounds-and-gate.md:63) 把「超时率」和「active FCO」同时列为 co-primary，两者因此不独立。

后果可以量出来。P2 GPU 单元格：

- Δ active FCO（含超时，原口径）= **+0.0284**
- Δ active FCO（仅捕获回合）= **−0.0046** ← 符号翻转

P1 v1：−0.0660 → −0.1015，绝对值放大 1.5 倍。

但有一件让人放心的事：**这个缺陷没有动摇 P2 v3 的结论。**

我拿 W8 的这个发现回去重算 P2 v3 的 20 对配对（剔除 3 对 `degraded=True`，其中 2 对是一臂捕获、另一臂超时）：

| 口径 | n | Δ | 95% CI |
|---|---|---|---|
| 原口径 | 20 | −0.0561 | [−0.0971, −0.0151] |
| 剔 degraded | 17 | −0.0545 | [−0.1025, −0.0065] |

MME=0.10，CI 上限仍远低于门槛，因此 `falsified` 结论在干净口径下依然成立。这意味着改成干净指标口径，不需要重开 P2 的预注册。这是好消息，应当写清楚，免得因为修口径把整个 W7-b 一起推翻。

## 四、三个小缺陷（成本低，但都会让证据被误读）

1. **`wall_start_unix_s` 精度截断**：[run_logger.cpp:360-361](/home/chen/AGC/src/agc_task/src/run_logger.cpp:360) 直接 `<< double`，输出 `1.79291e+09`，分辨率 2 分钟；而同文件的 rtf/duration_s 是 6 位有效数字。一个时间戳字段被写成有效数字，实际丢掉了 3 个数量级的精度。修法：`std::setprecision(17)` 或直接写整数 Unix 秒。
2. **`gui_renderer` 不是逐 run 的证据**：[episode_runner.py:475-490](/home/chen/AGC/scripts/episode_runner.py:475) 的 `_read_gui_renderer()` 读共享的 `~/.gz/rendering/ogre2.log`，取「最近一次」。[ADR-0096:92](../../adr/0096-w8-gui-headless-equivalence-design-bounds-and-gate.md:92) 自己承认「假设 GUI 不并行」。GPU 批次报告里逐 attempt 的 `renderer=D3D12` 实际上来自批次常量 `render_backend='mesa_d3d12_x11'`，不是每次独立观测。一旦并行（W7-c 恢复）就会读串。
3. **`gui_render_backend=auto` 不该进平台冻结**：[ADR-0097:60](../../adr/0097-w8-historical-parity-and-conditional-platform-freeze.md:60) 把它写进冻结契约，但同一 ADR 的 [0096:92](../../adr/0096-w8-gui-headless-equivalence-design-bounds-and-gate.md:92) 承认「换到无 `/dev/dxg` 的机器时 `auto` 自动回退，不保证 GPU」。冻结一个随机器静默漂移的默认值，等于冻结了一个不可验证的条件。

4. 把 `gui_render_backend=auto` 从「冻结条件」降为「部署默认」，冻结的是选择逻辑 + 实际 renderer 必须逐 run 记录这个事实。

### P1 · 真正的阻断项，30 分钟出答案（当前关键路径）

在动任何统计公式之前，先跑一次**确定性探针**：

- 条件：同 scene、同 seed、同 mode，n=5，只测 active FCO 与窗口长度。
- 判定：
  - spread 仍在 0.0–0.27：确认这是执行级不确定性，立 ADR 定为平台边界，并放弃 δ=0.02 的等价目标，改规格（「同 seed 复现率」或固定窗口 + 更长窗）。
  - spread 塌到 <0.01：说明固定 seed 下本可复现，那 40 次 pilot 的散布全是 cell 内的随机，必须用真 seed 网格重跑。

**在探针出结果之前，不要再跑任何 pilot 或正式等价。** 现在的 40 次 run 已经证明了继续加样本只会重复同一个混淆。

### P2 · 指标口径裁定（需 ADR，但不重开 P2 v3）

- 等价门的 co-primary 只保留分母与终态无关的指标。active FCO 的窗口长度随终态翻倍，不合格。可选：`window_fixed_v1` 固定 60 s 窗口（但 `window_s` 必须小于最短回合，实测最短约 72 s，边界很窄），或改为按时间归一化的 `FCO/s`。
- 明确写：此裁定不改变 P2 v3 的 `falsified`（剔除 degraded 后 CI 上限 −0.0065，仍低于 MME），也不改变 P1 v5 的 `inconclusive`。

### P3 · 仅在 P1 通过后

重算正式等价：删掉可见率作为 co-primary（σ=0.30 使它在 n≤40 下 δ 下限 0.133，永远不可行），率类需要 756/模式/场景 ≈18 h。ADR-0096 的「δ≤0.05 ∧ n≤40 ∧ 公式定 n」三者必须删掉一个，不能留着。

- 不要用「差异不显著」或「pilot Δ 小」替代等价（[ADR-0096:62](../../adr/0096-w8-gui-headless-equivalence-design-bounds-and-gate.md:62) 已经禁止，保持）。

## 七、一句话总结

W8 的方法纪律是这套项目里最好的一次：把 W8 拆成两个出口、拒绝在数据不支持时宣称等价、把 pre-fix 结论原样保留。问题不在纪律，在测量。40 次整链 run 花在了用固定 seed 冒充重复上，算出来的「不可行」是实验设计的产物，不是平台的边界。探针 30 分钟、10 次 run 就能分辨这两种解释。这是当前唯一值得跑的东西。
