# P1-3 · 任务可观测与演示呈现

> 索引：[项目完成路线](README.md#plan-index)。前置：[P1-2](p1-2-一键演示入口.md#p1-2-goal)。
> 下游：[P2-1](p2-1-项目交付物.md#p2-1-goal)。
> 约束引用：[终态语义](../../ROS2迁移交接文档.md#terminal-semantics)、[C8 终态表述](../../ROS2迁移交接文档.md#hard-constraints)。

## 为什么做

项目内部能力不少（状态机、感知融合、安全层、捕获裁决、火控窗口），但**观众看不到**。

现在能观察到的只有：

- Gazebo 窗口里的车和无人机在动（**没有标注意图**）；
- `ros2 topic echo /agc/task/state` 的裸字段；
- 一堆 `experiments/` 里的 JSON。

**答辩时最常见的问题**："它们在干什么？为什么算成功？" 现在答不上来——不是系统没做，是**没表达**。

**目标：让状态、意图、结果三件事在演示中可读。** 不做大型 Web 控制台，先做终端 + 轻量可视化。

## 要做什么

<a id="p1-3-implementation"></a>
### 0. 已交付实现（2026-10-30 round-1）

设计与上面各项一一对应，实现全部落在 `scripts/demo/`（P1-2 的既有骨架里，不新起入口）：

| 能力 | 文件 | 说明 |
|---|---|---|
| **状态语义映射（单一实现）** | [`status_map.py`](../../../scripts/demo/status_map.py) | 9 个枚举 + 36 条 `reason_code`；C8 禁词守卫在**导入期**自检；`coverage_report()` 供离线核对 |
| **2 Hz 终端面板** | [`panel.py`](../../../scripts/demo/panel.py) | tty = 方框原地重绘；非 tty = 单行 + 心跳。**不 import rclpy / 任何渲染库**，headless 同源可用 |
| **事件时间线** | [`timeline.py`](../../../scripts/demo/timeline.py) | 只在状态跳变时记一行；结尾写关键节点数（不足 5 个**如实说明**，不凑数） |
| **终态判定说明** | [`verdict.py`](../../../scripts/demo/verdict.py) | 指标只读 `summary.json`；阈值只读本 run 的 `config/params_applied.yaml`，缺就明说"来源缺失" |
| **接线** | [`start.py`](../../../scripts/demo/start.py) | 三件产物随演示落盘：`timeline.txt` / `panel.txt` / `terminal_explanation.txt` |

**两条工程纪律**（都是 round-1 实测换来的）：

1. **呈现层降级，不终止演示** —— round-1 首次 T2 因 `Timeline.state()` 缺参数抛到 `run()` 之外，
   监督进程崩溃而仿真进程组仍在跑（后由 `./run_demo.sh stop` 回收 33 个进程）。
   现在面板 / 时间线 / 判定说明的任何异常都进 `result['presentation_errors']` 并**继续跑**，
   旁路产物缺失可以容忍，真实实验白跑不行。
2. **未知状态 / 未知 reason 如实标注** —— `未识别的状态名` / `未收录的原因码（原样显示：…）`，
   不猜语义、不静默丢弃。

### 1. 状态语义映射（先有"人话"，再有界面）

[AgcTaskState](../../../src/agc_msgs/msg/AgcTaskState.msg) 的 `state` 枚举是开发词汇。需要一张**展示映射表**：

| 枚举 | 内部名 | 演示文案（建议） | 观众该理解什么 |
|---|---|---|---|
| 0 `IDLE` | 待命 | 系统待命 | 还没开始 |
| 1 `AIR_SEARCH` | 空中搜索 | 无人机搜索中 | 在找目标 |
| 2 `TARGET_ACQUIRED` | 目标已捕获 | 已发现目标 | 看见了 |
| 3 `GROUND_APPROACH` | 地面接近 | 地面车前往目标 | 正在靠近 |
| 4 `TRACKING_SUCCESS` | 跟踪成功 | 抵近并持续跟踪成功 | **完成**（不是"击落"） |
| 5 `MISSION_FAILED` | 任务失败 | 未能在时限内达成 | 失败 + 原因 |
| 6 `ABORTED` | 中止 | 任务被中止 | 外部中断 |
| 7 `INTERCEPT_CONFIRMED` | 拦截确认 | 拦截确认（网捕获/干扰） | 阶段 B |
| 8 `INFRA_FAILURE` | 基础设施失败 | 系统故障（非任务失败） | 环境问题 |

> **必须守住 [C8](../../ROS2迁移交接文档.md#hard-constraints)**：`TRACKING_SUCCESS` **不得**表述为"拦截完成"。文案表要写进代码注释与 README，防止有人手滑改坏。

**`reason_code` 也要翻译**（`CAPTURE_NET` / `JAM_RTL` / `JAM_LAND` / `JAM_HOLD` / `JAM_LOST` / 超时等），这是"为什么成功/失败"的关键。

### 2. 终端状态面板（最小可用）

在 P1-2 的启动器里加一个轻量订阅（Python 或 `ros2 topic echo`），输出：

```text
┌─ AGC 任务状态 ─────────────────────────────┐
│ 状态      GROUND_APPROACH                  │
│ 说明      地面车前往目标                    │
│ 目标距离  8.4 m                            │
│ 观测年龄  0.12 s                           │
│ 空中控制  lqr_tracker_node                 │
│ 地面控制  ground_commander                 │
│ 已用时    01:20                            │
└────────────────────────────────────────────┘
```

数据全部来自 `/agc/task/state`，**不新增话题、不改消息**（[#messages](../../ROS2迁移交接文档.md#messages) 字段与顺序不得变更）。

**刷新率**：2 Hz 足够（人眼可读，不刷屏）。用 `\r` 原地刷新或简单重绘，避免日志洪水。

### 3. 事件时间线（关键节点打点）

状态是"当前快照"，观众还需要"发生了什么"。建议在演示目录落一份**人类可读的事件流**：

```text
[00:00.0] 系统启动
[00:03.2] 进入 AIR_SEARCH
[00:12.7] 发现目标 TARGET_ACQUIRED（置信度 0.82）
[00:13.0] 进入 GROUND_APPROACH
[00:15.3] 安全层介入 1 次（障碍规避）
[01:12.4] 终态 TRACKING_SUCCESS（目标距离 4.1 m，持续 3.0 s）
[01:12.5] 结果落盘 metrics/summary.json
```

**实现方式**：演示脚本订阅 `/agc/task/state`，**状态跳变时**记一行；同时读 `run_logger` 的 `summary.json` 补终态细节。**不要**自己算指标——指标真源是 `run_logger`。

> 落点：`experiments/demo/<timestamp>/timeline.txt`。这是**人读**的，不替代机器可读的 `summary.json`。

### 4. 轻量可视化（Gazebo 标注，可选但推荐）

Gazebo 里能加**视觉标注**，成本低、效果直接：

| 标注 | 做法 | 价值 |
|---|---|---|
| 目标高亮 | 给 `intruder_uav` 加醒目的 visual（如橙色） | 观众一眼看到"目标" |
| 车体朝向 | 已有 mesh，无需改 | — |
| 轨迹线 | 用 GZ `Trajectory`/marker 或外部发布 | 展示"走了哪条路" |
| 状态文字 | RViz 的 `Marker` / `OverlayText` | 屏幕上直接显示状态 |

**优先级**：目标高亮 > 轨迹 > 状态文字。

> **注意**：这些是**纯视觉**改动，**不得**改碰撞、质量、动力学（否则影响已验收的物理行为与证据）。给 `intruder_uav` 加颜色只改 `<visual>` 的 material。

### 5. 终态解释（"为什么成功/失败"）

`summary.json` 里有指标但没解释。演示时需要在结尾打印一段**判定说明**：

```text
结果：TRACKING_SUCCESS
依据：目标距离持续 ≤ 阈值 3.0 s（要求 ≥ 2.0 s），观测新鲜度全程 ≥ 0.5
用时：72.4 s
安全：安全层介入 1 次，无不可行规避（shield_infeasible_rate = 0.0）
复位：0 次失败（reset_failure_rate = 0.0）
```

**数据来源**必须是 `summary.json` 的现有字段（[run_logger.cpp](../../../src/agc_task/src/run_logger.cpp) 已产出，含 C9 要求的 `shield_infeasible_rate` / `reset_failure_rate`）。若字段不够，**先查是否已有**，不要急着加消息。

> 判定阈值应引用配置（`task_manager` 的跟踪判据），**不要在展示层硬编码**——否则改了配置解释就错。

### 目标视觉可辨识（round-2 达成）

**要求**：演示实际使用的目标在 Gazebo 里颜色或尺寸至少一项醒目。**round-1 未达成**
（当时只查了被动版与 RViz marker，漏看演示真正用的可控版），round-2 补齐。

| 路径 | round-1 现状 | round-2 现状 |
|---|---|---|
| `intruder_uav` **被动版**（`controlled:=false`） | 纯红方块（`<diffuse>1 0 0 1</diffuse>`） | **原样未动**（M0/W5 路径不回退） |
| `intruder_uav` **可控版**（`controlled:=true`，**演示实际使用**） | merge `model://x500`，白机身 + 碳纤维臂，**无醒目属性** | **新增 `target_highlight`**：1.2 m 半透明橙色自发光球 + fixed joint |
| `viz_markers` 的 RViz 目标球 | 1.2 m 暖黄 `SPHERE`（仅 GUI） | 不变（现在是**第二重**标注，不再承担唯一职责） |

**为什么不是"往 `base_link` 里加一个 visual"**（2026-10-30 用本机 `gz sdf -p` 实测四种写法）：

| 写法 | 实测结果 |
|---|---|
| `<include merge="true">` 里塞 `<link>` | **静默丢弃**（展开后高亮不存在，只留一条 not-defined 警告） |
| include 之后再写 `<link name="base_link">` | **硬失败** `Error Code 2: link with name[base_link] already exists` |
| 新增独立 link，**无** joint | 解析通过，但悬空 link 的物理归属不明确 |
| **新增独立 link + fixed joint**（采用） | 解析通过；`base_link` 等原有 link 逐字节不变 |

前两种不可行是因为 `<include merge="true">` 的子元素**只**允许
`uri/pose/plugin/name/static/placement_frame`（sdformat14 `model.sdf` spec），且 merge **不按名字合并 link**。
"独立 link + fixed joint"也正是本仓 `agc_car` 的既有装饰写法（`car/capture_net` / `car/jammer`），不是新范式。

**物理零影响**（由 `scripts/tests/test_intruder_visual_highlight.py` 逐项锁死，10 用例）：

- 展开式里**剥掉高亮元素后与改动前逐字节一致** —— 任何"顺手"改 collision / inertial / pose /
  plugin / 关节都会在这里暴露；
- 高亮 link **无 `<collision>`** → 不参与接触、测距与物理求解（`collision_count` 仍为 9，与基线相同）；
- 质量 `1e-6 kg`（**非 0**：dartsim 对零质量 body 行为未定义），挂 fixed joint，不改变 x500 动力学量级；
- 不改 plugin / 话题 / pose / 关节，PX4 attach 的模型名仍是 `intruder_uav`；
- **反向对照实证**：故意注入 `<collision>` → 3 条用例变红；把质量改成 5 kg → 2 条变红（守卫不是摆设）。

**两次真实运行**（`yard/s04/full/observe_yaw_mode=target`，均 `TRACKING_SUCCESS`）：

| attempt | 形态 | 目标视觉属性来自 | 结果 |
|---|---|---|---|
| `b1` | headless（`viz:=false`，无 rviz2 / viz_markers 进程） | **模型本身** —— 证明不依赖 RViz | `TRACKING_SUCCESS`，C9 两指标 0 |
| `b2` | GUI（`viz:=true`，rviz2 / viz_markers 各 1，GUI 四类证据齐） | 模型本身 **+** RViz 球（双重标注） | `TRACKING_SUCCESS`，C9 两指标 0 |

证据：`experiments/p1-3/round-2/evidence/`（`target-highlight.json` 为机器可读的几何/颜色采样；
`model-controlled.expanded.sdf` 从 **install 路径**展开，与 launch 实际使用的文件是同一份 symlink 目标）。

> **口径诚实性**：本项的证据链是"模型展开 + 颜色采样 + 两次真实 run 加载同一文件 + GUI 渲染器正常工作"，
> **不是**"从 GUI 截图中数出橙色像素"。本机无可用截屏工具（`xwd`/`import`/`ffmpeg`/`scrot` 全缺，
> 与 P1-1 round-6 的结论一致），故不宣称有像素级截图证据。

## 风险与注意

- **最容易犯的错**：在展示层自己算"成功率""拦截率"。**禁止**——指标真源是 `run_logger`，展示层只读不造。
- **C8 表述红线**：`TRACKING_SUCCESS` 是"抵近并持续跟踪"，不是"拦截完成"。演示稿、README、幻灯片都要守住。
- 状态面板不要刷屏：2 Hz + 原地刷新；日志文件里只记**跳变**。
- 若给目标加颜色，确认**不影响** `gt_bypass` 的实体名匹配（按名字找，颜色无关，但改模型要重跑一次核查）。
- 终端面板在 `--headless` 下也应可用（服务器演示场景）。
- 不要把面板做成"必须开 GUI 才有"——那是把可观测性绑死在渲染上。

## 非目标

- 不做 Web 控制台 / 前端框架（未来另议）。
- 不做多机 / 多任务并行展示。
- 不改状态机逻辑、不改终态判据。
- 不新增消息字段（若确实缺字段，先立 ADR，不在本项偷偷加）。
