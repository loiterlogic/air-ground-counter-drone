# P0-5 · 协作成本治理（批次授权与熔断）

> 索引：[项目完成路线](README.md#plan-index)。前置：无（可与 [P0-2](p0-2-暂停迁移与基线固定.md#p0-2-goal) 并行）。
> 决策记录：[ADR-0104](../adr/0104-batch-authorization-and-stall-circuit-breaker.md)。

## 为什么做

用户 2026-10-29 反馈：**"leader 的 tokens 消耗负担不起，worker 的消耗再多我也无所谓，主要是 worker 权限和自由度太低"**。

实测证据（W8 任务 `20261027-001-w8-validation-recovery`，已归档）：

| 项 | 值 | 问题 |
|---|---|---|
| 轮次 | 24 | 每轮必唤醒 Leader |
| Leader `cacheRead` | ≈530 万 | 每次唤醒约 22 万 |
| 空转轮次 | 6（第 19–24） | 同一根因无突破 |
| 产出 | 关闭（非验收） | 25% 成本零产出 |

**结论：贵的是唤醒次数，不是审查篇幅；空转的根因是 Worker 权限太窄 + 无熔断。**

## 参数

| 参数 | 值 | 含义 |
|---|---|---|
| **N** | 6 | 单次授权连续自主推进最大轮数 |
| **K** | 4 | 连续无区分性新证据触发熔断的轮数 |

## 要做什么（验证与调参）

规则改了不等于生效。需在**下一个真实任务**上验证：

1. **首次批次任务观察**：记录实际唤醒次数、批次内轮数、是否触发熔断、返工成本。
2. **对比基线**：与 W8 的 24 轮/530 万 `cacheRead` 对比，确认降幅达 75% 以上。
3. **调参判断**：
   - 若批次末常发现"方向全错、返工成本 > 省下的唤醒"，**下调 N**（如 4）或加密里程碑检查点；
   - 若熔断频繁误伤（确有进展但被判无进展），**上调 K** 或明确"区分性新证据"判据；
   - **不得**因调参取消熔断或独立验收。

## 出口判据

- [ ] 至少 1 个真实任务按批次授权跑完，记录唤醒次数与总轮数
- [ ] Leader `cacheRead` 相对 24 轮基线降幅 ≥ 75%
- [ ] 熔断机制至少被验证一次（真实触发或明确未触发的判据说明）
- [ ] 无因批次授权导致的硬约束违规或验收降级
- [ ] 调参结论回填本文件（N/K 是否维持 6/4）

## 风险与注意

- **最大风险**：Worker 跑偏后一次性返工，省下的唤醒成本被返工吃掉。护栏是 K=4 熔断 + 预登记停止条件 + 证据留痕。
- **"区分性新证据"主观**：Worker 可能自我豁免。Leader 审查时须**明确裁定**，不接受"又做了一次但没结论"算新证据。
- **不要为省 token 砍验收**：独立验收是质量底线，只改频率不改标准。
- **T2 闸门不变**：全链仿真/GUI/构建仍逐轮派发，批次授权**不**放宽真实实验授权。

## 非目标

- 不改 Worker 模型质量或路由（用户明确 Worker 消耗非瓶颈）。
- 不取消单任务链或一个任务一个 Worker。
- 不恢复已退役的跨进程叫醒机制。
