# P0-3 · 文档瘦身与入口重构

> 索引：[项目完成路线](README.md#plan-index)。前置：[P0-2](p0-2-暂停迁移与基线固定.md#p0-2-goal)（基线已固定）。
> 下游：[P0-4](p0-4-脚本系统瘦身.md#p0-4-goal)。
> 真源分层依据：[ADR-0002](../adr/0002-docs-source-of-truth-layering.md)、[目录与命名规范](../conventions/目录与命名规范.md#10-产物分类与生命周期)。

## 为什么做

用户原话：**"当前文档略显臃肿，agent 每次对话疯狂读取，既占用太多上下文又麻烦。"**

这不是感觉，是可量的：

| 项 | 实测 | 问题 |
|---|---|---|
| 每次开工必读 | AGENTS 30 + GLOSSARY 85 + 契约 157 + Runbook 347 = **619 行** | 还没算 workstream 三件套 |
| 契约文档 | 157 行，其中**附录 A（ROS1 基线盘点，47 行）** 是历史，不是约束 | 历史混在真源里 |
| Runbook | **347 行**，W0–W8 全历史 + 每轮补充 | 已是编年史，不是"现在做什么" |
| ADR | **102 篇**、约 1.0 MB，**无索引** | Agent 只能 grep，命中率低 |
| specs | **32 目录 / 96 文件**，含 `w0-repo-and-conventions` **1.9 MB** | 绝大多数已结档 |
| 协作轮次 | `.coordination/task/` **71 个 md** | 当前任务已归档后即为历史 |

**核心矛盾**：入口文档承担了"编年史"职责。每次开工必须从头读一遍历史，才能知道现在该干什么。

**目标不是删内容，是分层**：让"每次必读"只含**当前方向 + 红线**，历史按主题可查、默认不读。

## 要做什么

### 1. 确定"三层阅读模型"

| 层 | 什么时候读 | 内容 | 体量目标 |
|---|---|---|---|
| **L1 必读** | 每次会话 | [AGENTS.md](../../AGENTS.md)（索引+红线）+ [项目完成路线](README.md#plan-index)（当前方向） | ≤ 200 行 |
| **L2 按任务读** | 执行具体任务时 | 对应 plan 文件、对应包 README、[conventions](../conventions/目录与命名规范.md) | 单文件 ≤ 150 行 |
| **L3 按需查** | 遇到约束/历史问题时 | [契约真源](../ROS2迁移交接文档.md#namespace)、ADR 索引、归档 Runbook | 不预读 |

> **判据**：L1 体量从当前 619 行降到 ≤ 200 行（降幅 ≥ 60%），且**不丢失任何红线**。

### 2. 拆分契约文档（保留约束，移走历史）

[ROS2迁移交接文档](../ROS2迁移交接文档.md#namespace) 是**契约真源**，不能整体归档。但需拆成：

| 内容 | 去向 | 理由 |
|---|---|---|
| §1 命名空间与坐标系、§2 唯一执行口、§3 参数入口、§4 任务门控、§5 消息、§6 硬约束、§7 终态语义、§8 不可回退教训、§9 已决事项表 | **留在原文件** | 这些是活约束 |
| 附录 A（ROS1 基线盘点：包清单/节点清单/启动编排） | 移入 `docs/archive/ros1-baseline.md` | 纯历史，W8 才用；且 `reference/` 仍在，可随时查 |
| 已决事项表中**已失效**的条目（如 W7/W8 相关行） | 标注 `（历史）` 并移入归档索引 | 避免误导当前决策 |

**注意**：拆分**不得**改变任何锚点 ID（`#hard-constraints` 等），否则全仓引用断裂。附录 A 的锚点 `#appendix-a` 改为归档文件内的锚点，并在原文件留一行指向归档文件的说明。

### 3. Runbook 归档 + 新建"当前方向"入口

[ROS2迁移步骤](../archive/ROS2迁移步骤.md#usage)（347 行）是 W0–W8 的编排史。

- 整体移入 `docs/archive/ROS2迁移步骤.md`，文件头加 `> 历史归档（2026-10-29 起）。迁移已暂停，本文不再作为执行入口。`
- 在归档文件顶部保留一句话指引："当前方向见 [项目完成路线](README.md#plan-index)"。
- **不**在原路径留转发文件（避免 Agent 仍读到 347 行）；改为在 AGENTS.md 与 plan 索引中指向归档路径。

> **关键**：AGENTS.md 的"开工顺序"必须同时改，否则 Agent 仍会按老路径读。

### 4. specs 与协作轮次归档

> **2026-10-29 用户裁定修订**：Trae 退役，规格**整体迁出**到 `docs/archive/specs/`（不再留在 `.trae/` 内做 `_archive/`），并保持不发布（[ADR-0105](../adr/0105-retire-trae-and-relocate-specs-skills.md)）。下表为原计划，右侧"实际处置"为本轮落地结果。

| 目录 | 现状 | 实际处置 |
|---|---|---|
| 原 `.trae/specs/` | 32 目录 / 97 文件 | **整体迁入** [`docs/archive/specs/`](../archive/specs/README.md#specs-index)，逐文件 sha256 一致；索引 `README.md` + 迁移清单 `MIGRATION.md`；`.gitignore` 精确忽略，仍不发布 |
| `.coordination/task/` | 71 md | 历史轮次已在 `.coordination/archive/`；`task/` 保留**唯一当前任务链**（协议规定，验收后由 Leader 归档） |
| `.coordination/roles/`、`README.md` | 20K | **保留**（协作机制仍需，虽暂停） |

> `.trae/` 原在 `.gitignore`（公开仓库不发布）；迁移后规格的忽略规则改为精确的 `/docs/archive/specs/`，据此**归档不改变发布边界**，只改变 Agent 的读取范围与路径。

### 5. ADR 建索引（不删不改）

102 篇 ADR 按 [目录与命名规范](../conventions/目录与命名规范.md#10-产物分类与生命周期) 是"只追加、不重写历史"，**不删除**。但需要索引：

新建 `docs/adr/README.md`，表列 `编号 | 标题 | Status | 一句话结论 | 是否仍生效`。

**实现方式**：写 `scripts/adr_index.py` 从每篇 ADR 的 `# 标题` 与 `## Status` 自动生成，避免手工维护漂移；生成结果入库，脚本可随时重跑校验（CI 式：`--check` 模式，索引与 ADR 不一致则退出码非 0）。

> 这样 Agent 查历史时先读索引（约 102 行表），只打开命中的 1–2 篇，而不是 grep 全目录。

### 6. GLOSSARY 瘦身（小幅）

[GLOSSARY](../../GLOSSARY.md) 85 行，多数仍有效。只处理两类：

- **W8/研究专用术语**（如 `oracle 目标臂`、`有效火控机会`）→ 保留但标注"研究期术语，当前阶段非必读"；
- **已退役机制术语**（如 `Runbook` 定义）→ 改写为"历史：迁移期入口，已归档"。

**不改**术语定义本身（它们是契约与代码的共同语言）。

### 7. 重写 AGENTS.md（最终形态）

目标 ≤ 40 行，只含：

1. **这是什么项目**（2 行）
2. **现在做什么**（指向 plan 索引，1 行）
3. **开工顺序**（L1 两条，2 行）
4. **铁律**（保留全部红线，约 8 行——红线**一条都不能删**）
5. **按需查**（契约 / ADR 索引 / 归档，3 行）

> **红线校验**：改写后必须逐条对照原 AGENTS.md 的 7 条铁律，确认全部保留（项目根、真源分层、引用纪律、只读旧树、先学后做、红线即停、未决不静默）。少一条即视为失败。

## 建议的核对脚本

新增 `tests/docs_link_check.py`（退出码语义，符合 [目录与命名规范](../conventions/目录与命名规范.md#10-产物分类与生命周期) 的 `tests/` 归属）：

1. 扫描 `docs/**/*.md`、`AGENTS.md`、`GLOSSARY.md`、`src/**/README.md` 中的 markdown 链接（形如 `[文字](相对路径#锚点)`）；
2. 解析相对路径，确认文件存在、锚点 `<a id="…">` 或标题 slug 存在；
3. 报告断链清单，非空则退出码 1。

> 这个脚本是 P0-3 的**验收工具**，也是后续所有文档改动的护栏。

## 风险与注意

- **最大风险**：拆分契约文档时改坏锚点 → 全仓引用断裂。必须**先跑断链检查，再改**，改完再跑一次对比。
- 归档 ≠ 删除。所有移动用 `git mv` 保留历史，禁止 `rm`。
- 不要归档 [docs/conventions/](../conventions/目录与命名规范.md)——工程规范仍活。
- 不要动 [docs/reviews/](../reviews/agc-review-2026-10-25/W8测量规格裁定.md)——它是结论证据，按规范入库保留。
- 归档后 Agent 若仍读到旧路径，说明有索引没改；用 `grep -rn "ROS2迁移步骤"` 全仓核对引用点。

## 非目标

- 不删除任何 ADR、评审快照、实验产物。
- 不重写历史文档内容（只加归档头 + 改路径引用）。
- 不做"文档网站化"（Sphinx/MkDocs）——本阶段不增加构建依赖。
