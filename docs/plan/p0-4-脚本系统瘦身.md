# P0-4 · 脚本系统瘦身

## 为什么做

用户原话：**"脚本系统同样。"**（指臃肿、每次读太多）

实测现状：`scripts/` 顶层有 **32 个**（31 个 `.py` + 1 个 `.sh`），但 [scripts/README](../../scripts/README.md) 只登记了 **8 个长期工具**。

也就是说：**24 个脚本处于"无索引、无归属、无人认领"状态**。它们既不是明确的长期工具，也没进 `archive/`。

典型问题：

- `w7b_*.py` **14 个**、`w7c_*.py` **2 个**、`w8_*.py` **4 个** —— 全是研究期一次性探针/判定脚本，却和长期工具混在一起；
- Agent 每次 `ls scripts/` 会看到 32 个文件名，无法判断该用哪个；
- 新加"一键演示入口"时，会进一步加剧混乱。

**目标：`scripts/` 顶层回到"一眼能看懂"的规模，且索引与实际**永远一致**。**

## 目标结构

```text
scripts/
├── README.md                  # 索引：顶层工具表 + 子目录指引 + 自动核对说明
├── <8 个长期工具>.py/.sh       # 顶层只放"当前阶段会用"的
├── research/                  # 研究期工具（当前阶段不用，但保留）
│   ├── README.md              # 单列 16 个 + 一句话用途
│   └── w7b_*.py / w7c_*.py / w7_*.py / uxrce_*.py
├── tests/                     # 脚本自身单测（已存在，保留）
└── archive/                   # 一次性（已存在，继续接收）
```

**顶层目标 ≤ 12 个**（8 长期工具 + 未来新增 ≤ 4 个）。

> **为什么建 `research/` 而不是全塞 `archive/`**：`archive/` 语义是"证据归档后不再改动，保留供复核"，而这些脚本**仍可能被复跑**（研究虽暂停，未废弃）。混入 archive 会稀释 archive 的"冻结"语义。

## 要做什么

1. **建 `scripts/research/`**，`git mv` 移入 B 类 16 个（+ D 类按判定结果）。
2. **移入 archive** C 类 4 个（先 grep `experiments/` 确认无引用）。
3. **重写 [scripts/README](../../scripts/README.md)**：
   - 顶层表只列 8 个；
   - 加 `research/` 一节（表列 16 个 + 用途 + 为何不在顶层）；
   - 保留"新增脚本前先问一句"的规则，**加一条**：`research/` 用于"暂停但未废弃"的研究工具。
4. **修引用**：`grep -rln "scripts/w7b_\|scripts/w7c_\|scripts/w8_\|scripts/uxrce_"` 找出所有引用点（tests / docs / .trae / experiments 中的命令串），改路径。**注意**：历史 ADR / 归档文档中的旧路径**不改**（[目录与命名规范](../conventions/目录与命名规范.md#10-产物分类与生命周期) 说明 ADR 只追加不重写）；只在文件头加一行"路径已迁移，现位于 `scripts/research/`"。
5. **加自动核对**：扩展或新增 `scripts/tests/test_scripts_index.py`（pytest）：
   - 断言 `scripts/*.py|sh` 顶层文件集合 == README 顶层表所列集合；
   - 断言 `scripts/research/*` 与 research README 表一致；
   - 不一致则失败，并打印差异。

> 这是**防止再腐化**的关键：索引漂移是本次问题的根因，靠纪律不如靠测试。

## 出口判据

- [ ] `scripts/` 顶层文件数 ≤ 12
- [ ] 顶层每个脚本都在 [scripts/README](../../scripts/README.md) 表中出现，反之亦然（自动核对通过）
- [ ] `scripts/research/README.md` 存在且列全
- [ ] 活跃引用（非历史归档文档）全部指向新路径
- [ ] 新增的索引核对测试通过
- [ ] 所有移动用 `git mv`，`git log --follow` 可追溯

## 风险与注意

- **不要**删任何脚本——研究虽暂停，脚本是证据链一部分。
- 移动后 `python3 scripts/w7b_xxx.py` 的**相对导入**可能失效：检查每个脚本是否有 `sys.path` 或相对路径假设（如 `Path(__file__).parent.parent`），移入子目录后需 +1 层。
- `tests/` 下的核查脚本**不在此范围**（它们按 [规范](../conventions/目录与命名规范.md#10-产物分类与生命周期) 属验收核查，57 个虽多但语义正确）；若后续要瘦身，另立条目。
- 历史文档中的旧路径**保留**，只加迁移说明，避免改写历史。

## 非目标

- 不重构 `tests/` 的 57 个核查（另议）。
- 不合并脚本功能（先归位，再谈合并）。
- 不动 `scripts/archive/` 已有内容。
