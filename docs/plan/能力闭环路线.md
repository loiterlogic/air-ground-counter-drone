# 能力闭环路线（候选）

> 状态：**候选计划，未开工**。2026-10-31 根据同类项目对照与用户补充记录。
> 本文件只定义后续顺序、范围与验收；约束仍只引用[契约真源](../ROS2迁移交接文档.md#hard-constraints)。

## 总判断

现有工程演示已可复现，下一阶段不再以地图、文档或展示增量为主，优先补上
**真实图像 → 检测 → 三维目标估计 → 空地任务决策**的能力断点。
顺序为：

```text
H0 目标高度语义与基准标定 → N1 视觉驱动最小闭环 → N2 动态与失效恢复回归 → N3 持续验证
```

一次只推进一个任务链；本路线不恢复迁移、W8 或论文批量实验。

## 最新裁定（2026-10-31，用户补充 · 冲突处以本节为准）

> **优先级声明**：本节是 2026-10-31 用户对**空地数据流、地面规划与局部避障**的最新裁定，**晚于本文件其余段落**。
> 凡本节与本文其它段落（尤其 [N1](#n1-vision) 段）的现有表述冲突处，**以本节为准**。
> 为保留决策痕迹，**本轮不改写任何既有段落**；冲突段落由后续执行任务在改动落地时**同步回改**（每条附"执行时须回改"清单）。
> 本节只记**裁定 + 待改清单**，不复述约束；约束仍只引用[契约真源](../ROS2迁移交接文档.md#hard-constraints)。

### R1 · 全局路径规划器：先占位跑通，后续接入外部独立节点

- **终局裁定**：全局路径规划**最终由外部独立节点提供**——对方交付形态是**独立 ROS 节点**（**不是**本仓内部实现、**不是** Nav2 插件）。本仓须**预留可替换接入缝**，使该节点到货后能在**不改任务层、不改 9 消息 ABI、不改唯一执行口**的前提下接入（替换口径参照[捕获裁决器替换契约](../adr/0058-capture-adjudicator-replacement-contract-and-event-semantics.md)："对外零破坏、内部允许演进"）。
- **阶段口径**：**现在先用简单占位规划顶着位置跑通链路**（几何 / 直连占位，只要能到目标位置即可，**不追求路径质量与最优性**），先把"规划器 → 路径 → 小车"这段接口跑成，再等外部算法替换。
- **可复用既有资产（供任务选型，非强制）**：既有 `ground_baseline`（Navfn 插件 + LQR）本身已是"全局规划 + 路径跟随"的可运行实现，**可作占位**，但须先补上"**路径外发并被局部策略消费**"这条缝（现其 `/agc/ground/path` 只发不收）与 `command_source` 的互斥关系。
- **现状事实（须如实）**：这个"缝"**今天不存在**。仓内唯一有全局路径的是[离线对照基线](../adr/0004-rl-primary-controller-nav2-safety-layer.md#L7) `ground_baseline`（Nav2 `navfn` 插件 + `agc_control` LQR 跟随 + 自持 costmap，插件名见 [baseline.yaml:24](../../src/agc_ground/config/baseline.yaml#L24)），其 `/agc/ground/path` **只发不收**（无任何控制消费者，仅 RViz / bench 脚本 / 测试旁观，见 [ground_baseline.cpp:125](../../src/agc_ground/src/ground_baseline.cpp#L125)）；默认 `command_source=rl` 下**不起 costmap、不起任何规划器**（[costmap.yaml:5-6](../../src/agc_ground/config/costmap.yaml#L5-L6)），[agc_rl 推理节点](../../src/agc_rl/agc_rl/inference_node.py#L110-L114)直接出 `cmd_vel_raw`。
- **待确认项（外部节点形态，确认后写入契约）**：① 消费的世界表示（今天规划可用的只有 `z≈0.48 m` 单平面激光 + `/agc/map` 三态栅格）；② 输出路径的消息类型与坐标系（预期 `nav_msgs/Path`、`frame_id=world`）；③ 重规划触发语义（对齐 [ADR-0056](../adr/0056-goal-invalidation-policy-and-displacement-triggered-replan.md) 与 [ADR-0027](../adr/0027-baseline-path-binding-and-replan-failstop.md) 的既有口径）；④ **路径失效 / 规划失败时的 fail-stop 行为**。
- **执行时须回改**：`docs/adr/`（**新增**"全局规划器替换契约"ADR）；[契约 #params](../ROS2迁移交接文档.md#params)（若新增参数入口）；本节 [N1 第 4 条](#n1-vision)（现文"不同时更换规划器"须重写）；[ground_bringup.launch.py](../../src/agc_ground/launch/ground_bringup.launch.py#L117-L157) 的命令源分支与其注释。

### R2 · 无人机识别"地面障碍物分布"：先真值仿生，后换真视觉

- **裁定**：视觉算法到货前**继续用真值仿生**（沿用[真值派生感知](../adr/0020-perception-as-truth-derived-simulation.md)口径）；到货后再换**真视觉算法**。
- **现状**：地面障碍地图的静态先验来自配置 `obstacles_file`（[map_adapter.cpp:141-144](../../src/agc_perception/src/map_adapter.cpp#L141-L144)），空中障碍观测同样来自配置 YAML + 几何遮挡判定（[air_perception.cpp:259-285](../../src/agc_perception/src/air_perception.cpp#L259-L285)）——即"真值仿生"**已是现状**，本阶段无需新建。
- **边界（不得混淆）**：[N1 极简检测器](#n1-vision)只做**橙色高亮目标**，**不是**障碍物识别；"障碍物分布的真视觉化"是**另一条后端需求**，不得用目标检测器冒充其成果。视觉路径须遵守 [#perception-path](../ROS2迁移交接文档.md#perception-path) 的**互斥 + 无模型显式降级**，不得静默回退真值。
- **执行时须回改**：[N1 极简检测器](#n1-vision)段（显式区分"目标检测桩"与"障碍物视觉"两类后端）；后续视觉任务的范围声明；产物 `perception_path` / 模型标识记录。

### R3 · 空地数据流：空中只给"处理后的数据"，**地面自己规划全局路径**

- **澄清裁定**：此前"规划算法把路径生成给小车"的说法，实指——**空中只把视觉处理后的数据（障碍物分布 / 全局 map）交给地面，全局路径由地面车自己规划**。据此，[ADR-0017](../adr/0017-air-ground-collaboration-loop.md#L16) 对"把规划抬到空中"的**否决继续有效**，数据流沿用其"UAV 感知 → 融合 → 全局 map → 地面规划消费"骨架（`/agc/map`）。
- **与 R1 的关系（须同时成立的读法）**：R3 定"规划器住在**地面**侧"；R1 定"地面侧那个规划器**将来由外部独立节点实现**、现在先用占位"。二者**不矛盾**——**"小车自己规划" = 今天的占位实现；"外部独立节点" = 后续替换目标**。
- **执行时须回改**：[N1 三维与决策链接通](#n1-vision) 第 4 条（现文"实际是确定性 go-to-goal 速度控制…**不是 NavFn 全局路径规划**；本项不同时更换规划器"须按 R1/R3 重写）；[GLOSSARY](../../GLOSSARY.md#L53) 的`协同感知`（"地面自主规划"表述与新增"全局规划 / 局部避障"区分的对齐）。

### R4 · 局部精确避障：**要做**，且由强化学习实现（用户本人负责）

- **裁定**：局部避障**不是只靠安全层兜底**，要作为**独立能力**实现，**实现手段 = 强化学习**，属**用户本人负责范围**；载体预期为 [agc_rl](../../src/agc_rl/agc_rl/inference_node.py#L1-L17) 在线策略（[ADR-0004](../adr/0004-rl-primary-controller-nav2-safety-layer.md#L7) 的"RL 地面主控"地位**不变**）。
- **架构后果（必须显式，不得静默）**：现状 RL 策略只订 `/agc/ground/odom` / `scan` / `goal` / `state` 并**直接出 `cmd_vel_raw`**，**没有路径输入**。要实现"跟踪全局路径 + 局部避障"，须**新增"路径 → 局部策略"输入缝**：全局规划器（占位 → 外部节点）→ 路径 → RL 局部策略 → `cmd_vel_raw` → `collision_monitor`（安全层，**仍是最后屏障，但不等于局部避障**）→ 唯一执行口。
- **边界（不得夸大）**：现有 `collision_monitor` 是**按速度多边形的减速 / 急停屏障**，不是绕障规划；其感知为 `z≈0.48 m` 单水平面，低障碍 / 悬空结构**不可见**、薄障碍受 `min_points=2` 限制（[ground.yaml:40-51](../../src/agc_ground/config/ground.yaml#L40-L51)、[ADR-0052](../adr/0052-sensor-and-vehicle-model-limitation-and-capability-calibration.md)）。RL 局部避障落地后，仍须**如实登记**它相对该可见性族的边界，**不得**写成通用避障保证。
- **执行时须回改**：[ADR-0004](../adr/0004-rl-primary-controller-nav2-safety-layer.md#L7)（策略输入由"goal"扩展为"路径 + goal"）；[ADR-0060](../adr/0060-nav2-absorption-applicability-and-command-source-trimming.md)（"`command_source=rl` 不消费 costmap"是否仍成立）；[rl.yaml](../../src/agc_rl/config/rl.yaml#L13) 与 [ground.yaml:233-235](../../src/agc_ground/config/ground.yaml#L233-L235) 的链路注释；[GLOSSARY](../../GLOSSARY.md)（**新增**"局部避障 vs 安全层"条目）；F2 架构图资产（[system-structure.svg](assets/system-structure.svg) / [system-structure-detail.svg](assets/system-structure-detail.svg)）。

## H0 · 目标高度语义与基准标定（N1 前置）

### 已确认

- 用户明确指出：现有目标出生高度 **2 m 是早期为跑通而设，不代表合理任务高度，后续不得继续当作能力设计依据**。
- 代码现状有两个不同的高度量，不得混为一谈：
  - 出生/复位 `target.z=2.0`：[spawn_layout.yaml](../../src/agc_task/config/spawn_layout.yaml#L56-L60)；
  - 入侵者驱动相对回合原点的上升量 `alt_m=2.0`：[intruder_driver.py:197–207](../../src/agc_task/scripts/intruder_driver.py#L197-L207)。
- 因此不能只改出生值；须同时核对出生、复位、爬升参考与任务巡航高度，避免重复叠加。

### 推荐策略（待用户确认）

**由场景给定高度，目标控制层执行；不让目标在 N1 自主随机选高。**

- “固定”不是所有场景共用一个拍脑袋常数，而是**每个场景显式给出可复现的巡航高度**，并写入 run manifest。
- H0/N1：静态与线性基准采用场景固定巡航高度，先减少自变量。
- N2：可增加**预注册的脚本化高度剖面**（爬升、下降、分段保持），仍由场景和 seed 决定。
- 后续若研究自主逃逸，可让目标在预注册高度剖面间作有限选择；决策依据、随机源与日志必须显式，不得读取防守方真值形成隐藏 oracle。
- 具体高度数值不在本计划预设：由传感器量程/视场、己方跟踪安全、地图净空和地面载荷包络共同标定；任一既有能力因此不可达，必须如实报告，不得靠放大旧包络掩盖。

### H0 出口

1. 出生高度、相对爬升量、任务巡航高度语义只有一个有效来源，世界 spawn、复位与驱动不再歧义叠加。
2. 主场景与目标运动场景使用显式高度配置，产物能还原实际生效高度。
3. 己方起飞、standoff 跟踪、相机观测与地面载荷影响逐项核查；主场景 GUI 整链重新验收。
4. 不引入自主逃逸决策，不扩地图，不改[硬约束](../ROS2迁移交接文档.md#hard-constraints)。

<a id="n1-vision"></a>
## N1 · 视觉驱动最小闭环

### 目标

在一个高度语义已明确的基准场景中，使真实图像产生的目标航迹实际进入任务决策；
真值只用于评估，不得静默参与视觉路径。路径口径引用[感知路径契约](../ROS2迁移交接文档.md#perception-path)。

### 极简检测器（用户已确认的实施约束）

检测器只是**链路桩**，不是本批算法任务：

- 复用目标现有的[橙色高亮几何](../../src/agc_sim/models/intruder_uav/intruder_uav.sdf.xacro#L86-L107)，只做**颜色阈值掩膜 → 有效像素外接框**。
- 优先使用现有 NumPy/PIL 能力；不引入 OpenCV、训练框架、模型权重或新运行时。
- 不训练、不建数据集、不做多目标关联、不做 DeepSORT/KF、不做参数搜索，不为提高效果不断升级算法。
- 建议将实现与合成图单测限制在 **0.5 个工作日**；超时即停止并交回，不以增加复杂度续命。
- 后端显式命名为 `synthetic_color`；输出分数只是链路启发值，不宣称经过校准的识别置信度。
- 该后端只证明仿真高亮目标下的链路，**不得作为真实无人机识别能力或论文算法成果**。

### 三维与决策链接通

1. 先按 H0 的高度语义选定估计方案；只有固定巡航高度的基准臂才可使用显式高度平面先验，并须标注适用域。
2. 打通 `Detection2D → 相对三维定位/航迹 → /agc/targets`；视觉路径不得保留隐式真值决策旁路。
3. 真值仅用于离线计算检测与三维误差；不改变既有 9 消息 ABI 和唯一执行口。
4. 地面控制器在 N1 保持现状：默认 `command_source=rl` 实际是确定性 go-to-goal 速度控制加 Nav2 安全层，**不是 NavFn 全局路径规划**；本项不同时更换规划器。
5. 地面验收必须让 `/agc/ground/goal` 实际来自视觉航迹。固定目标的 `s04` 不跟随 `/agc/targets`，只能验证固定点控制；须用显式 `goal_follow_target:=true` 的视觉验收臂或等价明确场景，才能声称视觉驱动地面路径。

### N1 出口

- 一个真实图像后端实际驱动主场景任务；运行图能证明决策未消费真值。
- 记录检测率、无目标误检、三维误差 p50/p95、图像到航迹延迟，以及同 seed 的 `truth` / `vision` 终态和安全指标。
- 无目标负例不得产生虚假目标并导向成功；关键场景按契约留 GUI 证据。
- 单次语义未跑正确前，不扩 seed、不做论文统计。

<a id="n2-dynamic"></a>
## N2 · 动态目标与失效恢复回归

- 使用现有直线/机动场景，逐步加入出视场、遮挡、检测丢失、重捕获和无目标负例。
- 形成小矩阵：静态正常、动态正常、丢失重捕获、无目标；复用现有地图。
- 分开记录 `lightweight/full`、GUI/headless 与感知路径，不跨保真度混读指标。
- 工程对照 `truth vs vision` 只回答感知代价；未来若恢复研究，协同收益须另做同信息预算的协同/非协同对照。

<a id="n3-delivery"></a>
## N3 · 持续验证

- 每次提交运行既有离线冒烟；定时运行一条 `full` 整链回归。
- 逐步固化 PX4/toolchain 的可复现构建；关键 GUI 验收仍独立留证。
- 不把全部历史重型核查一次性搬入 CI，不以 headless CI 替代 GUI 验收。

## 暂不做

更多地图、多机规模、框架迁移、完整物理网捕获、实机迁移、新仪表盘、RL 批量实验。
这些均不优先于 H0 与 N1 的能力断点。
