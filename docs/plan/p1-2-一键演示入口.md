# P1-2 · 一键演示入口

> 索引：[项目完成路线](README.md#plan-index)。前置：[P0-3](p0-3-文档瘦身与入口重构.md#p0-3-goal)、[P0-4](p0-4-脚本系统瘦身.md#p0-4-goal)。
> 下游：[P1-3](p1-3-任务可观测与演示呈现.md#p1-3-goal)、[P1-4](p1-4-视觉算法接入.md#p1-4-goal)、[P2-1](p2-1-项目交付物.md#p2-1-goal)。
> 约束引用：[唯一执行口](../ROS2迁移交接文档.md#execution-port)（演示脚本**不得**新增命令者）。

## 为什么做

现在启动系统要敲类似这样的命令（实测来自 [w6.launch.py](../../src/agc_task/launch/w6.launch.py)）：

```bash
ros2 launch agc_task w6.launch.py backend:=full scene:=s08_... \
  gz_args:="-s -r -v 3 ..." gui_render_backend:=auto \
  own_px4_delay_s:=25.0 intruder_px4_delay_s:=35.0 agent0_port:=8888 ...
```

问题：

1. **名字对使用者无意义** —— `backend` / `s08` / `px4_warmup` 是开发内部词汇；
2. **失败不友好** —— 少 source 一个环境、DDS 残留、工具链缺失，报错分散在 5 个进程的日志里；
3. **退出不干净** —— 中断后常留 `gz sim` / `px4` / `MicroXRCEAgent` / 桥进程（[整链排障速查](../conventions/整链排障速查.md#0-三条环境铁律) 明确要按 PID 清）；
4. **演示无法重复** —— 每次靠人记参数，不可能做出稳定的演示。

**目标：一条命令起，一条命令停，失败说得清，退出不留垃圾。**

## 设计原则

1. **薄封装，不重写编排** —— 底层仍调 `w6.launch.py`（它是 [ADR-0061](../adr/0061-w6-runtime-topology-backend-identity-and-single-parameterized-entry.md) 的唯一参数化入口）。脚本**只做**：环境预检、参数收敛、进程组管理、状态呈现。**不复制** launch 逻辑。
2. **不新增命令者** —— 脚本不得直接发 `/agc/ground/cmd_vel` 或写模型位姿（[唯一执行口](../ROS2迁移交接文档.md#execution-port)）。
3. **默认能跑** —— 不传参数就该跑主场景（P0-1 选定）。
4. **可退出** —— `Ctrl-C` 或 `./run_demo.sh stop` 后必须无残留。

## 要做什么

### 1. 入口脚本：`run_demo.sh`（项目根）

```bash
./run_demo.sh                # 默认：yard 地图 + 主场景 + GUI
./run_demo.sh --headless     # 无头（快跑 / 服务器）
./run_demo.sh --map open_field
./run_demo.sh --duration 120 # 到时自动停
./run_demo.sh stop           # 停掉本脚本起的所有进程
./run_demo.sh doctor         # 只做环境预检，不启动
```

**为什么是 shell 而非 Python**：预检要 source ROS 环境、管进程组、调 `colcon`，shell 最直接。复杂逻辑（预检项、状态轮询）可拆 `scripts/demo/*.py` 由 shell 调用。

**已交付形态**（2026-10-30，P1-2 round-2）：`run_demo.sh` 只做 source / 参数收敛 / 人话错误外观，
逻辑在 [`scripts/demo/`](../../scripts/demo/)：`common`（进程组与状态文件）、`doctor`（预检）、
`start`（编排 + 进度 + 跟随）、`stop`（回收 + status）、`evidence`（取证）、`compare`（等价核验）。
另有 `status` 与 `compare` 两个只读子命令。

<a id="p1-2-oracle-arm"></a>
### 1b. 观测指向臂（**默认值即口径**，不得含糊）

默认演示**显式**传 `observe_yaw_mode:=target`：机头/相机对准**真值方位**，
是 [ADR-0070](../adr/0070-w7b-research-propositions-and-rl-role-adjudication.md) 允许的**显式 oracle 指向臂**，
不是 `air.yaml` 的默认 `velocity`，**也不代表真实视觉识别**；目标测量仍走 `air_fusion`。
依据：[P1-1 round-7 验收裁定](../../.coordination/archive/20261029-006-p1-1-scene-assets/round-7/review.md#p1-1-r7-acceptance)。

- 脚本把该参数**写死**在启动命令里（`scripts/demo/start.py::launch_argv`），并有回归
  [`test_demo_entry.py`](../../scripts/tests/test_demo_entry.py) 锁住"不得回退成空串/velocity"；
- 启动横幅、`result.md`、`result.json` 三处都显式打印该臂；
- **不得**据此宣称默认 `velocity` 或真实视觉识别已通过（已知缺口见 [P0-1 G1](p0-1-项目完成定义.md#p0-1-goal)）。

### 2. 四段职责

#### ① 预检（`doctor` 子命令，失败即停并说明）

按 [整链排障速查](../conventions/整链排障速查.md#preflight) 的检查单落地：

| 检查 | 判据 | 失败提示 |
|---|---|---|
| ROS 环境 | `/opt/ros/jazzy/setup.bash` 可 source | "先装 ROS 2 Jazzy" |
| 工作区已构建 | `install/agc_task` 等 8 包存在 | "先跑 `colcon build`" |
| 工具链二进制 | `toolchain/bin/MicroXRCEAgent`、`toolchain/PX4-Autopilot/build/px4_sitl_default/bin/px4` | "工具链未构建，见 toolchain/README" |
| `ROS_DOMAIN_ID` | 空或 0 | "自设非 0 域会导致 lifecycle 服务不通" |
| `ROS_AUTOMATIC_DISCOVERY_RANGE` | `LOCALHOST`（脚本自动设） | 自动设置 |
| 残留进程 | 无 `gz sim` / `px4` / `MicroXRCEAgent` / `parameter_bridge` | "有残留，先 `./run_demo.sh stop`" |
| DDS 共享内存 | `/dev/shm/fastrtps_*` 数量 < 阈值（如 200） | "残留段过多，建议清理" |
| 端口 | 8888/8889 空闲 | "端口被占" |

> **`doctor` 必须能在 30 秒内跑完**，且**不启动任何仿真**。这是给同学/老师第一次接触项目用的。

#### ② 启动

- 自动 `source` 环境（ROS + 工作区 install）；
- 组装 `ros2 launch agc_task w6.launch.py`，参数由脚本按 `--map` / `--scene` / `--headless` 映射；
- 用**独立进程组**启动（`setsid` 或 shell job control），记录 PID 到 `experiments/demo/.pids`；
- 日志统一落 `experiments/demo/<timestamp>/`（复用 [ADR-0007](../adr/0007-experiment-artifacts-convention.md) 落点约定，`campaign=demo`）。

#### ③ 等待与呈现

启动后不是"起完就完"，要告诉使用者进度：

```text
[00:00] 环境预检 ............ OK
[00:05] 启动仿真世界 ......... OK
[00:35] PX4 己方实例 ......... OK (25s 错峰)
[00:45] PX4 入侵者实例 ....... OK (35s 错峰)
[00:50] 任务层就绪 ........... OK
[01:20] 当前状态：GROUND_APPROACH  目标距离 8.4 m
[01:55] 终态：TRACKING_SUCCESS
[01:56] 结果：experiments/demo/20261029-.../metrics/summary.json
```

> **注意**：`backend:=full` 有 **25s + 35s 的 PX4 错峰延时**（[ADR-0094](../adr/0094-uxrce-participant-warmup-and-px4-stagger.md)），演示时必须**显式提示"正在等待 PX4 就绪"**，否则使用者以为卡死。
> 若 `lightweight` 后端无 PX4，启动只需几秒——**默认演示用哪个后端需在 P0-1 定**（建议演示用 full，快跑/回归用 lightweight）。

#### ④ 停止（必须可靠）

```bash
./run_demo.sh stop
```

- 按记录的 PID **先 SIGINT、再 SIGKILL**（进程组，不 `pkill -f`）；
- 确认 `gz sim` / `px4` / `MicroXRCEAgent` / 桥全部退出；
- 打印"已清理 N 个进程"；
- **不删除**本次 `experiments/demo/<ts>/`（那是证据）。

### 3. 状态呈现的数据源

不要自己造状态——读现有话题：

| 数据 | 来源 |
|---|---|
| 任务状态 | `/agc/task/state`（`AgcTaskState`，含 `state_name` / `reason_code` / `target_xy_distance_m`） |
| 结果摘要 | `metrics/summary.json`（[run_logger.cpp](../../src/agc_task/src/run_logger.cpp) 落盘） |

脚本用 `ros2 topic echo --once` 或轻量 Python 订阅（**不要**起 RViz 才能看状态）。

> **P1-3 会把这个呈现做得更好**；P1-2 只需"能打印状态 + 能拿到 summary"，不追求界面。

### 4. 参数收敛（对外只暴露 5 个）

| 对外参数 | 映射到内部 | 默认 |
|---|---|---|
| `--map` | `world_map`（P1-1 新增） | `yard` |
| `--scene` | `scene` | **`s04_static_static_obs_track`**（用户 2026-10-29 裁定） |
| `--headless` | `gz_args` 加 `-s` | GUI |
| `--duration` | 到时触发 stop | 不限（跟终态） |
| `--backend` | `backend` | **`full`**（用户 2026-10-29 裁定；快跑可用 `lightweight`） |
| `--perception` | `perception_path`（[ADR-0103](../adr/0103-vision-perception-decision-path.md)） | `truth`（视觉模型就绪后可选 `vision`） |

**其余内部参数一律由脚本固定**，不暴露。需要调试的人直接用 `ros2 launch`。

> **`backend:=full` 的演示节奏**（用户已裁定默认 full）：
> - 启动到任务开始约 **45–60 s**（PX4 own 25 s + intruder 35 s 错峰）；
> - 进度提示**必须**覆盖这段等待，否则使用者以为卡死；
> - 快跑/回归/批量场景仍可用 `--backend lightweight`（几秒起，无空中链路）。

### 5. 与现有工具的关系

- **不替换** [episode_runner.py](../../scripts/episode_runner.py)（那是批量实验，语义不同）；
- **不替换** `tests/` 核查（那是验收）；
- `run_demo.sh` 是**面向人的单次演示**，产物落 `experiments/demo/`，**不进**任何研究批次统计。

### round-3 补证（2026-10-30）

两个小范围修正，**不改**上表任何已封存结论：

1. **headless 不再起 RViz**：`viz` 改为**仅 GUI 为 true**、headless 为 false
   （[`scripts/demo/start.py::viz_enabled`](../../scripts/demo/start.py)）。
   依据是本页 §3 自己的规定——"**不要**起 RViz 才能看状态"；headless 用于经济快跑，
   多起 `rviz2`（≈257 MB）+ `viz_markers`（≈90 MB）+ `static_tf` 纯属浪费。
   现场对比：round-2 的 3 次 headless 各起 **1** 个 `rviz2`/`viz_markers`；round-3 起 **0** 个。
   该改动**不影响**已封存的 GUI↔headless 等价原始证据（等价的自变量是 `gz -s` 与渲染开销，
   而 headless 臂原本就不产出 GUI 证据、`gui_claim=not_applicable`）。
2. **`--duration` 主动停分支已闭环**（round-4，`--duration 8` 单次 attempt）：

   | 判据 | 实测 |
   |---|---|
   | 到时前无任务终态 | ✅ `terminal_reached=false`，停在 **`GROUND_APPROACH`** |
   | `exit_reason` | ✅ **`duration_limit`** |
   | `duration_branch_taken` | ✅ **`true`**（无 `duration_not_reached_note`） |
   | 退出码 | ✅ **3**（主动停 ≠ 任务失败 2 ≠ 任务成功 0） |
   | 回收 | ✅ `confirmed=true`，清 **33** 个进程，`members_after=[]`，`ps` 复核 **0** 残留 |
   | summary 保留 | ✅ `20261030-…-0-172926-7202`（`terminal_state=GROUND_APPROACH`、`latched=false`） |

   证据：[`experiments/p1-2/round-4/evidence/`](../../experiments/p1-2/round-4/evidence/)。

   > round-3 的 `--duration 15` 曾被 13.61 s 的终态抢先（属**有效判别结果**，不是失败）；

## 风险与注意

- **进程组管理是本项最大坑**：`ros2 launch` 会派生子进程（gz / px4 / agent / 桥）。用 `setsid` 建新会话组，`kill -INT -<pgid>` 整组发信号；只杀父 PID 会留孤儿。
- **PX4 错峰 25s/35s** 让"启动慢"成为常态。演示脚本必须**分段提示**，不能一个"loading..."转圈到底。
- 不要用 `pkill -f`（[整链排障速查](../conventions/整链排障速查.md#0-三条环境铁律) 明确：会匹配 shell 自身）。
- 不要在脚本里 `export ROS_DOMAIN_ID=77` 之类"优化"——实测会导致 lifecycle 服务数据面不通。
- 脚本必须**幂等**：重复 `stop` 不报错；重复启动应先检测已有实例并提示。
- 若在 WSL2 下，GUI 需要 `gui_render_backend` 选择（[world_bringup](../../src/agc_sim/launch/world_bringup.launch.py) 已有 `auto/d3d12/software` 机制）——脚本应自动探测，不要让人选。
