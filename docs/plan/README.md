## 阶段判断（为什么改方向）

项目**技术底子够、产品形态不够**。以下是 2026-10-29 实测的现状事实（可复核）：

| 维度 | 现状 | 证据 |
|---|---|---|
| 世界内容 | 一张 80×80 m 空地，**只有 2 根 0.3×0.3×3 m 柱子** | [world_geometry.yaml](../../src/agc_sim/config/world_geometry.yaml) |
| 世界生成器能力 | 只支持**长方体**注入（`<box><size>`），圆柱/墙体/网格资产一律不支持 | [world_bringup.launch.py](../../src/agc_sim/launch/world_bringup.launch.py) `_inject_static_obstacles` |
| 视觉传感器 | **全项目无相机**：无 image 话题、无相机模型、无桥接条目 | [bridge.yaml](../../src/agc_sim/config/bridge.yaml)、[perception_sensors.yaml](../../src/agc_perception/config/perception_sensors.yaml) |
| 对外入口 | 只有开发命名入口（`w6.launch.py backend:=…`），**无根目录 README、无一键脚本** | 项目根 |
| 文档入口 | 每次开工须读 4 类：AGENTS.md 30 行 + GLOSSARY 85 + 契约 157 + Runbook 347，另加 workstream 三件套 | [AGENTS.md](../../AGENTS.md) |
| 历史堆积 | ADR **102** 篇（约 1.0 MB）、specs **32** 目录 **97** 文件、协作轮次 **71** 文件 | `docs/adr/`、原 `.trae/specs/`、`.coordination/task/` |
| 脚本堆积 | `scripts/` 顶层 **32** 个（31 py + 1 sh），但 [scripts/README](../../scripts/README.md) 只登记 **8** 个长期工具 | `scripts/` |
| 测试堆积 | `tests/` **57** 个核查脚本，多为 W5/W6/W7 风险项编号 | `tests/` |

一句话：**继续加研究验证脚本的边际收益已低于"让项目看起来、跑起来像一个完整项目"的收益。**

## 推荐执行顺序

```text
P0-1 → P0-2 → P0-3 → P0-4 → P1-2 → P1-1 → P1-3 → P1-4 → P2-1
```

先定标准（P0-1），再停旧车（P0-2），再清场地（P0-3/P0-4），再修门面（P1-2 一键入口），
再填内容（P1-1 地图），再做解释（P1-3），再接外部能力（P1-4），最后打包（P2-1）。

> **为什么 P1-2 在 P1-1 之前**：一键入口是**壳**，壳先立起来，后面每加一张地图/一个面板都能立刻在演示入口上验证；否则容易做完地图却仍要手敲一堆内部参数。
