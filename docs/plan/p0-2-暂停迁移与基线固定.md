# P0-2 · 暂停迁移与基线固定

> 索引：[项目完成路线](./README.md#plan-index)。前置：无（可与 [P0-1](./p0-1-项目完成定义.md#p0-1-goal) 并行）。
> 下游：[P0-3](./p0-3-文档瘦身与入口重构.md#p0-3-goal)、[P0-4](./p0-4-脚本系统瘦身.md#p0-4-goal) 都以此处的基线为起点。
> 协作机制引用：[协议](../../.coordination/README.md#protocol)、[当前交接](../../.coordination/CURRENT.md#current)。

## 为什么先做这件事

当前 [CURRENT.md](../../.coordination/CURRENT.md#current) 状态是 **`待执行`**，任务 `20261027-001-w8-validation-recovery` 第 24 轮。这意味着**任何新会话都可能接着跑 W8 discovery 日志修复**——与"先完成项目"的方向直接冲突。

同时工作区有 **36 项未提交改动**（`git status` 实测：13 项 modified + 23 项 untracked），若不先固定，后续文档/脚本重构会与这些改动混在一起，回滚困难。

**这一步是"把车停稳"，不是"继续开车"。**

## 要做什么

### 1. 关闭当前任务链

按 [协作协议](../../.coordination/README.md#files) 的流转规则，当前任务**不是**"已验收"，应记为 **`已关闭`**（理由：用户裁定方向切换，非实现失败）。

具体动作：

1. 在 `.coordination/task/20261027-001-w8-validation-recovery/round-24/` 下补一份 `review.md`，写明：
   - 关闭原因：用户 2026-10-29 裁定暂停迁移推进；
   - 本轮未执行：T0/T1 未跑，无证据产出；
   - **不得**伪装为验收通过（[协作原则](../../.coordination/README.md#协作原则) 明确禁止）。
2. 把该任务目录移入 `.coordination/archive/`（[归档说明](../../.coordination/archive/README.md#archive)）。
3. 改写 [CURRENT.md](../../.coordination/CURRENT.md#current)：
   - 任务 ID：`无`
   - 轮次：`无`
   - 状态：`空闲（暂停迁移，转项目收尾）`
   - 指向：本目录 [项目完成路线](./README.md#plan-index)
   - **明确写**"迁移 workstream 暂停，W8 不再接单"。

> **为什么必须动 CURRENT**：Agent 每次会话会读它。只改文档不改进度指针，等于没停——下次会话照样接着跑 W8。

### 2. 固定工作区基线

1. 记录 `git rev-parse HEAD`、分支、`git status --short` 全量输出到本文件"基线（回填）"节。
2. **提交或暂存**当前 36 项改动，二选一：
   - 若改动是有效的（多数看起来是 W8 相关的有效修复）→ 分主题提交，例如 `w8: mission fco audit` / `docs: adr 0099-0102`；
   - 若不确定 → `git stash push -u -m "pre-completion-pivot 2026-10-29"`，并记录 stash id。
3. **禁止**在此步骤删除任何未提交改动（那是别人的工作，可能仍有价值）。

### 3. 建立"暂停"标记（供后续会话读取）

在项目根建一个**极短**的暂停说明（约 10 行），例如 `docs/plan/PAUSED.md`，内容只有：

- 迁移 workstream 已暂停（日期 + 裁定来源）；
- 当前方向见 [项目完成路线](./README.md#plan-index)；
- 迁移相关文档（Runbook / 契约 / specs）**默认不读**，需要时按主题查。

> 这是给 **Agent** 看的开关，不是给人看的长文。P0-3 会把它的内容并入新的精简入口，届时本文件可删。

### 4. 确认没有"活着的"自动接续机制

实测确认：

- [ADR-0102](../adr/0102-leader-worker-dual-model-handoff.md) 已退役跨进程叫醒；`.coordination/wake/` 已在 `.gitignore` 忽略。
- `.coordination/scripts/` 是否存在仍在运行的叫醒脚本 → 检查并停掉。

**判据**：不存在任何会**自动创建** W8 任务或自动给 Worker 派单的进程/定时任务。

## 风险与注意

- **不要**用 `git checkout .` 或 `git reset --hard` 清工作区——会丢 W8 证据修复。
- **不要** `pkill -f "<名字>"`（会匹配 shell 自身，见 [整链排障速查](../conventions/整链排障速查.md#0-三条环境铁律)）；用 PID。
- 归档 W8 任务**不等于**否定其结论；报告里应写"结论保留，任务链关闭"，便于以后需要时复活。
- 若用户以后要恢复迁移，只需改回 `CURRENT.md` 并取消 `PAUSED.md` 标记，**不需要**恢复叫醒机制。

- 不评价 W8 结论对错（本阶段不做研究判定）。
- 不重启或修复叫醒机制。
