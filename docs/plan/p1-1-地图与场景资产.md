# P1-1 · 地图与场景资产

> 索引：[项目完成路线](README.md#plan-index)。前置：[P0-1](p0-1-项目完成定义.md#p0-1-goal)（主场景已定）。
> 相关约束（只引用）：[C7 出生净空](../ROS2迁移交接文档.md#hard-constraints)、[ADR-0062 几何单一真源](../adr/0062-scene-geometry-single-source-and-derivation.md)、[ADR-0023 出生净空标定](../adr/0023-spawn-clearance-recalibration.md)、[ADR-0052 传感器安装高度与障碍族边界](../adr/0052-sensor-and-vehicle-model-limitation-and-capability-calibration.md)。

## 为什么做

用户原话：**"当前地图太过空旷简单，只有两个生成的障碍物。缺少合适的地图。"**

实测确认：

- [world_geometry.yaml](../../src/agc_sim/config/world_geometry.yaml) 只有 `pole_1`(0,-6) 与 `pole_2`(6,6)，均为 **0.3×0.3×3 m** 立方体；
- 作业区 80×80 m，**障碍覆盖率约 0.0003%**；
- 世界生成器 `_inject_static_obstacles` 只会生成 `<box><size>`，**没有圆柱、墙体、坡道、网格资产**能力。

后果不只是"不好看"：

1. **导航/避障能力无从体现** —— 空旷场景下任何规划器都能到终点，看不出差别；
2. **感知遮挡几乎不触发** —— 感知默认 `occlusion.enabled: false`（[perception_sensors.yaml](../../src/agc_perception/config/perception_sensors.yaml)），且两个细柱几乎挡不住视线；
3. **视觉识别无场景可识别** —— P1-4 要接的"空对地场景识别"需要**有内容的画面**，现在画面里只有地板和两个柱子。

**目标：用 2 张有明确用途的地图，替代"一张空地板"。**

## 关键约束：地图必须走单一真源派生链

这是本项目最容易踩坑的地方。改地图**不是**改 SDF 就行，[ADR-0062](../adr/0062-scene-geometry-single-source-and-derivation.md) 要求几何只有一个家，其余全部**派生**：

```text
world_geometry.yaml（唯一真源）
   ├─→ world_bringup._inject_static_obstacles  → GZ 物理世界（碰撞 + 视觉）
   ├─→ w6_composition.write_derived_obstacles  → 感知障碍先验（ObstacleObservation 来源）
   ├─→ w6_composition.write_derived_map        → 感知 OccupancyGrid 几何
   ├─→ w6_composition.apply_air_geometry       → 空中安全屏障障碍列表
   └─→ w6_composition.compose_params           → scenario_reset 障碍名/坐标/边界
```

**现有核查** [w6_geometry_check.py](../../tests/w6_geometry_check.py) 断言 (a)–(g) 七项，含"回退副本与真源一致""派生 == 真源"。

### 已知耦合陷阱（实测）

1. **`obstacle_safety_radius` 是位置对应的定长列表**
   [air.yaml](../../src/agc_air/config/air.yaml) 现为 `[2.0, 2.0]`，与 `obstacle_names` **按下标对齐**。
   → 加到 N 个障碍却不同步扩展该列表，会**索引错位或越界**。必须改为**按障碍派生**（每个障碍一个半径，或 schema 内写 `safety_radius`）。

2. **空中安全层是二维静态圆盘屏障**（[ADR-0052](../adr/0052-sensor-and-vehicle-model-limitation-and-capability-calibration.md) 明示限制）
   → 障碍一多，无人机可飞空间被"膨胀圆盘"吃掉，可能出现**无解**。必须验证跟踪轨迹仍可达。

3. **`car/lidar_link` 在 z=0.48 m**（[car.yaml](../../src/agc_sim/config/car.yaml) 已如实登记）
   → 只对"z≈0.48 有足够水平截面且进入光束"的障碍族可见。**矮墙、悬空结构、薄片对该激光不可见**。
   → 新地图若用"矮墙"，必须在文档中标注"该障碍对地面激光不可见"，不能假装能避。

4. **出生净空 C7**（[#hard-constraints](../ROS2迁移交接文档.md#hard-constraints) 第 7 条）
   → 障碍变密后，车/目标出生点可能与新障碍冲突。必须按 [ADR-0023](../adr/0023-spawn-clearance-recalibration.md) 重算并核查。

5. **回退副本会漂移**
   [obstacles.yaml](../../src/agc_perception/config/obstacles.yaml) 与 [map.yaml](../../src/agc_perception/config/map.yaml) 是 standalone 回退副本，**必须与真源一致**。改地图后忘同步 → 核查 (c) 直接失败。

## 要做什么

### 1. 扩展几何 schema（先扩能力，再做地图）

当前 schema 只有 `id/x/y/z/yaw/size/color` + 隐式 `box`。需扩展为**形状可表达**：

```yaml
work_area: {resolution, size_x, size_y, origin_x, origin_y}

obstacles:
  - id: building_a
    shape: box            # box | cylinder（先支持两种，够用）
    x: -8.0
    y: 12.0
    z: 1.5                # 中心高度
    yaw: 0.0
    size: [6.0, 4.0, 3.0] # box: x/y/z 尺寸；cylinder: [r, r, h]
    color: [0.55, 0.55, 0.60]
    safety_radius: 3.0    # 空中屏障半径（替代位置对应的定长列表）
    occludes: true        # 是否参与感知遮挡（供 P1-4/感知升级）
```

**派生点需同步改**：

| 位置 | 改动 |
|---|---|
| `world_bringup._inject_static_obstacles` | 支持 `<cylinder><radius><length>`，保留 `<box>` 分支 |
| `w6_composition.write_derived_obstacles` | 透传 `shape`（若感知只吃 box，可降级为包围盒，**须写明**） |
| `w6_composition.apply_air_geometry` | 从每个障碍读 `safety_radius`，不再用定长列表 |
| `agc_air/config/air.yaml` | 删除 `obstacle_safety_radius: [2.0, 2.0]`，改为"由真源派生"注释 |
| `w6_geometry_check.py` | 断言 (a) 扩 schema 校验；(b) 支持 cylinder 解析 |

> **兼容性**：`shape` 缺省为 `box`、`safety_radius` 缺省取全局默认 → 老配置不写也能跑，保证 `none`/`static` 两个既有轴不受影响。

### 2. 做 2 张地图（不是 10 张）

#### 地图 A：`yard`（演示主地图）

用途：**答辩/演示默认地图**，有结构、有遮挡、画面好看。

| 要素 | 建议布局 | 目的 |
|---|---|---|
| 4 栋建筑（box，6×4×3 m ~ 10×8×4 m） | 分布在四角，中间留通道 | 产生街道/遮挡 |
| 2 段围墙（box，0.4×12×1.2 m） | 斜置，形成半封闭院 | 演示"绕行" |
| 4 个圆柱罐体（cylinder，r=1.2，h=2.5 m） | 中部偏东 | 演示"圆柱绕障"+ 视觉可识别目标 |
| 保留 pole_1/pole_2 | 原位不动 | 既有核查/证据仍成立 |
| 车 spawn | 西南角空地 | 与目标分离 ≥ 30 m |
| 目标 spawn | 东北角建筑旁 | 需绕行才可达 |

覆盖面积目标：障碍占作业区 **5%–12%**（当前 0.0003%）。

#### 地图 B：`open_field`（能力对照地图）

用途：**回归/对照**，证明"空旷下也正常"，并作为 headless 批量跑的经济地图。

- 仅 3–5 个稀疏圆柱 + 1 栋建筑；
- 车/目标直线距离 ~40 m；
- 用于快跑、冒烟测试、CI 式核查。

#### 保留：`minimal`（现有 pole 双柱）

用途：**几何派生链核查的稳定基线**。`w6_geometry_check.py` 的断言 (b) 依赖 `pole_*` 命名，**不要删**。

> **三张地图的分工**：`minimal` 保证核查不断，`open_field` 保证跑得快，`yard` 负责好看。**不要**把 `yard` 直接替换成默认而删掉 `minimal`。

### 3. 地图选择机制（不新增复杂参数）

现有 `world_obstacles` 只有 `static | none` 两值（[scenario_carriers.yaml](../../src/agc_task/config/scenario_carriers.yaml)）。

建议**最小改动**：把真源文件按地图拆分 + 保留一个默认：

```text
src/agc_sim/config/
├── world_geometry.yaml          # 保留：minimal（pole 双柱）—— 默认，核查基线
└── maps/
    ├── yard.yaml
    └── open_field.yaml
```

新增参数 `world_map`（`minimal | yard | open_field`），由 launch 选文件；`world_obstacles: static|none` 语义**不变**（`none` 仍强制无任何障碍，用于轴对照）。

> **为什么不直接把 3 张图塞进一个 yaml 的多个 key**：分开文件后 `geometry_sha256` 天然按地图区分，证据/manifest 里能直接看出用的哪张图，比一个文件内切换更可审计。

### 4. 同步回退副本与核查

每张地图都要有对应回退副本（或明确"仅 w6 路径可用，standalone 只支持 minimal"）。

建议：**回退副本只保留 minimal**，standalone 感知启动时若指定非 minimal 地图则**显式报错**（比静默用错几何好）。相应把 `w6_geometry_check.py` 的 (c) 断言限定为"minimal 副本与 minimal 真源一致"。

### 5. 视觉资产（可选，最后做）

若时间允许，给 `yard` 加地面材质（柏油/草地贴图）与建筑材质。**优先级最低**——先保证几何与核查通过，材质不影响任何功能判据。

> 若要引入外部 3D 资产，必须走 [第三方资产与许可](../conventions/第三方资产与许可.md) + [ADR-0068](../adr/0068-third-party-asset-provenance-license-and-hash-manifest.md) 的 provenance/许可/哈希登记，**不能用来源不明的模型**。

**几何与飞行可行性的耦合（本轮实测结论，写下来避免后人重踩）**：8 字轨迹（rx15/ry9）水平占
x∈[-15,15]、y∈[-4.5,4.5]，其膨胀盘还要 +3.2 m（障碍余量 2.5 + 反应/可达 0.7）。因此**中央区域
可放物体的位置不是自由矩形**，而是"轨迹外围的两条带"。把大块物体硬塞进中央会直接切断 8 字轨迹，
使空中安全层判不可行。yard 的中央内容（塔 / 罐场 / 薄板 / 罐 / 配电房）正是安排在
北带 y≈8..14 与南带 y≈-7..-12 内。

## 视觉保真：材质 / 配色 / 建筑细部 / 地面分层（2026-10-29 21:00 用户裁定）

**用户原话**：「建筑和地面精细度不高，能不能优化，比如材质改变，颜色分配优化。二是小型物体
（路牌这种）现在有点少，略微增加不要过分密集。**网页看不了就不看了，学习本地能看的就行，
依旧设计好了再动手**」。→ 四件事：**材质 / 配色 / 细部 / 略增小型件**；取证只用**本机**资产。

**先学后做（决定性依据来自本机）**：`sdformat 1.11` 的
[`material.sdf`](/opt/ros/jazzy/opt/sdformat_vendor/share/sdformat14/1.11/material.sdf) 里
`<pbr><metal>` 的 `<metalness>` / `<roughness>` 是**标量**字段（默认 0.5）——**不需要贴图**，
因此"改材质"与"不引入外部资产"（[ADR-0062](../adr/0062-scene-geometry-single-source-and-derivation.md) 纪律）
不冲突。`gz sdf -p` 解析通过（无报错）。

| **材质档 `finish`（新 schema 字段）** | 7 档：`concrete`(0.00/0.90) / `steel`(0.75/0.35) / `paint`(0.15/0.45) / `glass`(0.05/0.08) / `rust`(0.10/0.95) / `asphalt`(0.00/0.95) / `rubber`(0.00/0.80)；**逐 part 可覆盖实体级**；非法值拒绝运行；**缺省不写 = 旧行为**（无 `<pbr>` 块） |

**渲染实测（118 m 俯视，sRGB）**：沥青 ~93 / 基层地面 **135** / 场坪 **150** / 金属屋面 **202**
→ 屋面−地面 **67 级**（R5 时期仅 6 级）。

### 口径变更（**需 Leader 追认**）

1. **实体上限 40 → 46**（断言 (o) `n_obstacles_le_46`）。理由：尺度参照物若做"无碰撞装饰"会
   出现"看着撞了却穿过去"的演示事故，故只能进真源、计入实体数。现 42，留余量 4。
2. **新增断言 (q) `q_luma_bands`**：屋面 albedo L − 基层地面 albedo L **≥ 0.30**，
   且屋面必须使用 `roofpanel` 档。这是"区分度"第一次可自动判定。
3. **`finish` 新增 `roofpanel`（0.06 / 0.40）**；`steel` 由 **metalness 0.75 / roughness 0.35**
   调为 **0.35 / 0.42**。
   依据（实测，非常关键）：**无环境贴图时 `metalness` 才是亮度杠杆**——metalness=0.75 的金属屋面
   在渲染里只有 **83/255**，旁边 metalness=0 的混凝土檐是 **161/255**；即"提亮 albedo 对金属件无效"。
4. **地面贴图属自产资产**（非第三方）：生成器 + 固定种子 + `manifest.json` 的 sha256 登记，
   不进 [第三方资产清单](../../docs/conventions/第三方资产与许可.md)。
5. **`install(DIRECTORY … materials)`**：贴图随 `agc_sim` 安装；SDF 用安装目录绝对路径引用
   （世界文件运行期生成到 `/tmp`，相对路径会失效）。

### 已知限制（如实登记）

- **贴图受 UV 限制**：`box` / `plane` 图元无 UV 缩放，一张图被拉伸到整个面。故只做**低频斑驳 +
  细颗粒**，分格/标线继续用真几何。**建筑外墙贴图暂不做**（会明显拉伸）。
- **RViz 占位栅格在本机有 GLSL 报错**（`indexed_8bit_image` 着色器链接失败，
  "active samplers with a different type refer to the same texture image unit"），
  属驱动/OGRE 层；marker 层不受影响。
- **`world` 帧不在 TF 中**：项目话题都在 `world` 系，但 TF 里没有该帧，RViz 的 Fixed Frame
  因此失效（**窗口全空且不报错**）。→ `viz:=true` 时发 `map→world` 恒等静态 TF，Fixed Frame 用 `map`。

### 仍然存在的缺口

**8 字轨迹净空没有正式断言**（官方核查只查"待机环带可行弧 ≥ 90°"）。R4/R5 依赖的临时核验器
写在 `/tmp` 已丢失。本轮新增参照物全部落在 y≈−30..−40 外环、远离 8 字带（|y|≤7.7）与待机环带，
故净空不可能改变——但这是**推理**，不是**验证**。建议下一轮把它做成 `tests/` 的正式断言。

## 风险与注意

- **最大风险：改了地图但派生链没跟上** → 感知/复位/空中安全用的是旧几何，出现"世界里有墙但地图上没有"的诡异行为。**每改一次真源，立刻跑 `w6_geometry_check.py`**。
- 障碍数量增加会**拖慢 GZ 物理与感知**（尤其遮挡判定）。yard 当前 **42 实体 / 234 图元**已由断言 (o) 限定实体 ≤46；新增实体须同时复核性能、净空与派生链，不得继续无序膨胀。
- `occlusion.enabled` 默认 `false`；若为演示开启遮挡，需确认 FOV/遮挡逻辑在密集场景下的性能与正确性（属感知域改动，可能牵出 W4 问题，**谨慎**）。
- 不要为了"好看"加**不可碰撞**的装饰物（视觉有、碰撞无）——会造成"看着撞了却穿过去"，演示事故。
- 圆柱碰撞用 `<cylinder>`，**不要**用高面数 mesh 做碰撞体（物理性能与稳定性都会变差）。
