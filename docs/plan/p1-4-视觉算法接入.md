# P1-4 · 视觉算法接入

> 索引：[项目完成路线](README.md#plan-index)。前置：[P1-1](p1-1-地图与场景资产.md#p1-1-goal)（有场景可识别）、[P1-2](p1-2-一键演示入口.md#p1-2-goal)（有稳定启动）。
> 下游：[P2-1](p2-1-项目交付物.md#p2-1-goal)。
> 相关决策（只引用）：[ADR-0020 真值派生感知](../adr/0020-perception-as-truth-derived-simulation.md)、[ADR-0052 传感器与平台能力限制](../adr/0052-sensor-and-vehicle-model-limitation-and-capability-calibration.md)、[接口分层](../conventions/接口分层.md)。

## 为什么做

用户说明：**"另一个同学开始着手开发空对地场景识别视觉算法。"**

这条线要成立，前提是**仿真里能拿到真实图像**。实测现状：

| 事实 | 证据 |
|---|---|
| 全项目**无相机传感器** | 无 `<sensor type="camera">`，无 `image` 话题 |
| 桥配置**无图像条目** | [bridge.yaml](../../src/agc_sim/config/bridge.yaml) 只有 clock/odom/点云/scan/contact/cmd |
| PX4 `gz_bridge` **不消费相机图像** | `GZBridge.cpp` 无 camera/image 相关代码 |
| 感知是**真值派生**，非视觉 | [ADR-0020](../adr/0020-perception-as-truth-derived-simulation.md)；[perception_sensors.yaml](../../src/agc_perception/config/perception_sensors.yaml) 头部明示"非真实视觉识别" |

也就是说：**现在没有任何一条能产出图像的链路。** 视觉同学拿不到数据，只能自己造数据集——那和仿真系统就脱钩了。

**目标：把"仿真 → 图像 → 识别 → 系统消费"这条链接上，且识别算法可插拔、可回退。**

## 关键事实（已实测，避免重复踩坑）

1. **PX4 自带相机模型**（`toolchain/PX4-Autopilot/Tools/simulation/gz/models/`）：
   - `mono_cam`：640×480、30 Hz、`hfov=1.74 rad`（约 99.7°）、话题 `camera`；
   - `x500_mono_cam`：把 `mono_cam` **merge** 到 `x500` 机体系，挂载位 `(.12 .03 .242)`；
   - 另有 `x500_depth`（深度相机）、`x500_vision`、`OakD-Lite`。
2. **己方无人机当前用 `gz_x500`**（无相机）：[air_bringup.launch.py](../../src/agc_air/launch/air_bringup.launch.py) `PX4_SIM_MODEL=gz_x500`。
3. **相机图像不经 PX4 回传**：`GZBridge.cpp` 无图像逻辑 → 必须**直接经 `ros_gz_bridge` 从 GZ 话题桥到 ROS**。
4. **桥类型可用**：`gz.msgs.Image` ↔ `sensor_msgs/msg/Image`、`gz.msgs.CameraInfo` ↔ `sensor_msgs/msg/CameraInfo`（`ros_gz_bridge` 标准支持）。

## 要做什么

### 1. 挂相机（最小改动）

**方案 A（推荐，改动最小）：己方无人机换 `gz_x500_mono_cam`**

- 改 [air_bringup.launch.py](../../src/agc_air/launch/air_bringup.launch.py) 的 `PX4_SIM_MODEL` 为 `gz_x500_mono_cam`；
- 优点：PX4 官方模型，挂载位/参数无需自造；`GZ_SIM_RESOURCE_PATH` 已含 models 目录。
- 风险：`x500_mono_cam` 是 **merge 模型**，需确认 PX4 spawn 时资源解析正常（`model://x500_mono_cam` → include `x500` + `mono_cam`）。
- **必须验证**：换模型后飞行行为不变（质量/惯量差异会改变 LQR 标定！`mono_cam` 仅 0.05 kg，影响应很小，但**必须实测跟踪误差**）。

**方案 B：在 `agc_sim` 自建相机模型挂到 `intruder_uav` 或车体**

- 适合"地面视角看空中目标"（空对地识别的另一种语义）；
- 改动大：要自己写 xacro、管 `GZ_SIM_RESOURCE_PATH`、可能影响既有模型核查。

> **建议**：先做方案 A（机载前视看地面场景），这是"空对地"最直接的解释；若视觉同学需要地面视角，再加方案 B 作为第二相机。

**挂载点选择**：

| 视角 | 传感器位置 | 看到的画面 | 适用 |
|---|---|---|---|
| 机载前视（mono_cam 默认，+x 朝前） | 机头 | 前方地面/建筑/目标 | **空对地主视角** |
| 机载下视（改 pose 俯角 -90°） | 机腹 | 正下方地面 | 正射/建图 |
| 车载前视 | 车顶 | 地面道路/目标 | 地面视角 |

> **注意**：`mono_cam` 的 `<pose>0 0 0 0 0 0</pose>` 在 `mono_cam/base_link` 上，`x500_mono_cam` 用 joint 挂到 `base_link` 且 pose 为 `.12 .03 .242 0 0 0`（**无俯角，正前视**）。若要俯视，需**改 xacro 或自建模型**，不能只改参数。

### 2. 桥接图像到 ROS

在 [bridge.yaml](../../src/agc_sim/config/bridge.yaml) 增加（示例，实际话题名以 `gz topic -l` 实测为准）：

```yaml
# 机载相机图像（GZ → ROS）
- ros_topic_name: "/agc/air/camera/image_raw"
  gz_topic_name: "/world/agc_world/model/<own_uav>/link/<cam_link>/sensor/imager/image"
  ros_type_name: "sensor_msgs/msg/Image"
  gz_type_name: "gz.msgs.Image"
  direction: GZ_TO_ROS
  qos_profile: SENSOR_DATA

- ros_topic_name: "/agc/air/camera/camera_info"
  gz_topic_name: ".../camera_info"
  ros_type_name: "sensor_msgs/msg/CameraInfo"
  gz_type_name: "gz.msgs.CameraInfo"
  direction: GZ_TO_ROS
  qos_profile: SENSOR_DATA
```

**踩坑提示**（与既有经验一致）：

- GZ 相机话题的实际路径由 **作用域 + 模型名 + link 名 + sensor 名** 决定，**不**完全取 SDF `<topic>` 值（对照 [bridge.yaml](../../src/agc_sim/config/bridge.yaml) 中 contact sensor 的注释：`gz-sim-contact-system` 的话题"不取 SDF `<topic>` 值"）；
- **必须** `gz topic -l | grep image` 实测确认，不要猜；
- QoS 必须 `SENSOR_DATA`（best-effort），否则图像会因 reliable 队列积压而严重延迟。

### 3. 定义识别接口（可插拔）

这是让"两个同学各干各的"不互相踩的关键。**识别节点只做一个方向的数据流**：

```text
sensor_msgs/Image  ──→  [识别节点]  ──→  识别结果
                          ↑
                    可替换实现（同学 A 的模型 / 简单色块检测 / 无模型回退）
```

**接口约定（建议）**：

| 项 | 约定 | 理由 |
|---|---|---|
| 输入 | `/agc/air/camera/image_raw`（`sensor_msgs/Image`）+ `CameraInfo` | 标准 ROS 相机接口 |
| 输出 | **新消息** `DetectionArray`（含 `id`/`class`/`confidence`/`bbox`/`pose_hint`） | 不与既有 9 消息混用 |
| 频率 | 与图像同频或降频（≤10 Hz） | 识别通常慢于采集 |
| 坐标系 | 检测结果若含位置，必须标 `frame_id` 并声明是**像素框**还是**世界坐标** | 避免下游误用 |
| 可回退 | 无模型时输出**空数组**，系统仍能跑（走既有真值派生感知） | 保证演示不因模型缺失而崩 |

> **已定（2026-10-29 用户裁定）**：识别结果**接入任务决策**，即用视觉识别**替代**真值感知作为决策输入。
> 该裁定触及 [ADR-0020](../adr/0020-perception-as-truth-derived-simulation.md) 的感知口径，已立 [ADR-0103](../adr/0103-vision-perception-decision-path.md) 显式记录：
> 两条路径**并存且互斥选择**（`truth` 默认 / `vision` 可选），**不可混读**，产物必须记录 `perception_path`。
>
> **因此本项不再是"只做展示"的零风险改动**，需要按 ADR-0103 的纪律实施：
> - `vision` 路径**不得**静默用真值坐标补齐检测；
> - 无模型时必须**显式降级**（输出空检测并标注），不得偷偷回退 `truth`；
> - 评估时保留 `truth` 作为**基线臂**，量化视觉替代的代价（召回/精度/时延/终态影响）。

| **回退** | `detector_backend=none`（默认）：**逐帧空数组** + `degraded=true / reason=no_model`；无图像时**不发检测**（不伪造时间戳），状态话题标 `reason=no_image`；后端异常 → 空数组 + `reason=backend_error` | `_backend_none` / `_on_image` / `_publish_status` |

**给视觉同学的接入步骤**：① 写一个返回上述 dict 列表的函数；② 在 `BACKENDS` 注册（`model_required=True`）；
③ `vision_model_id/name/version/sha256` 传实参；④ 用 `camera_probe.py` 确认输入流，用
`record_dataset.py` 取数据。**不需要**碰 `agc_msgs`、`w6.launch.py` 或既有真值链。

> **口径**（ADR-0103）：本链路产出的是**仿真图像上的检测**，不得表述为真实部署能力；
> `truth` 路径的结果也不得当作视觉能力。


### 4. 不改既有感知链（但新增第二条路径）

[perception_sensors.yaml](../../src/agc_perception/config/perception_sensors.yaml) 的 `air_eo_front` / `air_ir_top` 是**真值派生的观测通道**，`vision` 路径**不替代**它们，而是**并行新增**一条路径，由 `perception_path` 选择（[ADR-0103](../adr/0103-vision-perception-decision-path.md)）。

- 视觉链路**新增**话题与选择参数，**不修改** `TargetObservation` / `SensorObservation` 语义；
- 9 消息 ABI（[#messages](../ROS2迁移交接文档.md#messages)）**不得变更**；
- 视觉结果进入融合需**新增一路输入**，并在消息/字段上**明确标注来源是视觉还是真值**（否则论文口径混乱）；
- `perception_path` 须进入契约 [参数入口](../ROS2迁移交接文档.md#params) 清单，由 launch 单一设置；
- `run_logger` 的 `summary.json` 须记录 `perception_path` + 视觉模型标识（名称/版本/哈希）。

### 5. 数据集与评估（给视觉同学的支撑）

视觉同学需要**带标注的数据**。仿真能直接提供**完美真值**，这是相对真实数据集的优势：

- 每个 episode 的 `experiments/<run>/` 已有目标/障碍真值（`gt_bypass`）；
- 可加一个**录制脚本**：按帧存 `image_raw` + 同步的真值位姿 → 生成 `(image, labels)` 对；
- 落点建议 `experiments/vision-dataset/<campaign>/`（遵守 [ADR-0007](../adr/0007-experiment-artifacts-convention.md)）。

> **注意**：数据集属实验产物，**不入 git**（`.gitignore` 已排除 `experiments/`）。

> 口径不变：不得以 `TRACKING_SUCCESS` 单独替代跟踪误差对比，也不得把 `vision_model.id=none` 的成功 run 当作视觉识别能力证明。

## 风险与注意

- **最大风险：换模型改变飞行动力学**。`gz_x500` → `gz_x500_mono_cam` 增加 0.05 kg 相机与惯量，**可能**影响 LQR 跟踪。必须对比跟踪误差；若显著变化，按 [ADR-0019](../adr/0019-uav-trajectory-and-tracking-parameter-calibration.md) 重标定并记录。
- **渲染依赖**：相机需要 `ogre2` 渲染。`gz_args` 加 `-s`（无头）时**相机仍可出图**（sensors 系统独立于 GUI），但**必须实测**；若 headless 不出图，数据集录制只能在 GUI 下跑（性能与并行受限）。
- **性能**：640×480@30Hz 图像经桥传输 + 保存，开销不小。录制时建议**降频**（如 10 Hz）或**降分辨率**。
- **话题名不要猜**：GZ 相机话题路径实测确认，写进 `bridge.yaml` 注释里（与 contact sensor 的做法一致）。
- **不要把识别结果直接当真值用**——那会破坏"真值派生 vs 视觉"的口径，也让论文结论不可比。
- 若视觉同学用深度学习模型，**推理进程不要放进实时域**（[ADR-0011](../adr/0011-node-language-policy.md)：C++ 实时域 / Python 工具域）；建议独立 Python 节点，通过话题交互。

## 非目标

- 不实现识别算法本身（那是视觉同学的工作）。
- 不做 sim-to-real 迁移验证。
- 不删除 / 不否定真值派生路径（`truth` 保留为默认与基线臂；口径变更已由 [ADR-0103](../adr/0103-vision-perception-decision-path.md) 裁定，不再"另立"）。
- 不做多相机融合 / 深度估计 / SLAM。
- 不在 `vision` 路径里用真值补齐检测（那会让视觉贡献不可信，见 ADR-0103）。
