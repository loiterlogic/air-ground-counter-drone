# 引用与注释纪律

> 硬规范。**代码中引用设计决策，只允许引用 ADR**；注释只回答"这段做什么、为什么必须这样写"。

## 为什么

仓库曾并行多套内部编号：评审项、工作批次、结构评审、场景号、实验轮次、章节号，
加上"真源"这类口头指代。它们来自不同时期的过程台账，编号重叠、指向已删文件、
外人无法解析；实测复盘与轮次记录还被整段塞进源码注释，读代码要先考古。

收敛口径：**决策的归属只有 ADR，过程的归属只有归档**。

## 允许写进代码/配置的引用

**代码/配置里只有一种决策引用形式：ADR。**（2026-11-06 用户裁定：整个项目以后只能在代码中引用 ADR。）

| 形式 | 例 |
|---|---|
| `ADR-NNNN` | `ADR-0010` |
| 带锚点的完整链接 | `[ADR-0010](../adr/0010-....md#top)` |

其余**一律不许**出现在代码/配置里：

| 禁止 | 例 | 改成 |
|---|---|---|
| 评审项 / 结构评审编号 | `R-031`、`S-06` | 该编号对应的 ADR |
| 工作批次 / 里程碑编号 | `W7-b`、`P1-3`、`N3`、`M0` | 该批次产出的 ADR，或直接删掉 |
| 契约项编号 | `C1`、`C10` | 契约硬约束锚点 `../adr/0020-package-boundaries-and-runtime-topology.md#hc-1`（无对应 ADR 时） |
| 章节号 | `§3.5`、`第 4 节`、`规范 2.1` | 稳定锚点 `文件.md#anchor` |
| 「真源」口语 | `见真源` | 直呼文件名（`config/spawn_layout.yaml`） |
| 实验轮次 | `round-4b` | 直接删掉（过程记忆属于归档） |
| 已退役过程目录 | `.coordination/`、`docs/plan/` | 直呼文件名或删掉 |

**判据**：一条代码注释若只能靠某个非 ADR 编号才读得懂，说明该决策没有 ADR——**去补 ADR**，而不是把编号留在代码里。

数据标识（场景 ID、话题名、参数名、包名、文件名）不是决策引用，不受约束。

> **文档内的同文档锚点不受本条限制**：`docs/**` 正文里 `[§3.5](#perception)` 这类**同文件跳转**
> 是导航手段，不是「用章节号引用决策」。约束对象是**代码/配置**，以及文档里**跨文档**的章节号引用。

## 注释写什么

一条注释只回答下面之一，且**不超过 3 行**：

1. 这段代码做什么（函数名不够自解释时）；
2. 为什么必须这样写（易被"顺手改回去"的约束，附 `ADR-NNNN`）；
3. 数值/时序的当前口径（不写推导过程）。

不写：实测复盘、推导链、轮次记录、被否方案考古、裁定日期、多段编号对照表。
仍有效的内容写进对应 ADR 的「实施回填」；已过期的直接删。

## 例外

历史证据（`docs/archive/`、`scripts/archive/`、`scripts/research/`、
`.coordination/`、`experiments/`、`docs/temp/`）按 ADR-0002 不重写。
（`docs/reviews/` 已于 2026-11-06 退役，见 [ADR-0033](../adr/0033-review-snapshot-retirement.md#top)。）
活跃代码/文档不得反向引用这些路径陈述当前行为。

`docs/adr/` 内记录的历史沿革编号属记录，不受约束，但 ADR 索引须注明旧编号体系已退役。

## 自动核对

[`scripts/tests/test_reference_discipline.py`](../../scripts/tests/test_reference_discipline.py) 四条断言：

1. **全量清零**（`test_no_forbidden_references_anywhere`）：活跃区**任何**注释与**字符串**
   （含单行 `description=` / `help=` / `assert` 消息 / docstring）都不得出现上表的禁止形态。
   **存量为零**，因此新增自然为零——不再"存量豁免、只查增量"。
2. **增量不回潮**（`test_no_new_forbidden_references_since_baseline`）：相对基线的改动行同样不得出现。
3. **文件名**（`test_active_filenames_*`）：活跃区文件名与 ADR 文件名不得带 `W/R/S/C/F/P/N3/M0` 等过程编号。
4. **ADR 可解析**：所有 `ADR-NNNN` 必须能解析。

进 `tests/run_smoke.py` 的 `offline` 组。

### 为什么把「字符串」也扫进来（2026-11-07 改造）

原实现只扫注释，且只收**多行** STRING。实测活跃代码层 127 处命中里 **122 处在单行字符串**
（`description='…W7-c…'`、`help='…'`、`assert` 消息、`'proposition': '…F-04…'`），
闸门一行都拦不住——规则说"只能在代码中引用 ADR"，机器却只查注释，覆盖面比规则窄得多。
`launch` 的 `description` 会显示给用户、`assert` 消息会进报告，都属"代码/配置里的决策引用"。

### 全仓零容忍（2026-11-07 用户裁定）

用户原话：「现在谁能知道什么是 r1、w1、p1 呢，他们的存在就是会大幅增加阅读难度和维护难度」。
据此**取消 ADR 正文与协作台账的豁免**——编号一旦出现就必须能被人读懂，不能要求读者去查表。

**仍豁免**（都不是决策引用）：

| 豁免 | 判据 |
|---|---|
| 数据标识 | 整行含 `experiments/`（产物落点，规范第 37 行） |
| 目录名 | `task/<ID>/round-N/` 这类**文件系统目录名**（后接 `/`） |
| 冻结历史区 | `docs/archive/` · `scripts/archive/` · `scripts/research/` · `experiments/` · `.coordination/` 的**未入库**过程物（`task/` `drafts/` `locks/*.lock` `STOP-*.md`；ADR-0002 / ADR-0025 不重写） |
| 临时工作区 | `docs/plan/`（结档即删） |
| 反例本体 | 两个闸门测试自身必须**写出**禁止形态才能测"能否拦住" |
| 路径配置工具 | `tests/docs_link_check.py` 声明"扫哪些目录"是扫描范围的事实陈述 |
| 旧 ADR 编号 | 在 `docs/adr/README.md` 的**合并映射表**（`| 0070 | [0022](…) |`）里有释义，属可解析的历史沿革 |

**代码 vs 文档的规则差异**：路径类（`.coordination/`、`docs/plan/`、`specs/`）与术语「真源」
**只在代码/配置里禁**——文档里「产物落 `scripts/archive/`」「契约真源」是目录结构与专有名词，
不是口语指代。编号类（`R-`/`W`/`S-`/`C`/`F-`/`X-`/`N3`/`M0`/`P-`/`round-`）**两边都禁**。

**ADR 正文里的评审项**：不再保留裸编号，改为**该评审项的标题**
（如「运行身份与复现」「决策有效性与引用」），见 [ADR-0033](../adr/0033-review-snapshot-retirement.md#top) (d)。


### 契约条目的替代写法

`C1`–`C10` 不再作为编号出现，改用 [契约硬约束锚点](../adr/0020-package-boundaries-and-runtime-topology.md#hard-constraints)：
`C1`→`#hc-1` … `C10`→`#hc-10`（旧编号与 hc 条目一一对应，映射见 [归档挂载表](../archive/ROS2迁移步骤.md#hard-constraint-mounting)）。
