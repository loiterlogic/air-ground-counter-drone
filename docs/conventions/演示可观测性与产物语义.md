# 演示可观测性与产物语义

> **角色**：一键演示（`./run_demo.sh`）落盘产物与终端呈现的**语义来源**。
> **不承载**：状态机与终态语义本身（[ADR-0014](../adr/0014-task-fsm-and-scenario-transaction.md#terminal-semantics)），也不承载决策理由（[ADR 索引](../adr/README.md#adr-index)）。

## 为什么有这一层

系统内部有能力（状态机、感知融合、安全层、捕获裁决、火控窗口），但**观众看不到**。只看
Gazebo 窗口里的车与无人机，答不上"它们在干什么、为什么算成功"。目标是把**状态、意图、结果**
三件事在一次演示里表达清楚，而不是做一个大型控制台。

## 产物落点

跑完在 `experiments/demo/<时间戳>/` 落三件产物 + 机器可读指标：

| 产物 | 内容 |
|---|---|
| `timeline.txt` | **只在状态跳变时记一行**；结尾写关键节点数，不足 5 个**如实说明**、不凑数 |
| `panel.txt` | 2 Hz 终端面板副本（tty 为方框原地重绘，非 tty 为单行 + 心跳） |
| `terminal_explanation.txt` | **为什么成功 / 失败**：阈值取本 run 实际生效参数，指标只读 `summary.json` |
| `metrics/summary.json` | 机器可读指标（评估与出图的数据源） |

## 实现归属（全部在 `scripts/demo/`，不新起入口）

| 能力 | 文件 | 约束 |
|---|---|---|
| 状态语义映射 | `status_map.py` | 9 个枚举 + 36 条 `reason_code`；禁词守卫在**导入期**自检；`coverage_report()` 供离线核对 |
| 终端面板 | `panel.py` | **不 import rclpy / 任何渲染库**，headless 同源可用 |
| 事件时间线 | `timeline.py` | 只在状态跳变时记一行 |
| 终态判定说明 | `verdict.py` | 指标只读 `summary.json`；阈值只读本 run 的 `config/params_applied.yaml`，缺就明说「来源缺失」 |
| 接线 | `start.py` | 三件产物随演示落盘；`observe_yaw_mode` 的 **launch 参数已清退**（2026-11-04），实际值由场景覆盖决定（`s04` → `track`），**不再**由 `launch_argv` 传入 |

## 两条工程纪律（实测换来的）

1. **呈现层降级，不终止演示**。面板 / 时间线 / 判定说明的任何异常都进
   `result['presentation_errors']` 并**继续跑**——曾经有一次呈现层异常抛到 `run()` 之外，
   监督进程崩溃而仿真进程组仍在跑（须 `./run_demo.sh stop` 回收 33 个进程）。
2. **不猜数据源**。阈值与指标缺来源时**明说缺失**，不用默认值顶替，否则说明文字会与真实判定不符。


## 状态文案表（与 `scripts/demo/status_map.py` 的 `STATE_ROWS` 逐行一致）

| 状态 | 文案（对外唯一说法） |
|---|---|
| `IDLE` | 系统待命 |
| `AIR_SEARCH` | 无人机搜索中 |
| `TARGET_ACQUIRED` | 已发现目标 |
| `GROUND_APPROACH` | 地面车前往目标 |
| `TRACKING_SUCCESS` | 抵近并持续跟踪成功 |
| `MISSION_FAILED` | 未能在时限内达成 |
| `ABORTED` | 任务被中止 |
| `INTERCEPT_CONFIRMED` | 拦截确认（网捕获/干扰） |
| `INFRA_FAILURE` | 系统故障（非任务失败） |

> **纪律**：这张表与代码是**同一份定义的两面**——改文案必须同时改 `status_map.py`，
> 有回归锁住（`scripts/tests/test_demo_observability.py`）。禁词（如「拦截完成」）
> 不得出现在展示层；`INTERCEPT_CONFIRMED` 只能说「拦截确认」。
